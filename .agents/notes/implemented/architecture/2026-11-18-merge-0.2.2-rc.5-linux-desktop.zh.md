# Agent Note: 0.2.2-rc.5 上游同步 —— fork 保持裁剪的安装器代码树，上游新增两个连接器

Status: implemented

[English](2026-11-18-merge-0.2.2-rc.5-linux-desktop.md) | 中文

## Problem

上游 `master` 在 `0.2.2-rc.4` 留下的 merge base 之后前进 238 个提交，并切出 `0.2.2-rc.5`。该增量改动 960 个文件——新增 124 个、删除 4 个、修改 831 个、重命名 1 个——共 22274 行新增、2710 行删除。它新增 `packages/connector/linear` 与 `packages/connector/notion`（Linear 与 Notion 托管 MCP 服务器，通过共享 MCP manager 授权，各自带有 `cordis.patch.yml`、locale、快照与升级指南）、`packages/experimental/client-ui-forge` 中的 Forge 代码评审页、`packages/experimental/forge` 中的 Forge viewer 类型、把 sandbox、文件视图与发现统一到单一投影的 Session workspace-root 路由（`packages/sandbox/sandbox-policy`、`packages/api/workspace-files`、`apps/desktop-host/src/file-drag.ts`）、会话持久化的 SQLite 组提交，以及 CUA macOS/windows 鼠标按键切换。它移除 `packages/client/shortcuts/src/config.ts`、`packages/client/ui-account-notifications/src/config.ts`、`packages/client/ui-settings-models/src/onboarding-config.ts` 与 `packages/client/ui-sidebar-documentpreview/src/config.ts`，改用同级的 `types.ts` / `defaults.ts`，并把 `packages/session/working-directory/tests/admission.spec.ts` 移到 `packages/sandbox/sandbox-policy/tests/admission.spec.ts`。

合并产生十二处冲突：裁剪清单内九处 modify/delete，以及三处内容冲突。裁剪集为 `apps/desktop-publisher/package.json` 加上八个 Windows 安装器文件 `apps/desktop/installer/{drawing,lifecycle,pages}.nsh`、`apps/desktop/installer/window-frame.cpp`、`apps/desktop/scripts/installer.nsh`，以及 `apps/desktop/tests/windows-installer-{progress,render}.cpp` 与 `windows-installer-smoke.ps1`。内容冲突是 `apps/desktop/package.json`、`apps/desktop/scripts/dev.ts`，以及 `apps/desktop/README*.md` / `docs/diagnostics/README*.md` 双语页对与其 `README.i18n.yaml` 配对记录。

## Decision

**裁剪路径保持删除，安装器文件是本次同步必须移除的新增材料。**

上游改动的是已裁剪的 Windows 安装器源码而非新增它们，因此合并逐一报出 modify/delete。九处全部解析为 fork 侧的删除。`scripts/verify-sync-trimmed-paths.sh --stale upstream/master` 确认清单内 405 条路径在工作树中均不存在、且在上游树中均存在；本次增量没有在 `.github/` 下新增 workflow，也没有其他 mac/win 专有文件，所以裁剪清单无需新增条目。

`apps/desktop/package.json` 采用上游的 `0.2.2-rc.5` 版本，保留 fork 的 `productName`、author、homepage、Linux-only 脚本，以及移除 macOS/Windows 打包脚本和 publisher devDependency 的改动。

`apps/desktop/scripts/dev.ts` 采用上游新增的 `prepareDevelopmentState` 导入，它把开发 Harness 状态从 `.desktop-build` 移到 `apps/desktop/.desktop-dev`，并拒绝迁移仍在运行的 Harness Dev 所拥有的浏览器配置。它不采用上游的 `preparePrimaryRuntime` 导入与 `await preparePrimaryRuntime()` 调用：fork 已随其余 macOS/Windows 运行时准备一起裁剪 `apps/desktop/scripts/prepare-primary-runtime.ts`，而 `prepare-runtime.ts` 是直接导入 `scripts/primary-runtime/prepare.ts` 的 Linux 实现。去掉该调用让 fork 的开发启动器保持原有路径，Host 读取 `DSH_DESKTOP_PRIMARY_RUNTIME_DIR` 指定的运行目录。

`apps/desktop/README.md` 与 `.zh.md` 的 Windows 安装器段落采用上游新增的完成控件、完成闪烁与关闭按钮句子，但保留 fork 无链接的「目录替换和失败恢复遵循安装检查。」上游链接 `packaging/README.md#runtime-file-selection`，该页已被裁剪。`docs/diagnostics/README.md` 段落保留 fork 对已裁剪 `apps/desktop/tests/README.md` 的「not shipped in this Linux fork」措辞，同时采用上游新增的前任去重与 Windows 打开重试句子。合并后重新录制所有 `README.i18n.yaml` 配对。

桌面版本等于引擎版本 `0.2.2-rc.5`，无构建计数后缀，因为本次合并没有改动 fork 自有的壳行为。

## Alternatives considered

**在 `dev.ts` 保留上游的 `preparePrimaryRuntime` 导入并恢复 `prepare-primary-runtime.ts`。** 拒绝：该模块属于 fork 裁剪的 macOS/Windows 运行时准备（`prepare-primary-runtime.ts`、`sign-primary-runtime.ts` 与两个 primary-runtime spec 都在裁剪清单上），而 fork 的 `prepare-runtime.ts` 已经准备 Linux 载荷。恢复一个文件会重新引入 fork 打包构建永不执行的第二条运行时准备路径。

**在桌面 README 中采用上游的 `packaging/README.md` 链接。** 拒绝：该页已被裁剪，仓库的 Markdown 链接门禁会读取裁剪清单以豁免指向被裁剪文件的链接；保留指向已移除页面的链接会用一个死链换取干净的门禁结果。

**在 fork 的 `dev.ts` 中接入 `.desktop-dev` 状态处理，但保留旧的 `.desktop-build/development` 默认位置。** 拒绝：`pnpm run clean` 会删除 `.desktop-build`，这正是上游修复的缺陷；保留旧默认会让 fork 在每次 clean 时丢失开发状态。

**把桌面版本升到 `0.2.2-rc.5.1`。** 拒绝：本次合并没有改动 fork 自有的壳行为，fork 的发版历史把构建计数递增与同步合并分开。

## Consequences

下一次同步从上游 `master` 中 `dsh-v0.2.2-rc.5` 之后开始。Windows 安装器源码在裁剪清单上，只要 fork 继续裁剪它们，就会持续报出 modify/delete 冲突；每次都解析为删除。`apps/desktop/scripts/dev.ts` 现在是一个上游对应文件会调用被裁剪模块的文件，未来同步若改动其 `main()` 需要做同样的调用点检查。Session workspace-root 路由把生效目录的消费者移到了 `workspaceFiles` 上；直接读取 `sessions`、`sessionPersistence` 或 `sandboxPolicy` 来解析 Session 根的 fork 本地代码必须随之迁移。fork 基线在新 merge base 上仍与 fork 修改的文件匹配：需要决策的两个文件 `apps/desktop/package.json` 与 `apps/desktop/scripts/dev.ts` 都已在 `.github/sync-forked-paths.txt` 中。

## Testing

`scripts/verify-sync-trimmed-paths.sh --stale upstream/master` 及其工作树与暂存形式确认 405 条裁剪路径全部不存在且仍存在于上游。`node scripts/verify-sync-forked-paths.ts --base upstream/master` 报告基线在新 merge base 上与 fork 修改的文件匹配。`pnpm install --frozen-lockfile` 通过。`pnpm run typecheck` 通过五个门禁。`pnpm run lint` 在 `DSH_OXLINT_THREADS=2` 下通过，因为类型感知的 tsgolint 后端在默认并行度下会耗尽本机内存。`pnpm run test:docs` 通过 21 个门禁。`pnpm exec vitest run apps/desktop/tests apps/desktop-host/tests` 通过 99 个文件、1258 个用例，跳过五个。`pnpm run build:artifacts` 通过八个门禁，`pnpm run build:check` 通过两个，为两个新连接器包生成 `publint` 要求的 `lib/` 输出。`pnpm run hygiene` 通过 26 个门禁，前提是删除四个此前同步删除的包留下的未跟踪残留目录（`packages/client/ui-settings-plugin-inventory`、`packages/client/ui-settings-plugins`、`packages/credentials/deepseek-account`、`packages/session/tool-working-directory`）。其中 `verify-plugin-entry-exports` 与 `verify-optional-dependency-imports` 两个门禁在本机会耗尽默认堆内存，在 `NODE_OPTIONS=--max-old-space-size=8192` 下通过。
