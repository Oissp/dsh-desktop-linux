# Agent Note: 0.1.7-rc.2 合并的 Linux 桌面呈现面

Status: implemented

[English](2026-09-25-merge-0.1.7-rc.2-linux-desktop.md) | 中文

## Problem

上游 0.1.7-rc.2 重写了桌面浮层 API，并让关闭主窗口变成隐藏而非退出。`update-overlay.ts` 新增按父窗口记账的 `DesktopUpdateOverlays.input(parent)`，返回 `{ revision, blocked }`，其 `create()` 新增 `nativeModal` 与 `platform` 参数；`update-dialog.ts` 新增 `resize` IPC 通道与 `overlays` 接缝；`mandatory-update-window.ts` 新增 `overlays` 与按次读取的 `locale`，并在视图中发布 `surface`。关窗在所有平台都改为隐藏，Windows 侧由 `DesktopTray` 与 `DesktopQuitConfirmation`（退出前经 `inspectQuit` 询问 Host）承担。本 fork 只携带 Linux 打包面，且已有自己的托盘，因此自动合并同时保留了两个托盘、两套呈现面选择，以及 `apps/desktop/package.json` 中上游的 mac/win 打包脚本与依赖。

上游还新增了 `apps/desktop/scripts/flock-entry.ts` 与其 spec。只有被裁剪的 `macos-notarization-proxy.ts` 导入该入口模块，所以合并后的 spec 会去复制 fork 不携带的文件，并以 `ENOENT` 失败。

配对记录格式从整文件 blob 哈希改为按标题章节哈希，上游同时删除了 `scripts/merge-translation-pairing.ts`、`scripts/translation-pairing-merge.ts` 与 `resolve-translation-pairing-conflicts` 脚本。因此每个 fork 自有的 `*.i18n.yaml` 都会以 `malformed consistency record` 使 `verify-translation-pairing` 失败。

上游把 `@deepseek-ai/libreoffice-kit` 升到 0.1.1，而 fork 的 `patchedDependencies` 条目与补丁文件仍写 0.1.0，于是 `pnpm install` 以 `ERR_PNPM_UNUSED_PATCH` 失败。

## Decision

**Linux 托盘仍由 fork 自己维护。** `DesktopTray` 按上游写法只在 Windows 构造。fork 保留 `linuxTray`，在 `app.isPackaged && process.platform === 'linux'` 时创建，携带 `showWindow` / `checkUpdatesMenu` / `quit` 菜单；`refreshApplicationMenu()` 在该构建上仍安装 `Menu.setApplicationMenu(null)`，使托盘成为唯一入口。窗口的 Linux 图标与托盘图标由同一个外观控制器驱动。

**呈现面移入新的浮层 API。** `desktopDialogSurface(platform)` 与 `mandatoryUpdateSurface(platform)` 仍归 fork。`create()` 现接收上游的 `nativeModal` 与 `platform` 参数，并保留 fork 的 macOS 输入拦截；`createPrompt` 与 `createMandatory` 在 fork 的 `createDialogCard` / `createFramedModal` 与透明遮罩之间选择；`fitDialogCard` 不变，仍按文档上报的高度调整不透明卡片。`closed` 处理器保留上游的父窗口已销毁保护，因为 macOS 的输入监听会活过 Electron 已经拆掉的父窗口。

**`flock-entry` 被裁剪。** `apps/desktop/scripts/flock-entry.ts` 与 `apps/desktop/tests/flock-entry.spec.ts` 列入 [sync-trimmed-paths.txt](../../../../.github/sync-trimmed-paths.txt)，因为唯一导入方是被裁剪的 macOS 公证代理。

**LibreOffice Kit 补丁按 0.1.1 重新生成。** 它修复的缺陷——`installedPackageExists` 用 `lstatSync(path, { throwIfNoEntry: false }) !== undefined` 判断，把不可读目录当成已安装——在 0.1.1 中未变，因此补丁针对该版本重新生成，`THIRD_PARTY_NOTICES.md` 一并更新。

**配对记录重新登记，被裁剪的链接保留原始路径。** `apps/desktop/README.zh.md` 现链接 `tests/README.md#verification-overlay`，与英文侧一致。`translationStructureDiff` 逐字比较链接目标，而只有当目标本身是已登记的配对源时才能把 `.zh.md` 目标归一化——被裁剪的 `apps/desktop/tests/README.md` 不是，于是上游的 `.zh.md` 写法与英文写法分歧，配对失败。要求 `.zh.md` 写法的合并驱动已被上游删除，如今没有任何东西再要求它。

## Alternatives considered

**在 Linux 上沿用上游的 `DesktopTray`。** 否决：fork 的托盘承担 Linux 专有的外观跟随图标与打包构建的菜单镜像，两个托盘会争抢同一份图标与菜单。

**让合并后的 `flock-entry.spec.ts` 改测 fork 自有的代理。** 否决：这等于为一个 fork 不发布的文件保留 spec，并让 fork 接手它有意裁剪的 macOS 代理路径。

**把 `@deepseek-ai/libreoffice-kit` 固定回 0.1.0 以保留原补丁。** 否决：合并已把引擎与所有消费方移到 0.1.1，而该修复是一行行为修正，可机械重新生成。

**保留 `tests/README.zh.md#verification-overlay` 并加配对例外。** 否决：例外文件必须枚举每份配对文档中的每个被裁剪目标，而原始路径本就是 fork 已记录的写法（[fork 裁剪链接只做声明，不改写](../process/2026-09-20-fork-trimmed-link-gate.zh.md)）。

## Consequences

上游每次改动 `main.ts`、`tray.ts`、`quit-confirmation.ts` 或 `update-overlay.ts`，fork 都要重新施加自己的托盘、两个呈现面选择器与打包 Linux 的菜单隐藏；裁剪清单只跟踪被删除的文件，因此这些被修改的行为记录在本笔记与 fork 的测试里。

上游的关窗即隐藏行为现已原样作用于 Linux，这正是 Linux 托盘存在的原因：没有它，打包的 Linux 构建关窗后将没有任何返回入口。

配对记录改为按章节记账，因此 fork 侧对配对文档某一章节的修改只需重新登记该配对，而非整份文件。若上游将来改动某份配对文档，而其 fork 侧链接的是被裁剪目标，就会以结构分歧的形式出现，需要对齐原始路径，而不只是重新登记。

## Testing

`pnpm run typecheck` 编译合并后的树；`pnpm run lint` 与 `pnpm run test:docs` 均干净，文档门禁报告 20 passed、0 failed。`pnpm exec vitest run apps/desktop` 通过 69 个文件、745 个测试，含合并后的 `update-overlay.spec.ts`、`update-dialog.spec.ts`、`mandatory-update-window.spec.ts`、`mandatory-update-policy.spec.ts` 与 `main-startup.spec.ts`。`pnpm install --frozen-lockfile` 接受重新生成的补丁与锁文件。
