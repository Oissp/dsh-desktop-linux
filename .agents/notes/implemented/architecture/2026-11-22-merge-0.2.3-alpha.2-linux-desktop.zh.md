# Agent Note: 0.2.3-alpha.2 上游同步 —— fork 提高 Node.js 与 Electron 下限，vendor 套件进入 4.2 alpha 线

Status: implemented

[English](2026-11-22-merge-0.2.3-alpha.2-linux-desktop.md) | 中文

## Problem

上游 `master` 在 `0.2.3-alpha.1` 留下的 merge base 之后前进五个提交，并切出 `0.2.3-alpha.2`。该增量改动 488 个文件——新增 3 个、修改 485 个——共 806 行新增、707 行删除，其中大多是 workspace 清单里的版本字段。它把 `engines.node` 提高到 `^24.22.3 || >=26.13.1`，因为这两个版本是内置 undici 首次包含 2026 年 11 月安全修复的版本；把主运行时移到 Node 24.22.3；把 Electron 提升到 44.11.5，并配套 `node-addon-require-builtin` 0.1.10；新增 undici 主版本覆盖；发布 vendor 包 cordis 4.2.0-alpha.1、cosmokit 1.10.0-alpha.1、group/hmr/include/loader/logger-console 1.2.0-alpha.1、schemastery 3.20.0-alpha.1 与 timer 1.3.0-alpha.1；并新增 `node-24-22-3` 升级指南。

合并产生 30 处冲突。其中 29 处是裁剪路径上的 modify/delete：二十七个 `.github/workflows` 文件、`apps/desktop-publisher/package.json`，以及 `apps/desktop/tests/updates/electron-updater/verified-versions.json`。唯一的内容冲突是 `apps/desktop/package.json`。

## Decision

**裁剪路径保持删除；`apps/desktop/package.json` 采用新版本与 Electron 范围，同时保留 fork 的 Linux-only 发布面。**

二十九处 modify/delete 冲突解析为 fork 侧的删除。workflow 改动是上游在每个 job 中固定 Node 下限；fork 不携带这些 workflow，而它自己的 `package-deb.yml` 与 `package-deb-test.yml` 已请求 `node-version: 24`，会安装满足新下限的 24.x 版本。它们的 `engines` 注释更新为 `^24.22.3 || >=26.13.1`。

`apps/desktop/package.json` 保留 fork 的 `productName`、author、homepage、Linux-only 脚本，以及移除 macOS/Windows 打包脚本、publisher devDependency 和 `cos-nodejs-sdk-v5` 的改动，后者只被已裁剪的 COS 公证与 publisher 工具调用。它采用上游的 `0.2.3-alpha.2` 版本与 `electron` `^44.11.5` 范围。锁文件由 `pnpm install` 重新生成，解析新的 Electron、0.1.10 addon 套件与 undici 覆盖。

桌面版本等于引擎版本 `0.2.3-alpha.2`，无构建计数后缀，因为本次合并没有改动 fork 自有的壳行为。

## Alternatives considered

**把 fork 的 workflow 固定到 `node-version: 24.22.3`。** 拒绝：`node-version: 24` 已解析到最新的 24.x 版本，满足新的 `^24.22.3` 下限；精确固定反而需要在每次提高下限时维护。

**保留上游的 `cos-nodejs-sdk-v5` devDependency。** 拒绝：该包只被已裁剪的 COS 公证与 publisher 路径调用，保留它只会增加 fork 从不导入的安装期依赖。

**在解决 `apps/desktop/package.json` 后手工编辑 `pnpm-lock.yaml`。** 拒绝：Electron、addon 套件、undici 覆盖与 vendor 发布都会改变解析结果；`pnpm install` 从合并后的清单重新生成并一次性通过供应链策略校验。

## Consequences

下一次同步从上游 `master` 的 `dsh-v0.2.3-alpha.2` 标签之后开始。上游按 job 固定的 Node 版本仍会对已裁剪的 workflow 产生 modify/delete 冲突；除非某个 workflow 增加了 fork 自有 workflow 应当采纳的行为，否则解析为删除即可，无需逐项检查。Node 下限现在与内置运行时一致，源码检出与打包应用因此都使用 24.22.3。

## Testing

`scripts/verify-sync-trimmed-paths.sh --stale upstream/master` 确认 419 条裁剪路径均不存在且仍存在于上游。`node scripts/verify-sync-forked-paths.ts --base upstream/master` 报告基线与新 merge base 的 fork 修改文件一致。`scripts/verify-sync-pairing-after-merge.sh` 未发现配对变动。`pnpm install` 报告锁文件已是最新，并通过供应链策略检查。`pnpm run typecheck` 通过五个门禁。`pnpm run lint` 在 `DSH_OXLINT_THREADS=1` 与 `NODE_OPTIONS=--max-old-space-size=4096` 下通过，因为类型感知的 tsgolint 后端在本机更高并行度下会耗尽内存。`pnpm run test:docs` 通过 21 个门禁。`pnpm exec vitest run apps/desktop/tests` 通过 92 个文件、1204 个用例，跳过 2 个文件与 5 个用例。`pnpm run hygiene` 在 `NODE_OPTIONS=--max-old-space-size=6144` 下通过全部 27 个门禁。`pnpm run build` 通过 `build:artifacts` 与 `build:check`。
