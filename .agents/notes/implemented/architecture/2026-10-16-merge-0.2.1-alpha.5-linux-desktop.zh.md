# Agent Note: 0.2.1-alpha.5 合并——账号通知、斜杠菜单刷新，发布管线加固被裁剪

Status: implemented

[English](2026-10-16-merge-0.2.1-alpha.5-linux-desktop.md) | 中文

## Problem

上游 `master` 在上一次同步点之后前进 36 个提交，发布引擎 `0.2.1-alpha.5`（tag `dsh-v0.2.1-alpha.5`，即本次合并的目标）；增量改动 586 个文件。覆盖四个领域：账号通知（新增 `packages/client/ui-settings-account/src/client/notice-transition.ts` 以层叠不同高度的通知，账号平台新增通用通知元数据字段，以及 `docs/upgrade-guide/v0.2.1-alpha.4/account-notification-fields` 升级指南）、客户端斜杠菜单与模型标签（`packages/client/ui-skill` 在插件管理器变更后刷新 `/` 菜单，`ui-model-selection` 新增按 provider 区分的模型标签插槽并让菜单留在视口内）、终端与 Web 修复（`packages/api/terminal-controller` 新增按会话共享的终端清单，`packages/client/ui-layout` 裁剪收起的右侧栏以防 PageUp 移动框架，`apps/web` 固定夹具时钟以覆盖页面计时器回归），以及 Desktop 发布加固（在安装依赖前拒绝调试包、Windows 打包默认签名、发布到未做行政版本标记的 COS 桶、用计划任务托管 Windows 打包 runner）。

合并产生 25 处冲突。24 处是命中被裁剪桌面路径的修改/删除对：四个上游独有 CI workflow、发布与 Windows 签名文档、COS 发布管线脚本及其测试，以及此前已裁剪的 `scripts/windows-package-workflow.spec.ts`。唯一的内容冲突是 `apps/desktop/package.json`。

另有 13 个上游文件合并不冲突，但落在被裁剪的发布与 Windows 打包范围内。

## Decision

**所有 24 处修改/删除冲突保留 fork 的删除。** 这些路径用 `git rm` 删除，保持 fork 的 Linux-only 姿态。

**13 个新到的裁剪范围文件被裁剪，清单从 350 条增至 362 条。** 发布前检查（`preflight-desktop-publish.mjs`/`.d.mts`）、发布资格诊断模块（`desktop-publish-qualification.mjs`/`.d.mts`）与 `apps/desktop/tests/desktop-publish-preflight.spec.ts` 属于已裁剪的 COS 发布管线：preflight 脚本只被 `.github/workflows/desktop-publish.yml` 调用，资格模块只被已裁剪的 `desktop-publish-route.ts` 与 `publish-desktop-ci.ts` 导入，spec 断言该 workflow 的 preflight 步骤。四个快照夹具（`expected/cos-GetObject-denied.json`、`expected/cos-PutObject-denied.json`、`expected/retained-unnotarized.md`、`expected/retained-unsigned.md`）由已裁剪的 `desktop-publish-cos.spec.ts` 与 `retain-desktop-ci.spec.ts` 中的 `toMatchFileSnapshot` 写入。Windows runner 托管脚本（`apps/desktop/scripts/windows-runner-task.ps1`、`run-windows-runner-task.ps1` 及其 `apps/desktop/tests/windows-runner-task.ps1` 验收脚本）只被已裁剪的 `.github/workflows/ci.yml` 与已裁剪的 Windows 签名 README 引用。

**`scripts/desktop-publish-workflow.spec.ts` 保留，并采用上游内容。** 上一次同步记录了 fork 的决定：保留两个其 workflow 已被裁剪的 spec（`macos-package-workflow.spec.ts`、`desktop-publish-workflow.spec.ts`），只裁剪同类新增 spec。上游本次新增 9 行，固定新的发布 preflight 步骤与其校验后的 attempt；该 spec 无论是否裁剪都无法在缺少 workflow 时加载，因此本次同步沿用已记录的策略，而不在机械合并中途改写它。

**`apps/desktop/package.json` 保留 fork 元数据并采用上游版本号。** `author` 与 `homepage` 继续指向 fork 仓库，版本号升至 `0.2.1-alpha.5`（与引擎版本相同）。上游在该增量中对本文件的唯一其他改动就是版本号，因此 fork 的 Linux-only scripts、省略的 `koffi` 与保留的 `tar` 均未受影响。

**`apps/desktop-host/package.json` 只取版本号**，仍不包含 `koffi`。

**本增量没有任何上游提交改动 fork 修改过的 Desktop 源文件。** `main.ts`、`locale.ts`、`update-coordinator.ts`、`desktop-build-paths.mjs`、`electron-builder.config.mjs`、`package-target.ts`、`prepare-runtime.ts`、`prepare-cli.ts`、`command-management.ts` 与 `tsdown` 配置均原样通过；fork 清单中唯一被上游触及的是 `apps/desktop/package.json`，且其唯一上游改动是版本号。

**上游引擎改动原样采纳。** fork 在 `packages/` 上没有任何分叉，因此账号通知、斜杠菜单、模型标签、终端清单与发布加固等引擎改动按上游原样进入代码树。

## Alternatives considered

**裁剪 `scripts/desktop-publish-workflow.spec.ts`。** 拒绝：alpha.4 合并笔记记录了 fork 有意保留该 spec 及其同类 `macos-package-workflow.spec.ts`（尽管其 workflow 已被裁剪），只裁剪同类的新增 spec。在此裁剪会在一场机械同步中推翻已记录的决定，并丢掉上游新增的 preflight 断言——若 fork 将来采纳发布管线，这些断言会重新变得有意义。两个 workflow reader 后来已在机械同步之外裁剪（[笔记](2026-10-28-trim-trimmed-workflow-readers.zh.md)）。

**保留新的 Windows runner 托管脚本。** 拒绝：它们通过 Windows 计划任务注册并托管打包 runner，只被上游独有的 `ci.yml` 与已裁剪的 `apps/desktop/windows-signing/README.md` 引用。fork 在 Linux runner 上构建 deb 与 AppImage，从未运行过它们。

**保留四个 `cos-*` 与 `retained-*` 快照夹具。** 拒绝：它们唯一的消费者是已裁剪的 `desktop-publish-cos.spec.ts` 与 `retain-desktop-ci.spec.ts`，与 alpha.3 同步中已裁剪的 `expected/publication-*.md` 夹具同理。

**保留 `preflight-desktop-publish.mjs` 并采纳调试包拒绝机制。** 拒绝：fork 完全不运行 COS 发布管线，而该脚本读取的 GitHub Actions run 元数据来自 `package-deb.yml` 从不产生的 attempt。

## Consequences

下一次同步从上游 tag `dsh-v0.2.1-alpha.5` 开始。裁剪清单保有 362 条路径。

fork 的裁剪策略现在区分两类发布范围文件：新增文件随其所属管线一并裁剪，而两个长期存在的 workflow spec 按 alpha.4 笔记记录的理由保留。未来同步若改动其中任一 spec，应保留上游内容并沿用该裁剪决定。

Windows 安装器源码树仍如 alpha.4 笔记所述处于半裁剪状态：`window-frame.cpp` 与 `installer/*.nsh` 保留，而其 include 的头文件已裁剪。本增量未向该组新增文件。
