# Agent Note: 0.2.0-rc.2 merge at da00f7f535 — kit 0.1.5 and the restored CLI payload

Status: implemented

[English](2026-10-03-merge-0.2.0-rc.2-da00f7f535-linux-desktop.md) | 中文

## Problem

上游 `master` 从 `639ed01539` 前进到 `da00f7f535`，258 个提交、3925 个文件，引擎版本仍是 `0.2.0-rc.2`。fork 原样接收的产品工作包括：带原始日志、分组对话与内嵌 DevTools 视图的 Session inspector；在准备阶段流式解析工具参数；Claude Code mods 作为 DSH 插件；LibreOffice Kit 0.1.5；以及一次性封存 306 条 Agent Note 的归档。Desktop 侧，Host 改为监听操作系统分配的端口，原生账号状态解码器接受 `no-response` 登录失败。

25 条路径冲突。其中 15 条是修改/删除对：多数落在裁剪清单内，另有 3 条以重命名形式到达——上游归档了 `desktop-cos-upload-transport`、`windows-lock-release-probe` 与 `desktop-mandatory-update-client` 三篇 Note，而 fork 此前或整组裁剪、或仍在维护。其余为内容冲突：`apps/desktop-host/package.json`、`pnpm-workspace.yaml`、`pnpm-lock.yaml`、Desktop README 双语对、开发指南双语对、`skill-office.spec.ts` 与 `.agents/notes/archived/manifest.json`。

本次合并还暴露出两个先于它存在的缺陷。`2026-09-30-desktop-cli-linux-sync` Note 只有英文，只要暂存任何 `.i18n.yaml` 文件就会触发双语配对门禁失败；而同一功能安装的 Linux `dsh` 命令根本无法运行。

## Decision

**裁剪清单内的冲突保留 fork 的删除。** 两篇 desktop installed-update 测试 Note、`ci.yml` 与 `ci-master.yml` 保持删除。

**两篇已归档的 mac/win Note 保持删除。** `2026-09-16-desktop-cos-upload-transport` 与 `2026-09-14-windows-lock-release-probe` 描述的是 fork 不携带的管线，因此其归档三元组连同 manifest 封印一并移除。cos-upload-transport 此前被删除时没有登记裁剪清单，现在两条路径都已列出。

**mandatory-update-client Note 接受上游的归档迁移。** fork 重新携带了该 Note 所述的 Desktop 命令，因此三元组移入 `archived/feature/`。fork 早先对指向已裁剪本地验收 Note 的链接所做的删除被重新套用，三元组与其 manifest 封印按合并后的内容重新记录。

**LibreOffice Kit 跟随上游升到 0.1.5，fork 的补丁随之重做。** 上游没有修 fork 所补的 `installedPackageExists` 探测，因此是重新套用而非放弃：`patches/@deepseek-ai__libreoffice-kit@0.1.5.patch` 保持同样的 `try` 内 `Boolean(lstatSync(...))` 形式，`patchedDependencies` 指向新版本。kit 0.1.5 并非装饰性升级——它加入 RTL 瓦片纠正与原生进程传输——所以留在 0.1.2 只会让 fork 在一个自己已经在打补丁的依赖上落后。`createRuntimeProjectMetadata` 会自动把被打补丁的版本钉进构建根，打包路径无需额外改动。`skill-office.spec.ts` 的冲突按 fork 从 manifest 推导版本号的写法解决，该写法在升级后依然成立。

**Desktop README 恢复裁剪期间移除的小节。** `Bundled command runtime` 小节与 `The Desktop-installed command can manage its plugins…` 一句描述的是 fork 重新携带的功能，两者都采用上游文本。fork 自己的 `Shell prompts are modal children of the product window` 段落保留。

**开发指南采用上游改动加 fork 的 CI 小节。** 只按 fork 一侧解决会丢掉上游的前置条件、DevTools 与构建加载器改动，并保留指向已归档 `ts-build-config` Note 的链接。fork 的 `CI gates` 段落替换上游同段，其余取上游。

**归档 manifest 取并集。** 上游的封印，去掉两个被裁剪的三元组，加上 fork 的 `desktop-cli-linux-sync-plan` 条目。

**恢复缺失的 CLI 入口。** `apps/desktop/cli/dsh` 执行 `app.asar` 内的 `@deepseek-ai/dsh-desktop-host/lib/cli.js`，但提交 `3266005df5` 在恢复该功能时没有一并恢复此前描述裁剪形态的四处：`tsdown` 入口列表、包 `files`、`DESKTOP_HOST_RUNTIME_FILES` 与工作区约束表都仍只列 `lib/index.js`。构建因此从不产出 `lib/cli.js`，任何已安装的命令都会以 `ERR_MODULE_NOT_FOUND` 失败。四处全部改回双入口形式，包集夹具补上对应文件。

**desktop-cli Linux 同步 Note 补上中文侧。** 仓库要求双语配对，而只要存在未配对 Note，暂存任何 `.i18n.yaml` 文件都会被配对门禁拦下。现有中文正文成为 `.zh.md`，另写一份对应的英文 `.md`，格式对齐同类的 `fork-debian-linux-packaging` Note。

## Alternatives considered

**保留 fork 的 kit 0.1.2 钉版。** 否决：只是把同样的冲突推迟到下次同步，并让 fork 在一个自己已经在打补丁的依赖上无谓落后，因为补丁机制本就把版本钉在它针对的那一版。

**用 `pnpm patch`/`pnpm patch-commit` 重新生成 kit 补丁。** 否决：没有必要。被补的函数在 0.1.2 与 0.1.5 中逐字节相同，针对 0.1.5 文件重做 diff 会得到同样的 hunk——这一点通过先从 0.1.2 自身源文件复现原补丁得到了验证。

**把 Linux 启动器指向 `lib/index.js`。** 否决：`index.ts` 是 Electron Host 入口；CLI 分派在 `cli.ts`，启动器运行的正是它的 `import.meta.main` 块。

**用 `--no-verify` 提交合并。** 否决：未配对 Note 是真实的门禁违规，会在之后每次触碰配对记录的提交上继续失败。

**在本分支顺手修掉既有的文档门禁失败。** 否决：超出范围。`verify-md-wrap` 与 `verify-repository-references` 失败于 fork 的 `2026-09-30-fork-debian-linux-packaging` Note，本次合并没有触碰该文件，fork CI 也不跑这些门禁。

## Consequences

kit 补丁从此跟随 kit 版本，未来的升级是"改名加重做 diff"，而不再是版本钉版决策。裁剪形态不再有调用方：fork 中已无任何地方假定 `apps/desktop-host` 只发布 `lib/index.js`。

`desktop-cli-linux-sync` 移出未配对集合，因此暂存配对记录不再触发 pre-commit 钩子失败。

仍有两处失败既非本次合并造成、也未被本次合并修复。`pnpm run test:docs` 报告 `markdown wrap` 与 `repository references` 在 `2026-09-30-fork-debian-linux-packaging.md` 上失败：其引用块被硬换行，且页首引用了提交哈希。`apps/desktop/tests/command-installation.spec.ts` 在 macOS 上无法加载，因为它的 `darwin` 分支会 import 已被裁剪的 `prepare-command-link.ts`；Linux CI 会运行该套件并通过。

桌面版本提升到 `0.2.0-rc.2.3`。由于 `shellVersionExtendsEngine` 只接受引擎版本本身或引擎版本加构建计数，只要引擎停在 `0.2.0-rc.2` 就无法构建稳定的 `0.2.0` 壳：发版要么提升引擎，要么留在 `.N` 线上。

## Testing

`pnpm run typecheck` 与 `pnpm run lint` 退出码 0。`pnpm exec vitest run apps/desktop/tests apps/desktop-host/tests` 在 73 个文件中报告 807 passed、3 skipped，唯一失败是先于本次合并存在、且只在 macOS 上出现的 `command-installation.spec.ts` 套件加载失败。`pnpm run test:docs` 报告 19 passed、2 failed，两处均为既有失败且都在未被本次合并触碰的 fork 打包 Note 中。

kit 补丁通过读取解析结果验证：工作区链接到 `@deepseek-ai+libreoffice-kit@0.1.5_patch_hash=a43eaeb2…`，且该副本的 `installedPackageExists` 为 `Boolean(...)` 形式。`verify-archived-agent-notes` 校验 6 类共 2769 个已封存产物，`verify-translation-pairing` 校验 875 对文档，裁剪清单报告 261 条路径全部不在工作树中。

CLI 入口通过实际构建验证：`tsc -b apps/desktop-host` 产出 `lib/types/cli.js`，`tsdown` 产出 `lib/cli.js`（4.23 kB），且该 bundle 在 `ELECTRON_RUN_AS_NODE=1 node --expose-internals` 下可加载，并从随包运行时解析 `@deepseek-ai/dsh/lib/bin.js`。
