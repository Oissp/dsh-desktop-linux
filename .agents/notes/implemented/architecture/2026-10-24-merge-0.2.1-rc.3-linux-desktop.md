# Agent Note: 0.2.1-rc.3 merge — a faulty conflict resolution is repaired, not merged forward

Status: implemented

English | [中文](2026-10-24-merge-0.2.1-rc.3-linux-desktop.zh.md)

## Problem

Upstream `master` advanced 1539 commits past the previous sync point (`dsh-v0.2.1-rc.2`) and released engine `0.2.1-rc.3`. The merge target is the `master` tip, which carries that release plus 1533 later commits; `dsh-v0.2.1-rc.3` is an ancestor of it. The delta changes 6360 files and adds 2911, among them 21 new packages, the `liveshare-protocol` identity layer, a `util/file-drag` capability with its Desktop wiring, `session/message-quotes`, `util/official-bundles`, the `action-cards` and creation/plugin recommendation experimental packages, `cua-bundle`, the split `core/tool-executor-native` and `core/tool-executor-ptc` executors, and 462 snapshot files.

The first attempt at this merge committed `the first attempt`. It resolved the tree without conflicting, but it dropped seventeen fork modifications by taking upstream's side wholesale where the fork's design and upstream's redesign overlapped. Inspecting the commit with `git diff --numstat upstream/master HEAD` shows the pattern: a file whose result is byte-identical to upstream while `main` had modified it. Two consequences made that tree unusable:

- **The update-dialog subsystem became internally inconsistent.** `update-overlay.ts`, `update-dialog.ts`, and `mandatory-update-window.ts` were taken from upstream, but `main.ts`, `preload-update-dialog.ts`, and `renderer/update-dialog.js` kept the fork's API. Typecheck failed at the fork's call sites, and `update-error-renderer.spec.ts` failed because the fork's close glyph no longer existed.
- **Six dictionaries lost the fork's tray strings.** `showWindow` and `quitMenu` — restored by the fork because its Linux tray shows them — were present in `en` and `zh` and absent from `ja`, `es`, `fr`, `de`, `ru`, and `pt`, so `locale.spec.ts` failed on six cases.

Two further fork edits disappeared the same way and are easy to miss because nothing fails: `packages/ptc-runtime/ptc-runtime-node/tsdown.config.ts` reverted from `deps: { alwaysBundle }` to the deprecated `noExternal`, and `apps/desktop/renderer/update-close.svg` vanished from the tree although no trim-list entry covers it.

## Decision

**The merge is repaired in place rather than accepted and patched later.** The branch was backed up as `backup/broken-merge-rc3`, and the resolution redone per file with the fork's intent restored. The recurring rule this note exists to carry: for a file both sides changed, the result may match neither side, but it must never equal upstream's blob while `main` had diverged — that is the signature of a dropped fork edit, and `git diff --numstat upstream/master HEAD -- <path>` finds it in one command.

**The dialog subsystem adopts upstream's `WebContentsView` design.** Upstream replaced the separate transparent prompt window with a view attached inside the parent window. That change structurally removes the problem the fork's Linux branch existed to solve: an uncomposited X11 or Wayland session painted a transparent window's alpha as an opaque slab over the product window, so Linux got an opaque centered card plus a `resize` channel for height fitting. With the document composited inside the parent, the scrim has a backdrop by construction. The fork therefore drops `desktopDialogSurface`, `mandatoryUpdateSurface`, `fitDialogCard`, the `resize` IPC channel, the `surface` view field, and the prepaint helper. What it keeps is the display-time locale getter: the update machinery is constructed before the engine's `locale.preference` is read, so capturing the dictionary at construction pinned every prompt to `app.getLocale()` while the menus followed the setting. `locale: () => DesktopLocale` on `DesktopUpdateDialog` and `DesktopMandatoryUpdateWindow` preserves that, while `MandatoryUpdateView.locale` stays a value because it crosses IPC.

**The tray strings are restored in all six dictionaries.** `showWindow` and `quitMenu` are fork-only keys, so a merge that rewrites the dictionary blocks drops them wherever upstream did not have them.

**Two accidental losses are repaired and one is recorded.** `tsdown.config.ts` returns to `deps: { alwaysBundle }`, which is the current spelling of the deprecated `noExternal` the fork adopted in [`2026-09-25-fork-build-config-edits`](../process/2026-09-25-fork-build-config-edits.md); upstream added `birpc` to the same list in this delta, so the repaired value carries both entries. `update-close.svg` is restored from upstream. `.github/dependabot.yml` is added to the trim list instead: the fork deleted it deliberately in `the fork's own CI commit`, but no entry recorded that, so a future merge would have reintroduced it.

**Upstream's engine work is adopted unchanged.** The fork carries no `packages/` divergence, so the 21 new packages, the file-drag capability and its Desktop wiring, the split executors, the liveshare identity layer, and every accompanying test enter the tree as upstream authored them.

## Alternatives considered

**Merge the faulty commit and repair it in follow-up commits.** Rejected: `the first attempt` is an eight-thousand-line conflict-resolution commit whose wrong side is visible only by diffing file blobs against upstream. Landing it would make the dropped edits indistinguishable from deliberate ones in history, and a follow-up note would have to describe a repair rather than a resolution. Rebuilding the branch keeps each decision reviewable against a clean base.

**Keep the fork's native-window card design and reject upstream's `WebContentsView` rewrite.** Rejected on evidence, not preference. The card existed because a separate transparent window cannot composite its alpha without a compositing manager, and it carried three follow-on mechanisms — a height-reporting channel, a surface field, and a prepaint color — that exist only to serve it. Adopting the view deletes all four and gives the fork upstream's ongoing attention to the same code. The one property the view does not supply on its own, display-time locale, is a four-line change the fork already knew how to make.

**Re-record every pairing hash and move on.** Rejected: the fork trims `apps/desktop/packaging/`, `windows-signing/`, and `publishing/`, which upstream created in this delta and which `apps/desktop/README.md` now links to. Re-recording without removing those links would bless a README that points at files the fork does not ship.

**Trim `apps/desktop/tests/signing-concurrency/` and the new Windows packaging scripts wholesale.** Rejected for the `signing-concurrency` pair: it documents qualification results the fork keeps even though it cannot run the Windows experiment. Trimmed instead are the Windows/macOS-only scripts, specs, and workflows whose only consumers are themselves, following the existing trim sections.

## Consequences

The next sync starts from upstream `master` at the `master` tip recorded above, not from the tag; the tag is 1533 commits behind the merged tip. The trim list grows from 377 to 407 paths, and `.github/sync-forked-paths.txt` records the divergences that survived the design adoption.

The fork no longer diverges from upstream in `update-overlay.ts` at all. It diverges in `update-dialog.ts` and `mandatory-update-window.ts` in one constructor option each, and in the tests that pin those. A future upstream change to the prompt surface merges cleanly; a change to the locale wiring conflicts, and the resolution is to keep the getter.

`apps/desktop/README.md` follows upstream's restructured version, which is 394 lines and delegates build and release operations to a packaging guide. The fork does not carry that guide, so the README is made self-contained: the three-guide bullet list collapses to a pointer at the fork's own [`LINUX_PACKAGING.md`](../../../../apps/desktop/LINUX_PACKAGING.md), and the remaining links into trimmed guides become prose. Readers lose the Windows EV-token, notarization, and COS-upload detail those guides carried; the fork ships none of that machinery.

## Testing

`scripts/verify-sync-trimmed-paths.sh` and its `--staged` form confirm all 407 trimmed paths are absent from the worktree and the index. `scripts/verify-sync-pairing-after-merge.sh` and `verify-translation-pairing` report 1120 pairs consistent, and `verify-md-links-trimmed` reports 2260 files checked with every relative link resolving. `verify-archived-agent-notes` reports 2775 frozen artifacts intact across 6 kinds.

`pnpm run typecheck` exits clean. `pnpm exec vitest run apps/desktop/tests` passes, including the 16 locale cases restored by the dictionary fix and the dialog suite re-pinned against the adopted design. `pnpm run test:docs` passes all 21 gates.

`apps/desktop/package.json` moves to `0.2.1-rc.3`, equal to the engine version rather than carrying a `.N` suffix, because the fork shell code changed only where this merge had dropped it — the tree is restored to the shell the fork already shipped plus upstream's engine work.
