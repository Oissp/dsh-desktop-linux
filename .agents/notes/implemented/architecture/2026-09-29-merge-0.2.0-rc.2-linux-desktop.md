# Agent Note: 0.2.0-rc.2 merge — the Linux desktop command surface

Status: implemented

English | [中文](2026-09-29-merge-0.2.0-rc.2-linux-desktop.zh.md)

## Problem

Upstream 0.2.0-rc.2 is 187 commits over 1022 files. Most of it is product work the fork takes unchanged: the workspace opens from the sidebar file tree, long-session rendering and the whale animation are reworked, timed user-question replies arrive with their persistence change record, `pi-ai` moves to 0.87.1 with Mistral in the compatibility checks, settings stop gating the Creator entry on the code-work tool switch, and ACL failures are diagnosed and repaired in one run.

The Desktop half carries a new user-facing feature, **Manage dsh Command…**: a native menu that installs, repairs and removes a `dsh` command in the terminal, backed by terminal launcher scripts, a private CLI entry in `apps/desktop-host`, an elevated install worker, and its dialogs. The same range adds a login-shell environment read that runs before the first Host, and installer ownership and rollback hardening.

Eighteen conflicts needed a decision. Ten were modify/delete pairs inside [sync-trimmed-paths.txt](../../../../.github/sync-trimmed-paths.txt). `apps/desktop/package.json` and the root `package.json` both rewrote the desktop script block, where the fork carries Linux packaging scripts and upstream the mac, win and upload ones. `pnpm-workspace.yaml` and `pnpm-lock.yaml` carried the fork's `libreoffice-kit@0.1.2` patch against upstream's `pi-ai@0.87.1` bump. `apps/desktop/scripts/prepare-dsh.ts` and `prepare-runtime.ts` are the fork's Linux-only rewrites. `THIRD_PARTY_NOTICES.md` is generated, and `apps/desktop/README.i18n.yaml` records a pairing both sides had edited.

## Decision

**The desktop command-installation feature is trimmed.** It has no Linux code path: the menu entry is gated to `darwin` or `win32` in `main.ts`, `prepareDesktopCli()` accepts only those two platforms, `prepare-command-link.ts` compiles a macOS helper with `clang`, and the two launchers are a macOS app-bundle script and a Windows `.cmd`. Twenty-eight paths join the trim list: the launchers, the private CLI entry and its Windows console-signal shim, the install worker, the manager and its dialogs, and the mac-only tests, fixtures and expected outputs that arrived with them. `apps/desktop-host` drops the `koffi` dependency and the three CLI devDependencies that only served the bundled profile, and both `tsdown` configs return to the fork's entries.

**`login-shell-environment.ts` and its `duration-env.ts` extraction stay.** The read is POSIX-generic, returns the inherited environment unchanged on `win32`, and takes the login shell from the account record rather than `$SHELL`. The fork's Linux launcher has the same gap the macOS Dock and Finder do: a `.desktop` launch inherits only the session manager's environment, so `~/.profile` exports never reach the Host, agent shells or terminals.

**The Desktop README keeps the merged prose, not the feature's.** The `Terminal command` and `Bundled command runtime` sections are removed from both language files because they describe a menu entry the fork does not show, and the `Installation ownership` sentence returns to `The CLI cannot boot or mutate this profile.` The new `Host environment` section stays: it documents the login-shell read. The pairing hashes are re-recorded.

**The two fork-owned gates learn the trimmed shape.** `scripts/check-workspace-constraints.ts` requires only `lib/index.js` from `apps/desktop-host`, because the trimmed CLI entry is what would have produced `lib/cli.js`. `scripts/rescope-vendor.ts` gains the three new extensions-event-domain files in `GENERIC_SKIPS`, the list that already records `cordis/*` as an event namespace rather than a package subpath.

## Alternatives considered

**Carry the feature as inert code.** Rejected: every layer of it is unreachable on Linux, so the fork would maintain locale copy, a `tsdown` worker bundle and a runtime-payload requirement that nothing invokes, and resolve the same conflicts at every release.

**Trim only the packaging and keep `src/command-*.ts`.** Rejected: the manager is constructed in `main.ts` and its dialogs are reached from strings the fork would have to keep, so the trim boundary would still cut through the feature.

**Ship a Linux launcher and enable the menu.** Rejected as a product change: upstream has written no Linux launcher, and the fork's job at a merge is to carry upstream's work, not to extend it.

**Keep `lib/cli.js` in the constraints table and emit a stub.** Rejected: a stub the fork never runs is the inert code the trim removes, and the constraint would stop describing the shipped payload.

**Accept the rescope codemod's rewrite of `cordis/inspect-query`.** Rejected: the codemod's quote rule cannot tell a package subpath from the extensions event domain, and the rewrite broke 13 `cordis-host-runner` tests because the emit side keeps the literal name.

## Consequences

Future syncs resolve the twenty-eight paths to the fork's deletion by reading the trim list. The fork's application menu carries no command-registration entry, so terminal users install `dsh` from npm or run the bundled profile. `scripts/check-workspace-constraints.ts` and `scripts/rescope-vendor.ts` are now fork-divergent tables and will need the fork's side when upstream edits them. The Desktop version moves to `0.2.0-rc.2.1`, tracking the engine base as it did through the 0.1.x line. The per-release merge notes stay active: each records its own upstream range, and none supersedes another.

## Testing

`pnpm run typecheck` and `pnpm run lint` are clean. `pnpm run test:docs` reports 21 passed and 0 failed, including `markdown links`, which reads the extended trim list, and `translation pairing`, which validates the re-recorded README pair. `pnpm exec vitest run apps/desktop/tests apps/desktop-host/tests` passes 789 tests across 71 files, and `pnpm exec vitest run packages/extensions/cordis-host-runner` passes 114 after the skip-list correction. `pnpm run test:snapshot -t cordis-inspect` passes its 3 cases. `pnpm run test` reports 10 failing files, none caused by the merge: six CI-workflow specs read `.github/workflows/ci.yml` and its siblings, which the fork does not carry; `executor`, `spawn-runner` and `helper-processes` fail the same way on this host before the merge; and `checkers` passes when run alone. `pnpm run hygiene` reports the same two pre-existing failures on both sides of the merge — `constraints` requires `@deepseek-ai/dsh-desktop` to equal the root version, which the fork's build suffix never does, and `publint` reports the `./src/*` export of 300 package publication views that declare no `src` in `files` — while `vendor rescope` now passes.
