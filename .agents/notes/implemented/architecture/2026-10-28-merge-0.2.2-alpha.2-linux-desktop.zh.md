# Agent Note: 0.2.2-alpha.2 合并 —— 保留 fork 的壳，采纳上游的诊断工作

Status: implemented

[English](2026-10-28-merge-0.2.2-alpha.2-linux-desktop.md) | 中文

## Problem

上游 `master` 在上一个同步点（0.2.1-rc.3 的合并提交）之后推进了 637 个提交，并发布了引擎 `0.2.2-alpha.2`；tag `dsh-v0.2.2-alpha.2` 指向合并目标。增量改动 2118 个文件、新增 711 个，其中有七个新包——`experimental/client-ui-forge`、`experimental/client-ui-stats`、`experimental/forge`、`experimental/forge-bundle`、`experimental/forge-github`、`experimental/forge-session` 与 `experimental/liveshare`——以及 39 个快照文件，还有 Desktop 壳现在驱动的操作报告与诊断界面（`operation-report.ts`、`operation-report-job.ts`、`operation-report-worker.ts`、`locale-cache.ts` 与 `apps/desktop-host` 下的诊断模块）。

本次合并产生八个内容冲突与四十二个 modify/delete 冲突。每个 modify/delete 冲突都落在裁剪清单内的路径上，因此清单本身即可解决，不需要判断。八个内容冲突是 `apps/desktop/package.json`、`apps/desktop/scripts/desktop-build-paths.mjs`、`apps/desktop/src/main.ts`、`apps/desktop/tsdown.config.ts`、`docs/development.i18n.yaml`、`package.json`、`packages/ptc-runtime/ptc-runtime-node/tsdown.config.ts` 与 `pnpm-lock.yaml`。

fork 没有 `packages/` 分叉，因此上游的引擎工作原样进入；冲突落在壳、它的构建配置与清单上。

## Decision

**本次合并再裁剪九个上游文件，裁剪清单从 407 条增至 416 条。** 三个 `pr-check-*.yml` 通过上游组织的 `deepseek-harness-check` action 与仓库变量在 `master` 上运行上游的合并策略检查；fork 的默认分支是 `main`，两者都不携带，因此它们永远不会运行。`macos-intel-package.yml` 归入已裁剪的 macOS 打包 workflow。`scripts/desktop-package-forms.spec.ts` 读取这三个已裁剪的打包 workflow。`desktop-edgeone.ts` 是腾讯云 EdgeOne 的发布与清理管线，`desktop-publish-targets.ts` 是上游的多平台发布路由表，唯一调用方是已裁剪的发布脚本；二者在 fork 中是孤儿文件，随附的两个 spec 与断言已裁剪 `purge:latest` 脚本链的 `purge-command.spec.ts` 一并裁剪。`tencentcloud-sdk-nodejs-teo` devDependency 只为 `desktop-edgeone.ts` 而存在，随之去掉。另两个读取同一批 workflow 的 reader —— `scripts/macos-package-workflow.spec.ts` 与 `scripts/desktop-publish-workflow.spec.ts` —— 已另行裁剪，清单因此增至 418 条（[笔记](2026-10-28-trim-trimmed-workflow-readers.zh.md)）。

**`main.ts` 采纳上游的语言缓存初始化，保留 fork 的 Linux 壳状态。** 上游现在用 `readDesktopLocaleCache` 初始化 `windowsLanguage`，并据此解析启动语言。冲突解决保留该初始化，随后接上 fork 的模块级托盘引用、外观辅助函数与 `rebuildTrayMenu`，并用上游的 `windowsLanguage` 分支加 fork 的托盘重建槽位解析 `locale`。fork 的托盘、外观与菜单栏行为没有任何改变。

**Desktop 打包保留 fork 的 command-manager 入口，采纳上游新增的 operation-report worker 入口。** 上游新增了第二个 `command-manager-entry` 打包块，其输出文件正是 fork 自己的块已经产出的那个；两个都留会重复构建 `lib/command-manager-entry.js`。fork 的块保留，同时加入上游的 `operation-report-worker` 入口，因为壳现在会启动该 Worker，而打包文件清单已随 `lib/*.js` 覆盖它。

**PTC Node 运行时保留 fork 的打包写法，采纳上游的新入口。** `deps: { alwaysBundle }` 保留——它是 [`2026-09-25-fork-build-config-edits`](../process/2026-09-25-fork-build-config-edits.zh.md) 记录的、对已弃用 `noExternal` 的当前写法——解决结果加入上游的 `configuration.js` 入口，并把 `acorn` 与 `acorn-walk` 加进两个进程 bundle。

**清单保留 fork 的打包面。** `package.json` 与 `apps/desktop/package.json` 解决为 fork 的 Linux-only 脚本、author 与 homepage；被删除的 macOS/Windows 打包与上传脚本保持在外，`desktop-build-paths.mjs` 的 `desktopTargetPlatform` 继续返回 Linux x64。桌面版本提升到 `0.2.2-alpha.2`，等于引擎版本，因为本次同步没有改变壳行为。

**`apps/desktop` 去掉包内的 React 类型依赖。** `main` 声明了 `@types/react` 与 `@types/react-dom`，而根清单已提供两者；上游删除了自己的局部副本，`verify-package-dependencies` 也强制根-only 规则。合并后的清单不再声明它们，TypeScript 的 JSX 检查使用提升到根的这些类型。

**锁文件先取存活 importer 条目的并集，再重新生成。** fork 的 `tar` 与上游的 `tencentcloud-sdk-nodejs-teo` 都在合并中存活，其余冲突块取上游的 `form-data@2.5.6` 与 `form-data@3.0.5` 记录；随后 `pnpm install --no-frozen-lockfile` 产出最终文件，最终差异只有删除。

**诊断文档在两种语言中链接同一目标。** `apps/desktop/docs/diagnostics/README.zh.md` 原本指向 `../../tests/README.zh.md`，但 fork 裁剪了 `apps/desktop/tests/README` 双语对，配对检查因此无法再把两个语言侧折叠成同一个语义目标。中文页现在链接 `../../tests/README.md`，与英文页目标相同；该链接在两种语言里都指向被裁剪的路径，`verify-md-links-trimmed` 予以豁免。

## Alternatives considered

**把上游的 `command-manager-entry` tsdown 块与 fork 的块并排保留。** 否决：两个入口都产出 `lib/command-manager-entry.js`，第二个要么覆盖第一个，要么依赖构建顺序。

**保留三个 `pr-check-*.yml`，因为它们在 fork 中不会运行。** 否决：它们面向 `master` 并调用上游组织的 action，而裁剪清单的职责就是让工作树只包含 fork 实际运行的内容。它们在场还会让 `scripts/ci-workflow.spec.ts` 读取 fork 不使用的 workflow 文件，从而错误描述 fork 的 CI。

**恢复 `apps/desktop/tests/README` 双语对，让诊断文档的链接可解析。** 否决：那份 README 描述的是 fork 已裁剪的 installed-update、macOS 与 Windows 打包管线；恢复它等于重新带回工作树并不携带的脚本说明。

**把两个诊断页面都改写以删除失效链接。** 否决：被裁剪的目标本就在豁免范围内，只改一处链接目标即可让两种语言都保留上游文本，并让英文页与上游逐字节一致。

**从清单整体重新生成锁文件，而不是合并它。** 否决：全新解析会移动无关的传递版本，并掩盖本次合并的真实影响——这里只是删除了一个依赖的子树。

## Consequences

下一次同步从上游 `master` 的 tag `dsh-v0.2.2-alpha.2` 开始。裁剪清单记录 416 条路径，`.github/sync-forked-paths.txt` 现记录 28 条 fork 修改路径，其中诊断文档的链接是唯一新增。

`scripts/ci-workflow.spec.ts` 仍会读取已裁剪的 workflow——它本来就读已裁剪的 `ci.yml`——因此它仍是 fork CI 不运行的仓库级测试失败；`package-deb-test.yml` 只收集 `apps/desktop/tests`。

诊断文档随它所描述的壳一起发布。`apps/desktop/README.md` 跟随上游，其中指向已裁剪 `apps/desktop/packaging/` 指南的链接已由裁剪清单的链接豁免覆盖。

## Testing

`scripts/verify-sync-trimmed-paths.sh` 及其 `--staged` 形式确认全部 416 条裁剪路径都不存在于工作树与索引。本 fork 早前记录规定的丢失改动检查——双方都改过的每个路径对照上游 blob——没有报告任何在 `main` 已分叉的情况下与上游相同的文件，并且 fork 自同步点以来修改过的全部 213 个路径仍然存在。

`pnpm run typecheck` 报告五个门禁通过，`pnpm run build:artifacts` 八个，`pnpm run build:check` 两个；构建产物必须在带开发头的 Node 安装下运行，因为原生插件要针对 `include/node` 编译。`pnpm run lint` 报告零错误，以及上游 `packages/experimental/client-ui-cot-translation` 中的一条警告（未使用的 `oxlint-disable` 指令）。`pnpm run test:docs` 通过全部 21 个门禁，其中包括覆盖 1156 对双语文档的配对检查。`pnpm exec vitest run apps/desktop/tests` 通过 86 个文件、1039 个测试，另有五个跳过。去掉包内 React 类型依赖后，`verify-package-dependencies` 报告 93 个包符合发布策略。

`pnpm run hygiene` 在本机通过 23 个门禁中的 22 个。`verify-optional-dependency-imports` 在这台 7 GiB 机器上耗尽默认 V8 堆，加上 `--max-old-space-size=6144` 后通过。`rescope-vendor:check` 因 `ENOBUFS` 失败：它用 `execFileSync` 读取 `git ls-files -z` 而未提高 1 MiB 的默认缓冲，而本 checkout 的路径名在 `main` 上就已超出（合并前 1.1 MB，合并后 1.16 MB）。
