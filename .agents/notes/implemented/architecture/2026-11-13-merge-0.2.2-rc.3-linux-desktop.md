# Agent Note: 0.2.2-rc.3 upstream sync — the fork trims the publisher workspace and follows upstream's Desktop authentication

Status: implemented

English | [中文](2026-11-13-merge-0.2.2-rc.3-linux-desktop.zh.md)

## Problem

Upstream `master` advanced 448 commits past the parent that `dsh-v0.2.2-rc.2` forked from and cut `0.2.2-rc.3`. The delta changes 3262 files — 517 added, 45 deleted, 2652 modified, 48 renamed — with 93416 insertions and 34804 deletions. It splits the Desktop release tooling into a new `apps/desktop-publisher` workspace, gives Desktop its own Host authentication (`apps/desktop-host/src/authentication.ts`, `apps/desktop/src/parent-authentication.ts`), makes `@deepseek-ai/dsh-error` a Desktop production dependency that the standalone command-manager worker inlines, retires Python PTC, and lands CUA MCP, the experimental Timeline plugin, DeepSeek chat export import, the Forge change panel, Host authentication packages, and `dsh-cua-macos`/`dsh-cua-windows` package renames. It also renames `.github/workflows/cua-helper-package.yml` to `cua-helper-package-macos.yml` and bumps the Desktop Host lifecycle protocol to 5.

Merging produced 115 conflicts: 104 modify/delete conflicts and 11 content conflicts (`apps/desktop/README.md`, `README.zh.md`, the pairing record, `README.i18n.yaml`, `package.json`, `scripts/desktop-build-paths.d.mts`, `scripts/development-project.ts`, `scripts/package-target.ts`, `src/main.ts`, `tsdown.config.ts`, and the CUA native README pair plus its pairing record). Sixty of the modify/delete conflicts were on already-trimmed paths; the other 44 were files that upstream moved into `apps/desktop-publisher`.

## Decision

**The merge adopts upstream's Desktop authentication and worker bundling, and trims the whole publisher workspace.**

`apps/desktop-publisher/` is trimmed as one directory entry instead of 53 file entries. Upstream declares it from `apps/desktop` as a devDependency, so leaving it present would add a real workspace member to every gate: the `apps/*` tsconfig globs, `check-workspace-constraints`, and the lockfile. The 44 historical entries that named its former `apps/desktop/scripts` and `apps/desktop/tests` paths left the trim list because the files no longer exist upstream; `apps/desktop-publisher/` covers them, and `.github/workflows/cua-helper-package-macos.yml` replaces the renamed workflow entry. The trim list records 404 paths plus that directory. `scripts/verify-sync-trimmed-paths.sh --stale upstream/master` confirms every entry still resolves in the upstream tree.

`apps/desktop/package.json` takes upstream's `0.2.2-rc.3` version, the `@deepseek-ai/dsh-error` production dependency and the `dsh-brand`, `dsh-client-connection`, `dsh-host-authentication-desktop` and `dsh-host-webserver` devDependencies, and keeps the fork's product name, author, homepage, Linux-only scripts and its removal of `tencentcloud-sdk-nodejs-teo` and `@deepseek-ai/dsh-desktop-publisher`. `apps/desktop/tsdown.config.ts` keeps the fork's relocated command-manager worker block and adds upstream's `@deepseek-ai/dsh-error` to its `alwaysBundle` list.

`apps/desktop/src/main.ts` takes upstream's private Host-authentication flow: `authenticateWebHost` disappears with upstream's `web-document.ts` change, and the shell uses the cookie the owned Host reports in `ready.authenticationCookie`. The fork's `DesktopCommandManager` import stays; upstream moved that import upward, which the merge duplicated.

`apps/desktop/scripts/desktop-build-paths.d.mts`, `scripts/development-project.ts` and `scripts/package-target.ts` keep the fork's `DesktopBuildTargetName = 'linux-x64'` and its Linux-only imports, since upstream's versions reference the trimmed publisher package.

`apps/desktop/README.md`, `README.zh.md` and their pairing record take upstream's `dsh-error` paragraph and drop the links to the trimmed packaging, signing, publication and publisher guides, keeping the fork's Linux packaging link. The CUA native README pair points both languages at `cua-helper-package-macos.yml`.

`pnpm-lock.yaml` drops the `apps/desktop-publisher` importer and the Desktop dependency on it, and `tsconfig.base.json`, `tsconfig.host.json` and `scripts/check-workspace-constraints.ts` drop their publisher paths and exemptions. The frozen install needs no other regeneration.

The fork's engine cache action gains `packages/util/error/lib`: `dsh-error` is now a Desktop production dependency that electron-builder packs, and a cache-backed `--builder-only` build would otherwise ship a main process without it. The fork-added patched-dependency cases in `apps/desktop/tests/core-package-set.spec.ts` read `DESKTOP_HOST_PROTOCOL_VERSION` instead of a hardcoded 4, because upstream advanced the protocol to 5.

**The desktop version equals the engine version, `0.2.2-rc.3`, with no build counter.** The fork's release repository has no `v0.2.2-rc.3` yet.

## Alternatives considered

**Keep `apps/desktop-publisher` and trim only the scripts the Linux build never runs.** Rejected: it is a real pnpm workspace member with its own COS, EdgeOne and macOS/Windows signing dependencies, and every gate that enumerates `apps/*` would have to special-case it.

**List all 53 publisher files individually.** Rejected: the directory entry matches the pre-existing `apps/desktop/tests/installed-update/` and `apps/desktop/tests/updates/electron-updater/` entries, and one entry cannot drift out of sync with upstream's file list.

**Keep the hardcoded `hostProtocolVersion: 4` in the fork-added spec cases.** Rejected: `parseDesktopRelease` rejects any value below the current constant, so the cases would fail on every run after the protocol bump.

**Leave the engine cache action unchanged.** Rejected: the cache-hit path skips prepare, and `package-target.spec.ts` fails when the list misses a packaged workspace package; the released application would then fail at launch instead.

**Bump the desktop version to `0.2.2-rc.3.1`.** Rejected: the merge changes no fork-authored shell behavior, and its release history separates build-counter bumps from sync merges.

## Consequences

The next sync starts from upstream `master` beyond tag `dsh-v0.2.2-rc.3`. The trim list records 404 paths and the fork baseline 81 entries. Python PTC is gone from both trees, so the fork carries no `packages/experimental/ptc-runtime-python` residue; CUA now ships as `dsh-cua-macos` and `dsh-cua-windows`, and its macOS packaging workflow is named `cua-helper-package-macos.yml`.

`pnpm run hygiene` fails on this host with an out-of-memory abort in `verify-plugin-entry-exports`; the same gate needs a 5120 MiB heap on a 7 GiB machine, and the run was recorded rather than retried indefinitely.
