# Agent Note: 0.2.2-alpha.3 上游同步 —— fork 采纳上游的更新配置界面并保留单一更新源策略

Status: implemented

[English](2026-11-03-merge-0.2.2-alpha.3-linux-desktop.md) | 中文

## Problem

上游 `master` 相对上一个同步点（tag `dsh-v0.2.2-alpha.2` 之后 351 个提交）又推进了 666 个提交，并发布了 `0.2.2-alpha.3`。增量改动 2654 个文件——新增 399、删除 111、修改 2108、重命名 36——把 agent-team 系列包从 `packages/experimental` 移到 `packages/team` 与 `packages/client/ui-agent-team`，退役 `agent-team-profile`，移除 `web-search-exa` 与 `web-search-perplexity`，新增 `packages/mcp/mcp-manager`，并围绕设置文件重建桌面的更新界面：在设置中选择渠道、配置失败后的重新读取、按原因区分的下载诊断，以及重写的协调器。

本次合并产生 53 个冲突：45 个落在裁剪清单内的 modify/delete 冲突，以及 8 个内容冲突（`apps/desktop/package.json`、`apps/desktop/src/main.ts`、`apps/desktop/src/locale.ts`、`apps/desktop/src/update-coordinator.ts`、`apps/desktop/tests/update-coordinator.spec.ts`、`docs/development.i18n.yaml` 与 CUA 原生 README 双语对）。fork 没有 `packages/` 分叉，因此上游引擎工作原样进入；取舍落在桌面壳的更新策略、语言字典与同步清单上。

## Decision

**合并采纳上游的更新配置界面，同时保留 fork 的单一更新源策略与 Linux 壳。**

`apps/desktop/src/update-coordinator.ts` 采纳上游重写的协调器——带配置错误的渠道状态，以及区分已检查、已下载与已交接版本的发布状态机——但调用 fork 的 `selectFeedChannel` 而不是上游的 `selectUpdateChannel`。本 fork 用同一个 `latest-linux.yml` 服务所有发布，因此所选渠道只决定是否接受预发布；把 `updater.channel` 钉成 `'nightly'` 或 `'stable'` 会让 GitHub provider 无法解析 fork 的 `v<桌面版本>` 发布 tag，并以 `ERR_UPDATER_NO_PUBLISHED_VERSIONS` 失败。`update-coordinator.spec.ts` 钉住 `updater.channel === undefined` 以及 nightly 渠道只影响预发布接受。

`apps/desktop/src/main.ts` 采纳上游的异步 `readDesktopSettings`、更新配置消息与 `removeLegacyHostCookies` 接线，并保留 fork 的打包 Linux `Menu.setApplicationMenu(null)`、镜像显示主窗口、检查更新、管理 dsh 命令与退出的托盘菜单、跟随外观的窗口与托盘图标，以及只存在于托盘中的 desktop-cli 入口。

`apps/desktop/src/locale.ts` 采纳上游新增的更新配置与下载失败文案（覆盖所有语言），并保留 fork 的托盘文案。

`apps/desktop/package.json` 保留 fork 的产品名、作者、主页与 Linux 专用打包脚本，去掉上游的 macOS 与 Windows 脚本及其签名依赖；相对上一个 fork 版本只有版本号一行变化，取上游的 `0.2.2-alpha.3`。

`apps/desktop/README.zh.md` 保留 fork 指向 `LINUX_PACKAGING.md` 的链接，去掉指向已裁剪的打包、发布与 Windows 签名指南的链接；其 Electron updater 兼容性链接改为指向英文 `tests/updates/electron-updater/README.md`，与英文页一致，因为本次同步裁剪了整个目录。CUA 原生 README 沿用[上一次同步](2026-10-30-merge-0.2.2-alpha.2-linux-desktop.zh.md)记录的单目标决定。

**再裁剪三条上游路径，裁剪清单从 425 增至 428。** `apps/desktop/scripts/test-update-channels.mjs` 只在 Windows 与 macOS 运行，并读取紧随其后的平台版本记录；`apps/desktop/tests/updates/electron-updater/` 为同一资格流程携带这些记录与双语 README；`scripts/cua-helper/package.spec.ts` 导入已裁剪的 `scripts/cua-helper/package.ts`，在导入阶段即失败。fork 只发布 Linux，也不运行这些流程。

**桌面版本等于引擎版本 `0.2.2-alpha.3`，发布无需构建计数提升。** fork 的发布仓库还没有 `v0.2.2-alpha.3`，合并落到 `main` 后打包 workflow 会发布该版本；`.N` 计数保留给同一引擎版本上的后续构建。版本一致也让 `check-workspace-constraints` 保持通过，因为 `@deepseek-ai/dsh-desktop` 必须与根版本一致。

## Alternatives considered

**保留上游的 `selectUpdateChannel`。** 拒绝：fork 只发布一个 `latest-linux.yml` 更新源，并用桌面版本给发布打 tag；钉住渠道会破坏 GitHub provider 的 tag 解析，而不是切换到另一个更新源。

**携带 electron-updater 平台记录，让 README 链接留在代码树内。** 拒绝：该目录记录 Windows 与 macOS 的渠道资格流程，而 fork 不运行其中的脚本，裁剪清单的链接豁免已在两种语言里覆盖该链接。

**恢复 `scripts/cua-helper/package.ts` 及其 macOS 签名依赖，让该 spec 能运行。** 拒绝：fork 不携带 macOS 打包流水线；只为让一个孤立 spec 通过编译而恢复流水线，会把已裁剪文件重新带回，[上一次同步](2026-10-30-merge-0.2.2-alpha.2-linux-desktop.zh.md)已记录同样理由。

**在合并提交里提升桌面版本号。** 拒绝：同步合并与构建计数提升保持分离，桌面版本与引擎版本一致也能让 `check-workspace-constraints` 保持通过。

**重新生成 lockfile 而不是接受合并后的文件。** 拒绝：`pnpm install --frozen-lockfile` 接受合并后的 lockfile，重新解析只会移动无关的传递依赖版本。

## Consequences

下一次同步从上游 `master` 的 `dsh-v0.2.2-alpha.3` tag 之后开始。合并落到 `main` 的 push 会触发打包 workflow，在 fork 的发布仓库发布 `v0.2.2-alpha.3`，无需版本提升；`chore(desktop): 版本提升到 0.2.2-alpha.3.N` 留给同一引擎版本上的后续构建。

裁剪清单记录 428 条路径；`.github/sync-forked-paths.txt` 保持 34 条。上游退役了 `agent-team-profile`，并把 agent-team 系列包移到 `packages/team` 与 `packages/client/ui-agent-team`；`@deepseek-ai/dsh-experimental-agent-team-profile` 加入 `RETIRED_BUNDLES`。

两项验证失败是继承而来而非本次引入。`scripts/rescope-vendor.ts --check` 仍期待上游重写 `vendor/README.md` 前的 `17. **@deepseek-ai rescope**` 后置条件文本，并报告上游文档中残留的改名前的名称 token；该检查在 fork 的 `main` 上同样失败。仓库级单元测试仍会读取已裁剪的 workflow，`scripts/ci-workflow.spec.ts` 现在还读取已裁剪的 `apps/desktop/tests/updates/electron-updater/check-versions.mjs`。
