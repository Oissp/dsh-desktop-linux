# Agent Note: 0.2.1-alpha.3 合并——桌面发布管线裁剪，更新频道与 CUA 到来

Status: implemented

[English](2026-10-15-merge-0.2.1-alpha.3-linux-desktop.md) | 中文

## Problem

上游 `master` 在上一次同步之后前进 868 个提交，发布引擎 `0.2.1-alpha.3`；本次合并目标是该 tag 之后 16 个提交的上游 head。增量改动 3325 个文件，覆盖五个领域：桌面发布管线（经批准的 COS 上传 workflow、保留包发布、发布批准摘要、带可选公证的 macOS 打包 runner 服务，以及一个 `app-builder-lib` 补丁）、更新频道拆分（nightly 与 latest 频道、批准前确认发布）、CUA（新增 `packages/experimental/cua` 与 `packages/experimental/cua-macos`、截图像素映射、悬停保持）、远程访问 RBAC（新增 `packages/api/remote-access`、显式对端上的调用者主体、远程方法与事件资源），以及客户端工作（新增 `ui-secret-mask` 与 `harness-dev-context` 包、插件功能预览、web 字号快捷键、profile 重组时的 HMR 插件替换）。

合并产生 63 处冲突。45 处修改/删除对命中被裁剪的 workflow 与桌面脚本路径。18 处内容冲突命中 fork 修改路径文件（`package-target.ts`、`prepare-dsh.ts`、`electron-builder.config.d.mts`）、桌面清单、三个 `tsdown` 配置、`main.ts`、`update-coordinator.ts`、`desktop-build-paths.mjs`、`pnpm-workspace.yaml`、`pnpm-lock.yaml`、`THIRD_PARTY_NOTICES.md` 与双语配对记录。

约 100 个上游新增文件落在被裁剪的桌面发布与 macOS/Windows 打包范围内：两个 workflow、28 个发布与平台 CI 脚本、22 个测试、打包/签名配置以及平台 README。两个自动合并的上游测试断言了 fork 未实现的行为。上游还重构了文档链接门禁，从 `scripts/verify-md-links.ts` 移除 `anchorCache`，改为每次运行共享的 `markdownLinkCache()`。

## Decision

**所有修改/删除冲突保留 fork 的删除。** 45 条被裁剪路径用 `git rm` 移除，以维持 fork 的 Linux-only 定位。

**fork 修改路径的源文件保留 fork 版本。** 上游在 `package-target.ts`、`prepare-dsh.ts` 与 `electron-builder.config.d.mts` 中的增量是 macOS 公证、Windows 签名与发布路由。fork 的 `prepare-dsh.ts` 保留自己内联的 `applyRuntimePatches`；其 `prepare-runtime.ts` 导入 `../../../scripts/primary-runtime/prepare.ts`，而非上游的 `prepare-primary-runtime.ts`。

**`apps/desktop/package.json` 保留 fork 元数据并接受上游版本号。** `author` 与 `homepage` 仍指向 fork 仓库。版本提升到 `0.2.1-alpha.3`（与引擎版本一致）。fork 保留 `tar`（运行时目录树打包），省略 `koffi`、`cos-nodejs-sdk-v5` 与 `@electron/notarize`（仅 mac/win）。`sharp` 采用上游锁定的 `0.35.5`。

**`apps/desktop-host/package.json` 接受上游新增的 `devDependencies`**（`@deepseek-ai/cordis-plugin-loader`、`@deepseek-ai/cordis-plugin-include`、`@deepseek-ai/dsh-skill`），并省略 `koffi`。

**三个 `tsdown` 配置合并双方内容。** 根配置保留 fork 的桌面打包注释，并采用上游的 `[...packages, 'apps/cli', ...]` 展开写法。`benchmarks/tsdown.config.ts` 保留 fork 的 `client-bundle-composition.worker` 条目并新增上游的 `user-text.worker` 条目。`ptc-runtime-node/tsdown.config.ts` 保留 fork 的 `deps.alwaysBundle` API 形式并新增上游的 `persistent-process` 条目。

**`main.ts` 保留 fork 的 Linux 托盘并接受上游更早的 manifest 读取。** fork 代码块中重复的 `const manifest` 被删除，因为上游把该读取移到了策略代码块之前。合并后的 `DesktopUpdateCoordinator` 调用传入自动合并的 `updateChannel` 实参，合并后的构造函数以未使用的 channel 形参接受它。

**`update-coordinator.ts` 保留 fork 的构造函数体，不设置 `updater.channel`。** 上游的 `channel` 形参与 `this.channel === 'latest'` 判断干净合并并保留；只丢弃 `this.updater.channel = channel`。fork 的 release tag 形如 `v<desktop version>`，钉住 `updater.channel` 会让 GitHub provider 完全解析不出 tag。

**`desktop-build-paths.mjs` 保留 fork 的 `linux-x64` 目标类型，并在 JSDoc 返回类型中接受上游的 `unnotarizedArtifacts` 字段。**

**`pnpm-workspace.yaml` 与 `THIRD_PARTY_NOTICES.md` 保留 fork 的 `libreoffice-kit@0.1.5` 条目并接受上游的 `pi-ai@1.1.0` 条目。**

**发布管线与平台打包范围被裁剪，新增 70 条（276 → 346）。** 覆盖发布与回滚脚本、macOS/Windows runner 与签名脚本、mac/win 打包配置、平台 README，以及导入被裁剪模块的测试。

**SSH helper workflow 被裁剪，新增 2 条（346 → 348）。** `build-exe-for-ssh-helper.yml` 用 `pkg` 编译一个独立的 SSH helper 可执行文件（四个原生 Node 24 目标），`publish-ssh-helper.yml` 把校验过的压缩包发布到 GitHub Release。该 helper 是可选的远程执行产物；fork 的 `prepare-dsh.ts` 与 `prepare-runtime.ts` 不引用它，`apps/desktop/package.json` 不依赖 `@deepseek-ai/dsh-ssh`，`package-deb.yml` 也不调用这两个 workflow。它们从 fork 建立至今从未运行。需要 SSH 执行能力的桌面用户从上游 Release 获取 helper 即可。

**两个自动合并的上游测试回退到 fork 版本。** `update-coordinator.spec.ts` 新增的上游测试断言 `updater.channel` 为 `'nightly'`/`'latest'`，与 fork 的 no-channel 决策及其自身的 `expect(f.updater.channel).toBeUndefined()` 断言矛盾。`package-target.spec.ts` 新增的上游测试打包 `mac-arm64` 目标并传入 `--skip-notarization`，两者都被 fork 的目标解析器拒绝。

**桌面 README 保留 fork 版本。** 上游把单体的 `apps/desktop/README.md` 拆成 `apps/desktop/packaging/`、`apps/desktop/publishing/` 与 `apps/desktop/windows-signing/` 下的专题 README，这些文件在本 fork 全部被裁剪。fork 的 README 带有自己的 Linux shell 提示文本，并省略上游的 Terminal 命令注册章节——后者描述的是 macOS 与 Windows 的路径改动。

**上游指向被拆出 README 的成对文档改为指向 fork 的单体 `apps/desktop/README.md`。** 两个随包携带的桌面对文档保留上游正文，并把 `apps/desktop/packaging/README.md` 与 `apps/desktop/publishing/README.md` 链接改指到仍存在的 README，与本次同步前 fork 使用的目标一致。

**`scripts/verify-md-links-trimmed.ts` 迁移到新的链接门禁 API。** 上游重构把 `anchorCache()` 换成每次运行共享、传给 `findViolations` 的 `markdownLinkCache()`；fork 的裁剪感知包装脚本跟随该签名，门禁才继续可运行。沿用旧调用会让包装脚本导入已被移除的导出，类型检查与 `no-unsafe-*` lint 规则都会报错。

## Alternatives considered

**采用上游发布管线。** 拒绝：它上传到 COS 并发布保留的多平台构建，而 fork 的 `package-deb.yml` 用 `gh release` 直接从 deb 与 AppImage 产物创建 GitHub Release。这些发布脚本还导入已被裁剪的 `desktop-upload-plan.ts` 与 `desktop-cos.ts`，在本 fork 上是孤儿代码。

**设置 `updater.channel` 并保留上游的 channel 测试。** 拒绝：fork 的预发布 tag 携带桌面版本号，而 GitHub provider 中 `updater.channel` 优先于版本号自带的预发布段。把它钉成 `latest` 会让 `shouldFetchVersion` 与 `isNextPreRelease` 都不成立，解析不出 tag，检查更新抛 `ERR_UPDATER_NO_PUBLISHED_VERSIONS`。

**保留自动合并的 macOS 公证测试并在 Linux 上跳过。** 拒绝：该测试用 `mac-arm64` 与 `--skip-notarization` 调用 `parseDesktopPackageInvocation`，而 fork 的解析器既没有该目标也没有该标志。跳过的测试会在暗示有覆盖的同时让解析器的拒绝路径失去覆盖。

**裁剪 `packages/experimental/cua-macos`。** 拒绝：裁剪清单从未包含 `packages/` 条目，且该包在 Linux 上是惰性的——桌面 shell 与默认 profile 都不引用它。保留它让包图与上游一致，并使后续同步少一处分歧。

**保留 SSH helper workflow。** 拒绝：`build-exe-for-ssh-helper.yml` 与 `publish-ssh-helper.yml` 编译并发布一个独立的 SSH helper 可执行文件，与 deb/AppImage 桌面包无关。fork 的运行时准备不引用它，`package-deb.yml` 不调用它们，且它们从未在 fork 上运行。保留它们只会发布上游已从自己的 Release 发布的相同二进制。

## Consequences

下一次同步从 `dsh-v0.2.1-alpha.3` tag 之后 16 个提交的上游 head 开始。裁剪清单增加 72 条，达到 348 条路径。

fork 的 `update-coordinator.ts` 现在带有一个未使用的 `channel` 构造形参。它存在只是因为上游的声明与强制更新策略身份共用它；移除它会在每次同步时重新打开冲突，而 `this.updater.channel` 仍保持未设置。

全部九个被补丁的依赖都解析到上游解析的版本。八个补丁文件与上游逐字节相同；仅 fork 独有的 `@deepseek-ai/libreoffice-kit@0.1.5` 补丁保留，因为它跟随的 kit 本体不在上游的引擎选择补丁范围内。

`scripts/verify-md-links-trimmed.ts` 是上游链接门禁内部实现的唯一 fork 消费者。此后 `scripts/verify-md-links.ts` 的任何重构都会让该包装脚本在导入期失败，因此每次改动该模块的同步都需要重新检查包装脚本的调用点。

fork 保留两个 workflow：自己的 `package-deb.yml` 与 `package-deb-test.yml`。上游的 `build-exe-for-ssh-helper.yml` 与 `publish-ssh-helper.yml` 在裁剪清单中声明，因为它们产出的独立 SSH helper 可执行文件是与桌面包无关的可选远程执行产物。全部 23 个上游独有 CI workflow 也已在裁剪清单中声明。
