# Agent Note: 0.2.1-alpha.4 merge — the plugin market arrives and Linux containment hardens

Status: implemented

English | [中文](2026-10-16-merge-0.2.1-alpha.4-linux-desktop.zh.md)

## Problem

Upstream `master` advanced 73 commits past the previous sync point and released engine `0.2.1-alpha.4` (tag `dsh-v0.2.1-alpha.4`); the delta changes 802 files. It spans five areas: the plugin market (new `packages/boot/plugin-market`, `packages/util/plugin-market-index`, `packages/client/ui-plugin-market`, and `packages/experimental/plugin-market-bundle`, plus the private `apps/plugin-market-generator` reference generator, the Discover install flow, and a "Custom plugin markets" bundle), the client release-change refresh prompt (`packages/client/modules` compares the host release before applying another host's graph), composer command chips (`ui-conversation`, `ui-commands`, and `ui-input-trigger` claim slash commands as atomic chips), models reasoning-level editing for custom API models, and Linux process containment (`packages/subprocess/subprocess-local` probes the user systemd manager, supports systemd before v254 for native scopes, and moves the containment decision into a testable selector).

The merge produced 24 conflicts. Twenty-three are modify/delete pairs on trimmed Desktop paths: the publication route and release store, the directory installer scripts, and their tests, all of which the fork removed in the previous syncs. The one content conflict is `apps/desktop/package.json`.

Two new upstream files arrived without conflict but belong to the trimmed macOS/Windows scope: the Windows NSIS `directory-report.h` header and the `scripts/desktop-package-source.spec.ts` fixture that reads the trimmed `macos-package.yml` and `windows-package.yml`.

## Decision

**All modify/delete conflicts keep the fork's deletion.** The 23 trimmed paths were removed with `git rm` to preserve the fork's Linux-only posture.

**The two new macOS/Windows files are trimmed, growing the list from 348 to 350 paths.** `apps/desktop/installer/directory-report.h` follows the earlier trims of `extract-report.h` and `uninstall-data.h`: it is a Windows-only header for the trimmed directory installer, referenced only by the retained Windows-only `window-frame.cpp`, which the Linux build never compiles. `scripts/desktop-package-source.spec.ts` reads the two trimmed packaging workflows and both fixtures are absent, so the spec cannot run — the same reason `scripts/windows-package-workflow.spec.ts` is trimmed.

**`apps/desktop/package.json` keeps fork metadata and takes upstream's version.** `author` and `homepage` stay on the fork repository. The version moves to `0.2.1-alpha.4` (equal to the engine version). Scripts stay Linux-only, and the fork keeps `tar` while omitting `koffi`.

**The auto-merged forked files keep their fork content.** `apps/desktop-host/package.json` takes only the version bump and stays without `koffi`. `scripts/check-workspace-constraints.ts` takes upstream's new `apps/plugin-market-generator` exception. `THIRD_PARTY_NOTICES.md`, `package.json`, and `pnpm-lock.yaml` merge both sides: upstream's `hosted-git-info`, `minisearch`, `@types/hosted-git-info`, and relocated `tar` entries plus the new `verify-no-top-level-await` script, alongside the fork's `libreoffice-kit@0.1.5` entry and Linux-only dependency set. `scripts/no-unknown-casts.baseline.json` takes upstream's shrunken baseline.

**The Desktop shell keeps its Linux edits untouched.** No upstream commit changes a forked Desktop source file this sync: `main.ts`, `locale.ts`, `update-coordinator.ts`, `desktop-build-paths.mjs`, `electron-builder.config.mjs`, `package-target.ts`, `prepare-runtime.ts`, and the desktop-cli files carry through unchanged, and the two auto-merged upstream tests that contradicted the fork in the previous sync (`update-coordinator.spec.ts`, `package-target.spec.ts`) are untouched here.

**Upstream's Linux containment work is adopted unchanged.** `packages/subprocess/subprocess-local` is upstream Linux work the fork consumes as-is; the fork carries no `packages/` divergence and the new `linux-scope-selector.ts` enters the tree unmodified.

## Alternatives considered

**Keep `apps/desktop/installer/directory-report.h`.** Rejected: the fork already trims every other newly added Windows installer source (`extract-report.h`, `uninstall-data.h`, `uninstall.nsh`), and the header only serves the trimmed directory installer. The retained `window-frame.cpp` still includes it, matching its existing dangling include of the also-trimmed `extract-report.h`; it never compiles on Linux.

**Keep `scripts/desktop-package-source.spec.ts`.** Rejected: the fork keeps two other specs whose workflow is trimmed (`macos-package-workflow.spec.ts`, `desktop-publish-workflow.spec.ts`), but this new spec is the direct analogue of the already-trimmed `scripts/windows-package-workflow.spec.ts`, and every fixture it reads is absent.

**Revert upstream's Linux containment changes to the fork's earlier behavior.** Rejected: the fork is the Linux consumer this work targets, and the selector is upstream-planned engine work, not a macOS/Windows-only path.

## Consequences

The next sync starts from upstream tag `dsh-v0.2.1-alpha.4`. The trim list holds 350 paths.

The fork still carries a half-trimmed Windows installer source tree: `window-frame.cpp` and the `installer/*.nsh` files stay while the headers they include are trimmed. They are inert on Linux, and trimming the group wholesale remains a possible future simplification.

`pnpm run test:docs` fails only `verify-repository-references`, which flags commit-hash text in the previous merge's Agent Note and in `python/sdk/uv.lock`. Neither file is changed by this merge, so the failure predates it.
