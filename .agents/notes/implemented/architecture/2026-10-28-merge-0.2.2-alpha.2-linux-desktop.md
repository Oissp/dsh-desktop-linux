# Agent Note: 0.2.2-alpha.2 merge — the fork keeps its shell while adopting upstream's diagnostics work

Status: implemented

English | [中文](2026-10-28-merge-0.2.2-alpha.2-linux-desktop.zh.md)

## Problem

Upstream `master` advanced 637 commits past the previous sync point (the 0.2.1-rc.3 merge) and released engine `0.2.2-alpha.2`; tag `dsh-v0.2.2-alpha.2` names the merged tip. The delta changes 2118 files and adds 711, among them seven new packages — `experimental/client-ui-forge`, `experimental/client-ui-stats`, `experimental/forge`, `experimental/forge-bundle`, `experimental/forge-github`, `experimental/forge-session`, and `experimental/liveshare` — plus 39 snapshot files and the operation-report and diagnostics surfaces the Desktop shell now drives (`operation-report.ts`, `operation-report-job.ts`, `operation-report-worker.ts`, `locale-cache.ts`, and the `apps/desktop-host` diagnostics modules).

Merging produced eight content conflicts and forty-two modify/delete conflicts. Every modify/delete conflict is a trimmed path, so the trim list resolved them without a decision. The eight content conflicts were `apps/desktop/package.json`, `apps/desktop/scripts/desktop-build-paths.mjs`, `apps/desktop/src/main.ts`, `apps/desktop/tsdown.config.ts`, `docs/development.i18n.yaml`, `package.json`, `packages/ptc-runtime/ptc-runtime-node/tsdown.config.ts`, and `pnpm-lock.yaml`.

The fork carries no `packages/` divergence, so upstream's engine work enters unchanged; the conflicts land on the shell, its build configuration, and the manifests.

## Decision

**Nine more upstream files are trimmed, and the trim list grows from 407 to 416 paths.** The three `pr-check-*.yml` workflows run upstream's merge-policy checks on `master` through the upstream organization's `deepseek-harness-check` action and repository variables; the fork's default branch is `main` and it carries neither, so they can never run. `macos-intel-package.yml` joins the already-trimmed macOS packaging workflow. `scripts/desktop-package-forms.spec.ts` reads those three trimmed packaging workflows. `desktop-edgeone.ts` is the Tencent EdgeOne publishing and purge pipeline and `desktop-publish-targets.ts` is upstream's multi-platform release routing table whose only callers are trimmed publish scripts; both are orphaned here, and their specs plus `purge-command.spec.ts` — which asserts the trimmed `purge:latest` script chain — are trimmed with them. The `tencentcloud-sdk-nodejs-teo` devDependency exists only for `desktop-edgeone.ts` and is dropped with it.

**`main.ts` takes upstream's locale cache initialization and keeps the fork's Linux shell state.** Upstream now seeds `windowsLanguage` from `readDesktopLocaleCache` and resolves the startup locale through it. The conflict resolution keeps that initializer, then continues with the fork's module-level tray reference, appearance helpers, and `rebuildTrayMenu`, and resolves `locale` with upstream's `windowsLanguage` branch followed by the fork's tray rebuild slot. Nothing in the fork's tray, appearance, or menu-bar behavior changes.

**The Desktop bundle keeps the fork's command-manager entry and adopts upstream's new operation-report worker entry.** Upstream added a second `command-manager-entry` bundle block whose output file is the same one the fork's own block already emits; keeping both would build `lib/command-manager-entry.js` twice. The fork's block remains, and upstream's `operation-report-worker` entry is added because the shell now starts that Worker and the packaged file list already ships `lib/*.js`.

**The PTC Node runtime keeps the fork's bundling spelling and takes upstream's new entries.** `deps: { alwaysBundle }` stays — it is the current spelling of the deprecated `noExternal` recorded in [`2026-09-25-fork-build-config-edits`](../process/2026-09-25-fork-build-config-edits.md) — and the resolution adds upstream's `configuration.js` entry plus `acorn` and `acorn-walk` to both process bundles.

**The manifests keep the fork's packaging surface.** `package.json` and `apps/desktop/package.json` resolve to the fork's Linux-only scripts, author, and homepage; the DELETED macOS/Windows package and upload scripts stay out, and `desktop-build-paths.mjs` keeps `desktopTargetPlatform` returning Linux x64. The desktop version moves to `0.2.2-alpha.2`, equal to the engine version, because this sync changes no shell behavior.

**`apps/desktop` drops its package-local React type dependencies.** `main` declared `@types/react` and `@types/react-dom` although the root manifest provides both; upstream removed its local copies and `verify-package-dependencies` enforces the root-only rule. The merged manifest keeps them out, which leaves TypeScript JSX checking to the hoisted root types.

**The lockfile is resolved as the union of the surviving importer entries and then regenerated.** The fork's `tar` and upstream's `tencentcloud-sdk-nodejs-teo` both survive the merge, and the remaining hunks take upstream's `form-data@2.5.6` and `form-data@3.0.5` records; `pnpm install --no-frozen-lockfile` then produced the final file, which only removes entries.

**The diagnostics documentation links one target in both languages.** `apps/desktop/docs/diagnostics/README.zh.md` pointed at `../../tests/README.zh.md`, but the fork trims the `apps/desktop/tests/README` pair, so the pairing check can no longer collapse the two locales into one semantic target. The Chinese page now links `../../tests/README.md`, the same target as its English counterpart; the link resolves to a trimmed path in both languages, which `verify-md-links-trimmed` exempts.

## Alternatives considered

**Keep upstream's `command-manager-entry` tsdown block next to the fork's.** Rejected: both entries emit `lib/command-manager-entry.js`, so the second one either overwrites the first or depends on build order.

**Keep the three `pr-check-*.yml` workflows because they are inert in the fork.** Rejected: they target `master` and call an action from the upstream organization, and the trim list exists to keep the tree to what the fork runs. Their presence would also make `scripts/ci-workflow.spec.ts` read workflow files the fork does not use, which misstates the fork's CI.

**Restore the `apps/desktop/tests/README` pair so the diagnostics links resolve.** Rejected: that README documents the installed-update, macOS, and Windows packaging pipelines the fork trims; restoring it would bring back descriptions of scripts the tree does not carry.

**Rewrite both diagnostics pages to drop the dead link.** Rejected: the trimmed target is exempt, so one link-target change keeps both languages on upstream's text and leaves the English page byte-identical to upstream.

**Regenerate the whole lockfile from the manifests instead of merging it.** Rejected: a fresh resolution would move unrelated transitive versions and hide the merge's actual effect, which here is the removal of one dependency's subtree.

## Consequences

The next sync starts from upstream `master` at tag `dsh-v0.2.2-alpha.2`. The trim list records 416 paths and `.github/sync-forked-paths.txt` now records 28 fork-modified paths, the diagnostics link being the only addition.

`scripts/ci-workflow.spec.ts` keeps reading trimmed workflows — it already reads the trimmed `ci.yml` — so it stays a repository-wide test failure the fork's CI does not run; `package-deb-test.yml` collects only `apps/desktop/tests`.

The diagnostics documentation ships with the shell it documents. `apps/desktop/README.md` follows upstream, whose link into the trimmed `apps/desktop/packaging/` guide is already handled by the trim-list link exemption.

## Testing

`scripts/verify-sync-trimmed-paths.sh` and its `--staged` form confirm all 416 trimmed paths are absent from the worktree and the index. The dropped-edit check this fork's earlier note prescribes — every path both sides changed, compared against upstream's blob — reports no file that matches upstream while `main` had diverged, and all 213 paths the fork changed since the sync point still exist.

`pnpm run typecheck` reports five gates passed, `pnpm run build:artifacts` eight, and `pnpm run build:check` two; the artifact build must run under a Node installation that ships development headers, because the native addon compiles against `include/node`. `pnpm run lint` reports zero errors and one warning in upstream's `packages/experimental/client-ui-cot-translation` (an unused `oxlint-disable` directive). `pnpm run test:docs` passes all 21 gates, including translation pairing over 1156 pairs. `pnpm exec vitest run apps/desktop/tests` passes 86 files and 1039 tests, with five skipped. `verify-package-dependencies` reports 93 packages matching the published policy once the local React type dependencies are gone.

`pnpm run hygiene` passes 22 of its 23 gates here. `verify-optional-dependency-imports` exhausts the default V8 heap on this 7 GiB machine and passes with `--max-old-space-size=6144`. `rescope-vendor:check` fails on `ENOBUFS` because it reads `git ls-files -z` through `execFileSync` without raising the 1 MiB default buffer, and this checkout's path names already exceed it on `main` (1.1 MB before the merge, 1.16 MB after).
