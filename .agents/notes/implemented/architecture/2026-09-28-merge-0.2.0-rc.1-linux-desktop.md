# Agent Note: 0.2.0-rc.1 merge — the Linux desktop surfaces

Status: implemented

English | [中文](2026-09-28-merge-0.2.0-rc.1-linux-desktop.zh.md)

## Problem

Upstream 0.2.0-rc.1 is the first 0.2 release candidate: 106 commits over 672 files. Most of it is product work the fork takes unchanged. The Session Log upload preference ships as the new `packages/client/ui-settings-session-log` package and registers into the fork's own `cordis.patch.yml` composition; the persistence schema type inventory is compacted, shrinking `docs/persistence-schema.json` from 97057 to 25277 lines; inherited settings compositions skip unoverridden entries and unused shared compositions; and the Desktop preload begins forwarding the device description the feedback survey prefills.

Five conflicts needed a decision rather than a side already chosen. `apps/desktop/package.json` gained a `koffi` devDependency that upstream pins to 3.1.1, and the only consumers of that dependency are the Windows signature scripts the fork trims. `apps/desktop/electron-builder.config.d.mts` gained `entitlements` and `entitlementsInherit` in a `mac` block the fork's Linux-only interface does not carry. `apps/desktop/scripts/macos-entitlements.plist` arrived as a new file whose only referent is the already-trimmed `apps/desktop/scripts/electron-builder-config.mjs`. Both sides edited the `installation-ownership` section of the `apps/desktop/README.md` pair, so its recorded hashes matched neither side. Three trim-list paths arrived as modify/delete conflicts.

## Decision

**`koffi` stays out of `apps/desktop`.** The fork dropped this devDependency when it trimmed the Windows signing scripts, and upstream's pin commit is what reintroduced the conflict, not a new consumer. `apps/desktop/tests/fixtures/runtime-payload-smoke.mjs` still names koffi, but it runs inside a packaged runtime payload where the module comes from the bundled profile rather than this manifest. The matching `pnpm-lock.yaml` importer entry is dropped with it, and the workspace-wide 3.1.1 pins in `packages/host/directory-picker-native` and `packages/subprocess/*` stay.

**The Linux-only builder interface keeps no mac block.** `macos-entitlements.plist` joins [sync-trimmed-paths.txt](../../../../.github/sync-trimmed-paths.txt) and is deleted, because the file the fork would have shipped it through does not exist here.

**The trim-list modify/delete conflicts resolve to the fork's deletion**: `.github/workflows/sandbox.yml`, `apps/desktop/scripts/electron-builder-config.mjs`, and `apps/desktop/tests/macos-signature.spec.ts`.

**The README pairing is re-recorded** for the merged `installation-ownership` section rather than aligned to either side, because the merged section carries the fork's prompt-window and shell-appearance paragraphs beside upstream's new device-description and fullscreen paragraphs.

**The Office kit version assertion derives from the resolved manifest.** `packages/skill/skill-office/tests/skill-office.spec.ts` hardcoded the kit version upstream last wrote, and had failed since the fork pinned the kit to 0.1.2; it now resolves `@deepseek-ai/libreoffice-kit/package.json` the way the skill does and asserts the version that copy reports. The [Office preview patch](../bug-fix/2026-09-18-desktop-office-preview-asar-engine-probe.md) is unaffected and still applied.

## Alternatives considered

**Re-add `koffi` to `apps/desktop` to keep the manifest tracking upstream.** Rejected: it would install a Windows FFI package into a Linux-only shell that no longer has a script importing it, and the next release would re-litigate the same conflict.

**Keep `macos-entitlements.plist` as harmless data.** Rejected: nothing in the fork reads it, and a file the fork does not ship that upstream keeps editing produces the same conflict every release.

**Adopt upstream's `mac` fields in `electron-builder.config.d.mts`.** Rejected: the interface mirrors the fork's `electron-builder.config.mjs`, which builds Linux targets only; declaring fields the factory never emits would misdescribe it.

## Consequences

Future syncs resolve the `koffi`, plist, and `.d.mts` conflicts by keeping the fork's side; all three are now recorded in the trim list or in this note. The desktop version moves to `0.2.0-rc.1.1`, so the fork's build suffix tracks the engine base as it did through the 0.1.x line.

## Testing

`pnpm run typecheck` compiles the merged tree and `pnpm run lint` is clean. `pnpm run test:docs` reports 20 passed and 0 failed, including `markdown links`, which reads the extended trim list, and `translation pairing`, which validates the re-recorded README pair. `pnpm exec vitest run apps/desktop/tests` passes 746 tests across 67 files, and `apps/desktop-host` plus the new `ui-settings-session-log` suite pass 27 tests across 6 files. `pnpm run test` reports 11 failing files, none of them caused by the merge: six CI workflow specs read `.github/workflows/ci.yml` and its siblings, which the fork does not carry; `executor`, `spawn-runner`, and `helper-processes` fail the same way on this host before the merge; and `watch-config` and `checkers` pass when run alone. `pnpm run hygiene` reports the same two pre-existing failures on both sides of the merge: `constraints` requires `@deepseek-ai/dsh-desktop` to equal the root version, which the fork's build suffix never does, and `publint` reports the `./src/*` export of 300 package publication views that declare no `src` in `files`.
