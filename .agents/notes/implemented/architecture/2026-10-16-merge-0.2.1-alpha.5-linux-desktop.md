# Agent Note: 0.2.1-alpha.5 merge — account notices, slash-menu refresh, and publication hardening trimmed

Status: implemented

English | [中文](2026-10-16-merge-0.2.1-alpha.5-linux-desktop.zh.md)

## Problem

Upstream `master` advanced 36 commits past the previous sync point and released engine `0.2.1-alpha.5` (tag `dsh-v0.2.1-alpha.5`, which is this merge's target); the delta changes 586 files. It spans four areas: account notices (new `packages/client/ui-settings-account/src/client/notice-transition.ts` for stacking notices of differing heights, a generic notification-metadata field on the account platform, and the `docs/upgrade-guide/v0.2.1-alpha.4/account-notification-fields` guide), the client slash menu and model labels (`packages/client/ui-skill` refreshes the `/` menu after a plugin-manager change, `ui-model-selection` gains a provider-aware model-label slot and viewport-contained menus), terminal and web fixes (`packages/api/terminal-controller` adds a shared per-session terminal inventory, `packages/client/ui-layout` clips the collapsed right sidebar, `apps/web` pins the fixture clock for page-timer regressions), and Desktop publication hardening (rejection of debugging packages before dependency setup, signed-by-default Windows packaging, publication to administratively unversioned COS buckets, and a Task Scheduler supervisor for the Windows packaging runner).

The merge produced 25 conflicts. Twenty-four are modify/delete pairs on trimmed Desktop paths: the four upstream-only CI workflows, the publication and Windows-signing documentation, the COS publication pipeline scripts and their tests, and the already-trimmed `scripts/windows-package-workflow.spec.ts`. The one content conflict is `apps/desktop/package.json`.

Thirteen further upstream files arrived without conflict but inside the trimmed publication and Windows-packaging scope.

## Decision

**All 24 modify/delete conflicts keep the fork's deletion.** The paths were removed with `git rm`, preserving the fork's Linux-only posture.

**The thirteen newly arrived trimmed-scope files are trimmed, growing the list from 350 to 362 paths.** The publication preflight (`preflight-desktop-publish.mjs`/`.d.mts`), the publication-qualification module (`desktop-publish-qualification.mjs`/`.d.mts`), and `apps/desktop/tests/desktop-publish-preflight.spec.ts` belong to the already-trimmed COS publication pipeline: the preflight script is called only by `.github/workflows/desktop-publish.yml`, the qualification module is imported only by the trimmed `desktop-publish-route.ts` and `publish-desktop-ci.ts`, and the spec asserts that workflow's preflight step. The four snapshot fixtures (`expected/cos-GetObject-denied.json`, `expected/cos-PutObject-denied.json`, `expected/retained-unnotarized.md`, `expected/retained-unsigned.md`) are written by `toMatchFileSnapshot` in the trimmed `desktop-publish-cos.spec.ts` and `retain-desktop-ci.spec.ts`. The Windows runner supervisor (`apps/desktop/scripts/windows-runner-task.ps1`, `run-windows-runner-task.ps1`, and its `apps/desktop/tests/windows-runner-task.ps1` acceptance script) is referenced only by the trimmed `.github/workflows/ci.yml` and the trimmed Windows-signing README.

**`scripts/desktop-publish-workflow.spec.ts` is kept with upstream's content.** The previous sync recorded the fork's decision to keep the two specs whose workflow is trimmed (`macos-package-workflow.spec.ts`, `desktop-publish-workflow.spec.ts`) while trimming newly added specs in the same situation. Upstream's 9-line addition pins the new publication preflight step and its checked attempt; the spec cannot load without the trimmed workflow either way, so this sync follows the recorded policy instead of revising it mid-merge.

**`apps/desktop/package.json` keeps fork metadata and takes upstream's version.** `author` and `homepage` stay on the fork repository, and the version moves to `0.2.1-alpha.5` (equal to the engine version). Upstream's only other change to this file in the delta is the version bump, so the fork's Linux-only scripts, its omitted `koffi`, and its retained `tar` are untouched.

**`apps/desktop-host/package.json` takes only the version bump** and stays without `koffi`.

**No upstream commit in this delta changes a forked Desktop source file.** `main.ts`, `locale.ts`, `update-coordinator.ts`, `desktop-build-paths.mjs`, `electron-builder.config.mjs`, `package-target.ts`, `prepare-runtime.ts`, `prepare-cli.ts`, `command-management.ts`, and the `tsdown` configs carry through unchanged; the only forked-path file upstream touched is `apps/desktop/package.json`, and its sole upstream change is the version.

**Upstream's engine work is adopted unchanged.** The fork carries no `packages/` divergence, so the account-notice, slash-menu, model-label, terminal-inventory, and publication-hardening engine changes enter the tree as upstream authored them.

## Alternatives considered

**Trim `scripts/desktop-publish-workflow.spec.ts`.** Rejected: the alpha.4 merge note records that the fork deliberately keeps this spec and its `macos-package-workflow.spec.ts` sibling despite their trimmed workflows, and trims only newly added specs of that kind. Trimming it here would reverse a recorded decision inside a mechanical sync and would also discard upstream's new preflight assertions, which become relevant again if the fork ever adopts the publication pipeline.

**Keep the new Windows runner supervisor scripts.** Rejected: they register and supervise a packaging runner through Windows Task Scheduler, referenced only by the upstream-only `ci.yml` and the already-trimmed `apps/desktop/windows-signing/README.md`. The fork builds deb and AppImage on Linux runners and never ran them.

**Keep the four `cos-*` and `retained-*` snapshot fixtures.** Rejected: their only consumers are the trimmed `desktop-publish-cos.spec.ts` and `retain-desktop-ci.spec.ts`, mirroring the already-trimmed `expected/publication-*.md` fixtures from the alpha.3 sync.

**Keep `preflight-desktop-publish.mjs` and adopt the debug-publication rejection.** Rejected: the fork does not run the COS publication pipeline at all, and the script reads GitHub Actions run metadata for an attempt that `package-deb.yml` never produces.

## Consequences

The next sync starts from upstream tag `dsh-v0.2.1-alpha.5`. The trim list holds 362 paths.

The fork's trim policy now distinguishes two kinds of publication-scope file: newly added ones are trimmed with the pipeline they serve, while the two long-standing workflow specs stay for the reason recorded in the alpha.4 note. A future sync that changes either spec should keep upstream's content and leave the trim decision alone.

The Windows installer source tree stays half-trimmed as recorded in the alpha.4 note: `window-frame.cpp` and the `installer/*.nsh` files remain while the headers they include are trimmed. This delta adds no new file to that group.
