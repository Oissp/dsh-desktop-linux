# Agent Note: 0.2.1-alpha.1 合并——npm 发版频道到来，fork 保持 Linux 打包

Status: implemented

[English](2026-10-03-merge-0.2.1-alpha.1-linux-desktop.md) | 中文

## Problem

上游 `master` 在上一次同步之后前进 8 个提交，发布引擎 `0.2.1-alpha.1`——这是上游首次在隔离 npm 频道机制上发版。vendored cordis 组随之移动：`cordis` 到 `4.0.5-alpha.1`，八个同族 vendored 包到各自的 `-alpha.1`。每个 vendored `package.json` 中只有 Harness 发版版本字段变化，没有任何 vendored 源码主体改动。根 `package.json` 新增 `semver` 与 `@types/semver` devDependency，供 `scripts/release/publish.ts` 校验并保全已被占用的 dist-tag。其余增量是发版工具链及其 spec。

两条路径冲突。裁剪清单内的 `.github/workflows/release-vendor-publish.yml` 以修改/删除对到达；`apps/desktop/package.json` 则把上游的版本提升与 fork 的 author、homepage 和带构建后缀的版本撞在一起。

## Decision

**`release-vendor-publish.yml` 保留 fork 的删除。** fork 只运行 `package-deb.yml` 与 `package-deb-test.yml`，无法承载上游的 npm 发布 workflow。

**`apps/desktop/package.json` 保留 fork 元数据、采用上游版本。** `author` 与 `homepage` 继续指向 fork 仓库，因为它们会进入 deb 元数据。version 字段的取舍见下条。

**桌面版本等于引擎版本。** 本次同步没有改动任何壳源码，因此 `apps/desktop/package.json` 直接移到 `0.2.1-alpha.1`，不带 `.N` 构建后缀。后缀轨只为引擎发版之间发布的壳修复而存在，本次合并没有符合条件的内容。

**频道能力对本 fork 是惰性的。** `scripts/release/publish.ts` 与其新增的 31 条 spec 原样进入并通过，但 fork 没有任何路径调用它们：`package-deb.yml` 以 `--publish never` 打包，发布走 `gh release create` 针对 `Oissp/dsh-desktop-linux-release`。`semver` devDependency 同样不是新能力——`apps/desktop` 早已为 `release-version.ts`、`runtime-tree.ts` 与 `update-coordinator.ts` 依赖它，根上的条目是为被裁剪的 DSH 发版脚本服务。

## Alternatives considered

**给桌面版本加 `.1` 后缀。** 拒绝：本次没有壳改动发布，纯引擎同步正是发版版本门禁接受裸引擎版本的情形。

**携带上游的 `release-vendor-publish.yml`。** 拒绝：fork 没有 vendor 发布步骤，保留该文件会让裁剪清单门禁在之后每次同步时重新触发。

**删掉被裁剪的 `scripts/ci-workflow.spec.ts`。** 拒绝：该 spec 也覆盖与 fork 相关的 workflow 内容，且运行手册已把它读取 workflow 的测试记录为 fork 的已知失败。

## Consequences

下一次同步从 `0.2.1-alpha.1` 发版（上游 PR #5648）开始。由于引擎从 `0.2.0-rc.2` 移到 `0.2.1-alpha.1`，壳放弃 `0.2.0-rc.2.N` 这条线；不存在已发布的 `0.2.0` 桌面版，也没有相关计划。

`scripts/ci-workflow.spec.ts` 在本 fork 上按构造必然失败：它的 workflow 测试读取被裁剪清单删除的 `.github/workflows/*.yml`，而上游又为 `release-vendor-publish.yml` 增加了一条同类测试。fork CI 不运行该 spec。

## Testing

`pnpm run typecheck` 与 `pnpm run lint` 退出码 0。`pnpm run test:docs` 报告 21 项门禁通过、0 失败——上一次合并记录的两处文档门禁失败现已修复。`pnpm exec vitest run apps/desktop/tests apps/desktop-host/tests` 在 75 个文件中报告 807 passed、3 skipped，唯一失败是既有、只在 macOS 上出现的 `command-installation.spec.ts` 套件加载失败；Linux CI 会运行该套件并通过。`pnpm exec vitest run scripts/release/publish.spec.ts` 31 条测试全部通过。

裁剪清单的验证方式是把每一条对照暂存区读取：267 条路径全部不存在，且 `scripts/verify-sync-pairing-after-merge.sh` 报告配对记录已一致。
