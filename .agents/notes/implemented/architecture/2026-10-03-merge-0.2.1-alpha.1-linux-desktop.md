# Agent Note: 0.2.1-alpha.1 merge — npm release channels arrive, the fork keeps Linux packaging

Status: implemented

English | [中文](2026-10-03-merge-0.2.1-alpha.1-linux-desktop.zh.md)

## Problem

Upstream `master` advanced eight commits past the previous sync and released engine `0.2.1-alpha.1`, its first release on isolated npm channels. The vendored cordis set moves with it: `cordis` to `4.0.5-alpha.1` and the seven sibling plugins to their `-alpha.1` counterparts. Only the Harness release-version field in each vendored `package.json` changes; no vendored source body does. Root `package.json` gains `semver` and `@types/semver` as devDependencies, which `scripts/release/publish.ts` now imports to validate and preserve occupied dist-tags. The rest of the delta is release tooling and its specs.

Two paths conflicted. The trim list's `.github/workflows/release-vendor-publish.yml` arrived as a modify/delete pair, and `apps/desktop/package.json` carried upstream's version bump against the fork's author, homepage and build-suffixed version.

## Decision

**`release-vendor-publish.yml` keeps the fork's deletion.** The fork runs only `package-deb.yml` and `package-deb-test.yml`, and cannot carry upstream's npm publication workflows.

**`apps/desktop/package.json` keeps the fork's metadata and takes upstream's version.** `author` and `homepage` stay pointed at the fork repository, since they feed the deb metadata. The version field is the merge-time decision below.

**The desktop version equals the engine version.** This sync changes no shell source, so `apps/desktop/package.json` moves to `0.2.1-alpha.1` rather than taking a `.N` build suffix. The suffix track exists for shell fixes that ship between engine releases; nothing in this merge qualifies.

**The channel work is inert for the fork.** `scripts/release/publish.ts` and its new 31-test spec arrive intact and pass, but no fork path calls them: `package-deb.yml` packages with `--publish never`, and publishing runs as `gh release create` against `Oissp/dsh-desktop-linux-release`. The `semver` devDependency is likewise not a new capability — `apps/desktop` already depended on it for `release-version.ts`, `runtime-tree.ts` and `update-coordinator.ts`; the root entry exists to serve the trimmed DSH release scripts.

## Alternatives considered

**Give the desktop the `.1` suffix.** Rejected: no shell change ships here, and a bare engine version is what the release-version gate accepts for a pure engine sync.

**Carry upstream's `release-vendor-publish.yml`.** Rejected: the fork has no vendor publication step, and keeping the file would re-arm the trim-list gate on every later sync.

**Drop the trimmed `scripts/ci-workflow.spec.ts`.** Rejected: the spec also covers fork-relevant workflow content, and the runbook already documents its workflow-reading tests as a known fork failure.

## Consequences

The next sync starts from the `0.2.1-alpha.1` release (upstream PR #5648). Because the engine moved from `0.2.0-rc.2` to `0.2.1-alpha.1`, the shell abandons the `0.2.0-rc.2.N` line; there is no published `0.2.0` desktop and none is planned.

`scripts/ci-workflow.spec.ts` fails on this fork by construction: its workflow tests read `.github/workflows/*.yml` files the trim list deletes, and upstream added one more such test for `release-vendor-publish.yml`. Fork CI does not run the spec.

## Testing

`pnpm run typecheck` and `pnpm run lint` exit 0. `pnpm run test:docs` reports 21 gates passed, 0 failed — the two documentation-gate failures recorded at the previous merge are now fixed. `pnpm exec vitest run apps/desktop/tests apps/desktop-host/tests` reports 807 passed and 3 skipped across 75 files, with the pre-existing macOS-only `command-installation.spec.ts` suite-load failure as the sole failure; Linux CI runs that suite and passes it. `pnpm exec vitest run scripts/release/publish.spec.ts` passes all 31 tests.

The trim list is verified by reading every entry against the staged tree: all 267 paths are absent, and `scripts/verify-sync-pairing-after-merge.sh` reports the pairing records already consistent.
