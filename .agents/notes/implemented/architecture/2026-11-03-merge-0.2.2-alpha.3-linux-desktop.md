# Agent Note: 0.2.2-alpha.3 upstream sync — the fork takes upstream's update configuration surfaces and keeps its single-feed updater

Status: implemented

English | [中文](2026-11-03-merge-0.2.2-alpha.3-linux-desktop.zh.md)

## Problem

Upstream `master` advanced 666 commits past the previous sync point, 351 commits after tag `dsh-v0.2.2-alpha.2`, and cut `0.2.2-alpha.3`. The delta changes 2654 files — 399 added, 111 deleted, 2108 modified, 36 renamed — moves the agent-team packages from `packages/experimental` into `packages/team` and `packages/client/ui-agent-team`, retires `agent-team-profile`, removes `web-search-exa` and `web-search-perplexity`, adds `packages/mcp/mcp-manager`, and rebuilds the desktop update surfaces around the settings file: channel selection from Settings, a reload path after a configuration failure, per-cause download diagnostics, and a rewritten coordinator.

Merging produced 53 conflicts: 45 modify/delete conflicts on trimmed paths and 8 content conflicts (`apps/desktop/package.json`, `apps/desktop/src/main.ts`, `apps/desktop/src/locale.ts`, `apps/desktop/src/update-coordinator.ts`, `apps/desktop/tests/update-coordinator.spec.ts`, `docs/development.i18n.yaml`, and the CUA native README pair). The fork carries no `packages/` divergence, so the upstream engine work enters unchanged; the decisions land on the desktop shell's update policy, its language dictionaries, and the sync lists.

## Decision

**The merge takes upstream's update-configuration surfaces while keeping the fork's single-feed updater policy and Linux shell.**

`apps/desktop/src/update-coordinator.ts` takes upstream's rewritten coordinator — channel state with configuration errors, the release state machine that separates a checked release from a downloaded or handed-off one — but calls the fork's `selectFeedChannel` instead of upstream's `selectUpdateChannel`. One `latest-linux.yml` serves every release in this fork, so the selected channel only decides whether prereleases are accepted; pinning `updater.channel` to `'nightly'` or `'stable'` would stop the GitHub provider from resolving the fork's `v<desktop version>` release tags and fail with `ERR_UPDATER_NO_PUBLISHED_VERSIONS`. `update-coordinator.spec.ts` pins `updater.channel === undefined` and the prerelease-only effect of the nightly channel.

`apps/desktop/src/main.ts` takes upstream's asynchronous `readDesktopSettings`, the update-configuration messages, and the `removeLegacyHostCookies` wiring, and keeps the fork's packaged-Linux `Menu.setApplicationMenu(null)`, the tray menu that mirrors Show Window, Check for Updates, Manage dsh Command, and Quit, the appearance-following window and tray icons, and the desktop-cli entry in the tray only.

`apps/desktop/src/locale.ts` takes upstream's new update-configuration and download-failure strings in every locale and keeps the fork's tray strings.

`apps/desktop/package.json` keeps the fork's product name, author, homepage, and Linux-only packaging scripts, and drops upstream's macOS and Windows scripts with their signing dependencies; relative to the previous fork version only the version line changes, to upstream's `0.2.2-alpha.3`.

`apps/desktop/README.zh.md` keeps the fork's links to `LINUX_PACKAGING.md` and drops the links into trimmed packaging, publishing, and Windows-signing guides; its Electron updater compatibility link now names the English `tests/updates/electron-updater/README.md` target, matching the English page, because this sync trims that whole directory. The CUA native README keeps the one-target decision recorded by the [previous sync](2026-10-30-merge-0.2.2-alpha.2-linux-desktop.md).

**Three more upstream paths are trimmed, and the trim list grows from 425 to 428.** `apps/desktop/scripts/test-update-channels.mjs` runs only on Windows and macOS and reads the platform version records next; `apps/desktop/tests/updates/electron-updater/` carries those records and their bilingual README for the same qualification flow; `scripts/cua-helper/package.spec.ts` imports the already-trimmed `scripts/cua-helper/package.ts`, so it fails at import. The fork publishes Linux only and runs none of those flows.

**The desktop version equals the engine version, `0.2.2-alpha.3`, and publishing needs no build-counter bump.** The fork's release repository has no `v0.2.2-alpha.3` release yet, so the packaging workflow publishes this version when the merge lands on `main`; a `.N` counter remains for a later build on the same engine version. Equal versions also keep `check-workspace-constraints` green, since `@deepseek-ai/dsh-desktop` must match the root version.

## Alternatives considered

**Keep upstream's `selectUpdateChannel`.** Rejected: the fork publishes one `latest-linux.yml` feed and tags releases with the desktop version; pinning a channel breaks the GitHub provider's tag resolution instead of selecting a different feed.

**Carry the electron-updater platform records to keep the README link inside the tree.** Rejected: that directory documents the Windows and macOS channel qualification flow, whose script the fork does not run, and the trim-list link exemption already covers the link in both languages.

**Restore `scripts/cua-helper/package.ts` and its macOS signing dependencies so the spec can run.** Rejected: the fork carries no macOS packaging pipeline; restoring the pipeline only to keep an orphaned spec compiling brings back the trimmed files, as recorded by the [previous sync](2026-10-30-merge-0.2.2-alpha.2-linux-desktop.md).

**Bump the desktop version in the merge commit.** Rejected: sync merges and build-counter bumps stay separate, and keeping the desktop version equal to the engine keeps `check-workspace-constraints` green.

**Regenerate the lockfile instead of accepting the merged one.** Rejected: `pnpm install --frozen-lockfile` accepts the merged lockfile, so a fresh resolution would only move unrelated transitive versions.

## Consequences

The next sync starts from upstream `master` beyond tag `dsh-v0.2.2-alpha.3`. The merge's push to `main` triggers the packaging workflow, which publishes `v0.2.2-alpha.3` to the fork's release repository without a version bump; an explicit `chore(desktop): 版本提升到 0.2.2-alpha.3.N` bump stays available for a later build on the same engine version.

The trim list records 428 paths; `.github/sync-forked-paths.txt` keeps its 34 entries. Upstream retired `agent-team-profile` and moved the agent-team packages into `packages/team` and `packages/client/ui-agent-team`; `@deepseek-ai/dsh-experimental-agent-team-profile` joins `RETIRED_BUNDLES`.

Two verification failures are inherited rather than introduced. `scripts/rescope-vendor.ts --check` still expects the pre-stable-ID `17. **@deepseek-ai rescope**` postcondition text that upstream's `vendor/README.md` rewrite replaced, and reports pre-rescope name tokens in upstream docs; the same check fails on the fork's `main`. Repository-wide unit runs still read trimmed workflows, and `scripts/ci-workflow.spec.ts` now also reads the trimmed `apps/desktop/tests/updates/electron-updater/check-versions.mjs`.
