# Agent Note: 0.2.2-rc.3 上游同步 —— fork 裁剪发布工具 workspace 并跟随上游的桌面端认证

Status: implemented

[English](2026-11-13-merge-0.2.2-rc.3-linux-desktop.md) | 中文

## Problem

上游 `master` 相对 `dsh-v0.2.2-rc.2` 分叉的父提交推进了 448 个提交，并发布了 `0.2.2-rc.3`。增量改动 3262 个文件——新增 517、删除 45、修改 2652、重命名 48——共 93416 行新增、34804 行删除。它把桌面端发布工具拆成新的 `apps/desktop-publisher` workspace；给桌面端自己的 Host 认证（`apps/desktop-host/src/authentication.ts`、`apps/desktop/src/parent-authentication.ts`）；把 `@deepseek-ai/dsh-error` 变成桌面端生产依赖并由独立命令管理 worker 内联；移除 Python PTC；并引入 CUA MCP、实验性 Timeline 插件、DeepSeek 官网对话导出导入、Forge 变更面板、Host 认证包，以及 `dsh-cua-macos`/`dsh-cua-windows` 改包名。它还把 `.github/workflows/cua-helper-package.yml` 改名为 `cua-helper-package-macos.yml`，并把桌面端 Host 生命周期协议推进到 5。

本次合并产生 115 个冲突：104 个 modify/delete 冲突与 11 个内容冲突（`apps/desktop/README.md`、`README.zh.md`、配对记录、`README.i18n.yaml`、`package.json`、`scripts/desktop-build-paths.d.mts`、`scripts/development-project.ts`、`scripts/package-target.ts`、`src/main.ts`、`tsdown.config.ts`，以及 CUA native README 双语对与其配对记录）。其中 60 个 modify/delete 冲突落在已裁剪路径上，另外 44 个是上游搬进 `apps/desktop-publisher` 的文件。

## Decision

**合并采用上游的桌面端认证与 worker 打包方式，并整目录裁剪发布工具 workspace。**

`apps/desktop-publisher/` 以一条目录条目裁剪，而不是 53 条文件条目。上游让 `apps/desktop` 以 devDependency 引用它，因此保留它会给每个门禁增加一个真实 workspace 成员：`apps/*` 的 tsconfig glob、`check-workspace-constraints` 与锁文件。44 条指向其旧址 `apps/desktop/scripts` 与 `apps/desktop/tests` 的历史条目因上游已无这些文件而退出裁剪清单，由 `apps/desktop-publisher/` 覆盖；`.github/workflows/cua-helper-package-macos.yml` 取代改名后的 workflow 条目。裁剪清单记录 404 条路径加该目录。`scripts/verify-sync-trimmed-paths.sh --stale upstream/master` 确认每条条目仍能在上游树中解析。

`apps/desktop/package.json` 取上游的 `0.2.2-rc.3` 版本、`@deepseek-ai/dsh-error` 生产依赖与 `dsh-brand`、`dsh-client-connection`、`dsh-host-authentication-desktop`、`dsh-host-webserver` 开发依赖，并保留 fork 的产品名、作者、主页、Linux 专用脚本，以及其对 `tencentcloud-sdk-nodejs-teo` 与 `@deepseek-ai/dsh-desktop-publisher` 的移除。`apps/desktop/tsdown.config.ts` 保留 fork 移位的命令管理 worker 块，并把上游的 `@deepseek-ai/dsh-error` 加入其 `alwaysBundle`。

`apps/desktop/src/main.ts` 采用上游的私有 Host 认证流程：随上游 `web-document.ts` 的改动，`authenticateWebHost` 消失，壳改用自有 Host 在 `ready.authenticationCookie` 报告的 cookie。fork 的 `DesktopCommandManager` 导入保留；上游把该导入上移，合并因此产生重复。

`apps/desktop/scripts/desktop-build-paths.d.mts`、`scripts/development-project.ts` 与 `scripts/package-target.ts` 保留 fork 的 `DesktopBuildTargetName = 'linux-x64'` 与 Linux 专用导入，因为上游版本引用已裁剪的发布工具包。

`apps/desktop/README.md`、`README.zh.md` 及其配对记录采纳上游的 `dsh-error` 段落并去掉指向已裁剪的打包、签名、发布与发布工具指南的链接，保留 fork 的 Linux 打包链接。CUA native README 双语对把两侧都指向 `cua-helper-package-macos.yml`。

`pnpm-lock.yaml` 去掉 `apps/desktop-publisher` importer 与桌面端对它的依赖；`tsconfig.base.json`、`tsconfig.host.json` 与 `scripts/check-workspace-constraints.ts` 去掉其 publisher 路径与豁免。冻结安装无需其它重新生成。

fork 的引擎缓存 action 增加 `packages/util/error/lib`：`dsh-error` 现在是 electron-builder 会打包的桌面端生产依赖，缓存命中的 `--builder-only` 构建否则会产出缺它的主进程。fork 自补的 `apps/desktop/tests/core-package-set.spec.ts` patchedDependencies 用例改读 `DESKTOP_HOST_PROTOCOL_VERSION`，因为上游把协议推进到 5，硬编码 4 会被 `parseDesktopRelease` 拒绝。

**桌面版本等于引擎版本 `0.2.2-rc.3`，不追加构建计数。** fork 的发布仓库还没有 `v0.2.2-rc.3`。

## Alternatives considered

**保留 `apps/desktop-publisher`，只裁剪 Linux 构建从不运行的脚本。** 拒绝：它是一个真实 pnpm workspace 成员，带自己的 COS、EdgeOne 与 macOS/Windows 签名依赖，每枚举 `apps/*` 的门禁都得为它开例外。

**逐条列出全部 53 个 publisher 文件。** 拒绝：目录条目与既有的 `apps/desktop/tests/installed-update/`、`apps/desktop/tests/updates/electron-updater/` 条目风格一致，且一条条目不会与上游文件列表失步。

**在 fork 自补的用例里保留硬编码的 `hostProtocolVersion: 4`。** 拒绝：`parseDesktopRelease` 会拒绝低于当前常量的值，协议更新后这些用例每次都会失败。

**不改引擎缓存 action。** 拒绝：缓存命中会跳过 prepare，`package-target.spec.ts` 在清单漏掉打包的 workspace 包时失败；否则出货应用会在启动时失败。

**把桌面版本提到 `0.2.2-rc.3.1`。** 拒绝：本次合并没有改动 fork 自有的壳行为，其发布历史把构建计数提升与同步合并分开。

## Consequences

下次同步从 `dsh-v0.2.2-rc.3` 之后的 `master` 开始。裁剪清单记录 404 条路径，fork 基线 81 条。Python PTC 在两棵树中都已移除，fork 不再有 `packages/experimental/ptc-runtime-python` 残留；CUA 现在以 `dsh-cua-macos` 与 `dsh-cua-windows` 出货，其 macOS 打包 workflow 名为 `cua-helper-package-macos.yml`。

`pnpm run hygiene` 在本机以 `verify-plugin-entry-exports` 的内存耗尽失败；在 7 GiB 机器上该门禁需要 5120 MiB 堆，本次记录了结果而不再无限重试。

## Testing

`scripts/verify-sync-trimmed-paths.sh` 及其 `--staged` 与 `--stale upstream/master` 形式确认 404 条裁剪路径既不在工作树也不在索引中，且仍存在于上游。`verify-sync-forked-paths --base upstream/master` 报告基线与 fork 修改的文件一致。

`pnpm install --frozen-lockfile` 通过。`node_modules/.bin/tsx scripts/build.ts --scope typecheck` 通过五个门禁。`pnpm run test:docs` 通过 21 个门禁，其中 `translation pairing` 覆盖 1321 对、`markdown links` 通过。`pnpm exec vitest run apps/desktop/tests` 通过 92 个文件、1199 个用例，跳过 5 个。预提交钩子通过翻译配对、归档 Agent Note、暂存区 lint、空白、pi-ai provider 元数据与 vendor manifest 守卫。
