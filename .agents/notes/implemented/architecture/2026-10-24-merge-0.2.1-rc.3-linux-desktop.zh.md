# Agent Note: 0.2.1-rc.3 合并 —— 修复一次错误的冲突解决，而不是把它合并下去

Status: implemented

[English](2026-10-24-merge-0.2.1-rc.3-linux-desktop.md) | 中文

## Problem

上游 `master` 在上一个同步点（`dsh-v0.2.1-rc.2`）之后推进了 1539 个提交，并发布了引擎 `0.2.1-rc.3`。合并目标是 `master` 顶端，它包含该发布以及其后的 1533 个提交；`dsh-v0.2.1-rc.3` 是它的祖先。增量改动 6360 个文件、新增 2911 个，其中有 21 个新包、`liveshare-protocol` 身份层、带 Desktop 接入的 `util/file-drag` 能力、`session/message-quotes`、`util/official-bundles`、`action-cards` 与创建/插件推荐等实验包、`cua-bundle`、拆分出的 `core/tool-executor-native` 与 `core/tool-executor-ptc` 执行器，以及 462 个快照文件。

这次合并的第一次尝试提交为 `the first attempt`。它在没有冲突的情况下解决了工作树，但在 fork 设计与上游重构重叠之处整体采用了上游一侧，因而丢掉了十七处 fork 修改。用 `git diff --numstat upstream/master HEAD` 检查该提交即可看清这一模式：某个文件的结果与上游逐字节相同，而 `main` 曾修改过它。两个后果使那棵树无法使用：

- **update-dialog 子系统内部自相矛盾。** `update-overlay.ts`、`update-dialog.ts` 和 `mandatory-update-window.ts` 取自上游，但 `main.ts`、`preload-update-dialog.ts` 和 `renderer/update-dialog.js` 保留了 fork 的 API。类型检查在 fork 的调用点失败，`update-error-renderer.spec.ts` 也失败，因为 fork 的关闭图标已不存在。
- **六个词典丢掉了 fork 的托盘文案。** `showWindow` 与 `quitMenu` 是 fork 为 Linux 托盘恢复的键，在 `en` 和 `zh` 中存在，却在 `ja`、`es`、`fr`、`de`、`ru`、`pt` 中缺失，导致 `locale.spec.ts` 失败六例。

另外两处 fork 改动以同样方式消失，而且因为没有任何检查失败而更难发现：`packages/ptc-runtime/ptc-runtime-node/tsdown.config.ts` 从 `deps: { alwaysBundle }` 退回已被弃用的 `noExternal`；`apps/desktop/renderer/update-close.svg` 从工作树中消失，尽管没有任何裁剪清单条目覆盖它。

## Decision

**合并就地修复，而不是先接受再补丁。** 分支备份为 `backup/broken-merge-rc3`，并逐文件重做解决过程以恢复 fork 的意图。这条记录要长期承载的规则是：双方都改过的文件，结果可以既不等于本侧也不等于上游，但绝不能在上游 blob 与 `main` 已分叉的情况下等于上游——那正是丢失 fork 改动的特征，而 `git diff --numstat upstream/master HEAD -- <path>` 一条命令即可发现它。

**对话框子系统采用上游的 `WebContentsView` 设计。** 上游用附着在父窗口内的视图取代了独立的透明提示窗口。这一变化从结构上消除了 fork 的 Linux 分支原本要解决的问题：没有合成器的 X11 或 Wayland 会话会把透明窗口的 alpha 画成盖在产品窗口上的不透明板块，因此 Linux 改用了居中的不透明卡片，并加了一条 `resize` 通道来适配高度。文档改在父窗口内合成后，蒙层就天然有了底衬。因此 fork 放弃 `desktopDialogSurface`、`mandatoryUpdateSurface`、`fitDialogCard`、`resize` IPC 通道、`surface` 视图字段以及预涂背景辅助函数。它保留的是显示时读取语言：更新机制在引擎读取 `locale.preference` 之前就已构造，因此在构造时捕获词典会把每个提示固定为 `app.getLocale()`，而菜单却跟随设置。`DesktopUpdateDialog` 与 `DesktopMandatoryUpdateWindow` 上的 `locale: () => DesktopLocale` 保留了这一点，而 `MandatoryUpdateView.locale` 仍是值，因为它要跨 IPC。

**六个词典都恢复托盘文案。** `showWindow` 与 `quitMenu` 是 fork 独有的键，因此任何重写词典块的合并都会在上游没有它们的地方将其丢弃。

**两处意外丢失得到修复，一处得到记录。** `tsdown.config.ts` 恢复为 `deps: { alwaysBundle }`，这是 fork 在 [`2026-09-25-fork-build-config-edits`](../process/2026-09-25-fork-build-config-edits.zh.md) 中采用的、对已弃用 `noExternal` 的当前写法；上游在本次增量中把 `birpc` 加进了同一列表，因此修复后的值同时带有这两项。`update-close.svg` 从上游恢复。`.github/dependabot.yml` 则改为加入裁剪清单：fork 在 `the fork's own CI commit` 中有意删除了它，但没有任何条目记录此事，未来的合并会把它重新带回来。

**上游的引擎工作原样采纳。** fork 没有 `packages/` 分叉，因此 21 个新包、file-drag 能力及其 Desktop 接入、拆分后的执行器、liveshare 身份层以及所有配套测试都按上游作者所写进入工作树。

## Alternatives considered

**合并那次错误的提交，再用后续提交修复。** 否决：`the first attempt` 是一个八千行的冲突解决提交，其错误一侧只有对照上游 diff 文件 blob 才能看出。把它落地会让丢失的修改在历史中与有意的修改无法区分，后续记录也只能描述一次修复而非一次解决。重建分支让每项决定都能对着干净的基线审查。

**保留 fork 的原生窗口卡片设计，拒绝上游的 `WebContentsView` 重写。** 基于证据而非偏好否决。卡片之所以存在，是因为独立透明窗口在没有合成管理器时无法合成其 alpha，而它带出三项后续机制——高度上报通道、surface 字段和预涂颜色——都只为服务它而存在。采用视图把它们全部删除，并让 fork 获得上游对同一代码的持续投入。视图本身不提供的唯一属性——显示时读取语言——是四行改动，fork 早已知道如何做。

**重新记录所有配对哈希然后继续。** 否决：fork 裁剪了 `apps/desktop/packaging/`、`windows-signing/` 和 `publishing/`，而这些正是上游在本次增量中创建、且 `apps/desktop/README.md` 现在链接到的。不删除这些链接就重新记录，等于认可一个指向 fork 不携带文件的 README。

**把 `apps/desktop/tests/signing-concurrency/` 与新增的 Windows 打包脚本整组裁剪。** 对 `signing-concurrency` 双语对否决：它记录了 fork 即使无法运行 Windows 实验也仍然保留的资格验证结果。实际裁剪的是那些唯一的消费者就是它们自身的 Windows/macOS 专用脚本、spec 与 workflow，沿用既有裁剪分组的做法。

## Consequences

下次同步从上游 `master` 的 `master` 顶端开始，而不是从标签开始；标签落后于合并的顶端 1533 个提交。裁剪清单从 377 条增至 407 条，`.github/sync-forked-paths.txt` 记录了在设计采纳后仍然存在的分叉。

fork 在 `update-overlay.ts` 上与上游不再有任何分叉。它在 `update-dialog.ts` 和 `mandatory-update-window.ts` 上各分叉一个构造器选项，以及固定这些选项的测试。未来上游对提示界面的修改可以干净合并；对语言接线的修改会冲突，解决方式是保留 getter。

`apps/desktop/README.md` 跟随上游重构后的版本，共 394 行，把构建与发布操作委托给一份打包指南。fork 不携带那份指南，因此该 README 被改造为自包含：三条指南的项目列表收缩为指向 fork 自己的 [`LINUX_PACKAGING.md`](../../../../apps/desktop/LINUX_PACKAGING.md) 的一句说明，其余指向被裁剪指南的链接改为纯文本。读者会失去那些指南承载的 Windows EV 令牌、公证与 COS 上传细节；fork 不交付任何相关机制。

## Testing

`scripts/verify-sync-trimmed-paths.sh` 及其 `--staged` 形式确认全部 407 条裁剪路径都不在工作树和索引中。`scripts/verify-sync-pairing-after-merge.sh` 与 `verify-translation-pairing` 报告 1120 个双语对一致，`verify-md-links-trimmed` 报告检查 2260 个文件且所有相对链接均可解析。`verify-archived-agent-notes` 报告 6 类共 2775 个冻结产物完好。

`pnpm run typecheck` 干净退出。`pnpm exec vitest run apps/desktop/tests` 通过，包括词典修复恢复的 16 个语言用例，以及针对所采纳设计重新固定的对话框测试套件。`pnpm run test:docs` 通过全部 21 个门禁。

`apps/desktop/package.json` 升至 `0.2.1-rc.3`，与引擎版本相同而不带 `.N` 后缀，因为 fork 的壳代码仅在此次合并丢弃它的地方发生过变化——工作树被恢复为 fork 已经交付的壳，再加上上游的引擎工作。
