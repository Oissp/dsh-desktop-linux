# Agent Note: 0.1.6-alpha.2 合并的 Linux 桌面取舍

Status: implemented

[English](2026-09-18-merge-0.1.6-alpha.2-linux-desktop.md) | 中文

## Problem

上游 0.1.6-alpha.2 把桌面运行时重构为「Electron 即运行时」，并以 darwin/win32 为一等打包目标。本 fork（linux-only deb + AppImage，GitHub Releases 更新源）整体吸收上游重写，但有三处冲突无法靠简单取某一方解决：哪些上游打包面进入裁剪清单、GitHub provider 实际能读哪个更新频道、打包的 Linux 壳是否保留顶部应用菜单。不记录基线，每次上游同步都会重新争论。

## Decision

本次合并整体采纳上游运行时模型，并把三处平台化取舍记录为后续同步的基线：

1. **裁剪清单扩展**（`.github/sync-trimmed-paths.txt`，新增 ~60 项）：mac/win 打包与签名脚本、installed-update 全套、COS 上传传输层、primary-runtime 准备代码及其测试与 fixtures。例外：`primary-runtime-lock.json` 保留——它是纯数据，`scripts/gen-third-party-notices.ts` 及其 spec 直接读取；fork 掉仓库级生成器会制造永久同步冲突，而过度披露（声称比实际捆绑更多）是合规上无害的方向。
2. **更新通道**：fork 的更新源是独立发布仓库 `Oissp/dsh-desktop-linux-release`（GitHub Releases），其频道元数据是 `latest-linux.yml`。本次合并为此钉住 `updater.channel = 'latest'`，以请求该文件而不是上游的 `nightly-linux.yml`。**已被取代**：钉住频道会让 provider 解析不出任何 release tag，因此 [频道推导笔记](../bug-fix/2026-09-19-desktop-update-channel-derivation.zh.md)删掉该赋值，交给已安装版本决定。
3. **打包的 Linux 隐藏顶部菜单栏**：`main.ts` 在 `app.isPackaged && process.platform === 'linux'` 时调用 `Menu.setApplicationMenu(null)`，入口由托盘镜像（显示窗口 / 检查更新 / 退出）承担。`main-startup.spec.ts` 的菜单结构断言改在未打包构建下运行，另有专门用例固定打包行为。

## Deferred

primary-runtime 的 python/pnpm 载荷没有 linux-x64 目标：上游 `primary-runtime-lock.json` 只记录 darwin/win32 摘要，`desktop-host` 的 `readPrimaryRuntime` 平台白名单是 `['win32', 'darwin']`。fork 不随包携带载荷，Host 启动不受影响；但 `load_workspace_dependencies` 工具是惰性安装，调用时会失败。移植载荷是独立工作项，不阻塞本次合并。

## Alternatives considered

**把 `gen-third-party-notices.ts` fork 成 Linux 变体。** 否决：它是每次上游同步都会触碰的仓库级门禁脚本，拆分等于每次发版必然冲突；保留锁数据只会多披露不会漏披露。

**维持 fork 旧的独立 Node 运行时打包。** 否决：上游已把宿主进程、office 集成、workspace 依赖全部改到 Electron 运行时语义上，双轨维护成本高于采纳重写加上 fork 保留的 `native-electron-fingerprint.ts` 改写（Electron 44.2+ 的内置 profile 表精确匹配仍必需）。

**沿用上游 `nightly` 频道并发布 `nightly-linux.yml`。** 否决：频道名必须贯通 electron-builder 配置、release 上传与更新器，相对 `latest`（GitHub provider 开箱即读）没有任何用户可见收益。

## Consequences

后续同步中，扩展裁剪清单内的冲突自动按 keep-trim 解决，打包隐藏菜单与锁文件例外视为已定的 fork 决策而非开放问题；更新通道由 [频道推导笔记](../bug-fix/2026-09-19-desktop-update-channel-derivation.zh.md)定案。代价：fork 在 `update-coordinator.ts` 与 `main.ts` 上持有少量补丁，上游重构这两个文件时需要重放；`load_workspace_dependencies` 工具在 Linux 上保持降级，直到载荷移植落地。

## Testing

`pnpm exec vitest run apps/desktop/tests apps/desktop-host/tests` 覆盖打包菜单固定用例与协调器余下的 updater 标志；`pnpm run typecheck` 编译合并树。打包门禁（`package-deb.yml`）在构建前运行桌面套件。
