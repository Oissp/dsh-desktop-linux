# Agent Note: 0.2.0-rc.2 合并的 Linux 桌面命令面

Status: implemented

[English](2026-09-29-merge-0.2.0-rc.2-linux-desktop.md) | 中文

## Problem

上游 0.2.0-rc.2 包含 187 个提交、1022 个文件。其中大部分是本 fork 原样接受的产品改动：工作区可从侧边栏文件树打开，长会话渲染与鲸鱼动画被重做，定时用户提问回复连同其持久化变更记录一起落地，`pi-ai` 升到 0.87.1 并在兼容性检查中加入 Mistral，设置项不再按代码工作工具开关限制 Creator 入口，ACL 失败可在一次运行中诊断并修复。

桌面这一半带来一个新的用户可见功能——**管理 dsh 命令**：一个原生菜单，可在终端中安装、修复、移除 `dsh` 命令，背后有终端启动脚本、`apps/desktop-host` 中的私有 CLI 入口、提权安装工作进程及其对话框。同一范围内还新增了在首个 Host 启动前读取登录 shell 环境的逻辑，以及安装器归属与回滚的加固。

有 18 处冲突需要判断。其中 10 处是落在 [sync-trimmed-paths.txt](../../../../.github/sync-trimmed-paths.txt) 内的修改/删除冲突。`apps/desktop/package.json` 与根 `package.json` 都改写了桌面脚本块，其中 fork 携带 Linux 打包脚本，上游携带 mac、win 与 upload 脚本。`pnpm-workspace.yaml` 与 `pnpm-lock.yaml` 携带 fork 的 `libreoffice-kit@0.1.2` 补丁，与上游的 `pi-ai@0.87.1` 升级相对。`apps/desktop/scripts/prepare-dsh.ts` 与 `prepare-runtime.ts` 是 fork 自己的 Linux-only 重写。`THIRD_PARTY_NOTICES.md` 是生成文件，`apps/desktop/README.i18n.yaml` 记录的配对两侧都被改过。

## Decision

**桌面命令安装功能整体裁剪。** 它在 Linux 上没有任何代码路径：菜单项在 `main.ts` 中被 gate 为 `darwin` 或 `win32`，`prepareDesktopCli()` 只接受这两个平台，`prepare-command-link.ts` 用 `clang` 编译 macOS 辅助程序，两个启动器分别是 macOS app bundle 脚本与 Windows `.cmd`。共有 28 条路径加入裁剪清单：两个启动器、私有 CLI 入口及其 Windows 控制台信号 shim、安装工作进程、管理器及其对话框，以及随它们到达的 mac 专用测试、夹具与期望输出。`apps/desktop-host` 去掉 `koffi` 依赖与三个仅为内置 profile 服务的 CLI devDependency，两个 `tsdown` 配置回到 fork 的入口。

**`login-shell-environment.ts` 及它抽取出的 `duration-env.ts` 保留。** 该读取逻辑是通用 POSIX 实现，在 `win32` 上原样返回继承的环境，并且从账户记录而不是 `$SHELL` 取登录 shell。fork 的 Linux 启动器面对与 macOS Dock、Finder 相同的缺口：`.desktop` 启动只继承会话管理器的环境，`~/.profile` 中的导出永远不会到达 Host、agent shell 或终端。

**桌面 README 保留合并后的正文，去掉该功能的章节。** 两个语言文件中都移除 `Terminal command` 与 `Bundled command runtime` 章节，因为它们描述的是 fork 不显示的菜单项；`Installation ownership` 一句恢复为 `The CLI cannot boot or mutate this profile.`。新增的 `Host environment` 章节保留：它记录的正是登录 shell 读取。配对哈希重新记录。

**两处 fork 自有的门禁学会裁剪后的形态。** `scripts/check-workspace-constraints.ts` 对 `apps/desktop-host` 只要求 `lib/index.js`，因为被裁剪的 CLI 入口才是 `lib/cli.js` 的来源。`scripts/rescope-vendor.ts` 在 `GENERIC_SKIPS` 中加入三个新的 extensions 事件域文件——该清单已记录 `cordis/*` 是事件命名空间而非包子路径。

## Alternatives considered

**把该功能作为惰性代码携带。** 否决：它的每一层在 Linux 上都不可达，fork 将维护无任何调用方的 locale 文案、`tsdown` worker 产物与运行时载荷要求，并在每次发版时重复解决同一批冲突。

**只裁打包部分，保留 `src/command-*.ts`。** 否决：管理器在 `main.ts` 中被构造，其对话框由 fork 必须保留的文案可达，裁剪边界仍会横穿该功能。

**提供 Linux 启动器并放开菜单。** 作为产品改动否决：上游没有写 Linux 启动器，fork 在合并中的职责是承接上游的工作，而不是扩展它。

**在约束表中保留 `lib/cli.js` 并产出桩文件。** 否决：fork 从不运行的桩文件正是裁剪要消除的惰性代码，而该约束也不再描述实际发布的载荷。

**接受 rescope codemod 对 `cordis/inspect-query` 的重写。** 否决：codemod 的引号规则无法区分包子路径与 extensions 事件域，该重写让 13 个 `cordis-host-runner` 测试失败，因为发射侧保留字面名称。

## Consequences

后续同步按裁剪清单把这 28 条路径解析为 fork 侧的删除。fork 的应用菜单不再有命令注册入口，终端用户仍从 npm 安装 `dsh` 或运行内置 profile。`scripts/check-workspace-constraints.ts` 与 `scripts/rescope-vendor.ts` 从此成为 fork 自有分歧表，上游改动它们时需要保留 fork 侧。桌面版本提升到 `0.2.0-rc.2.1`，与 0.1.x 线一样跟随引擎基线。各次发布的合并笔记仍然有效：每篇记录自己那一段上游范围，互不取代。

## Testing

`pnpm run typecheck` 与 `pnpm run lint` 干净。`pnpm run test:docs` 报告 21 项通过、0 项失败，其中包括读取扩展后裁剪清单的 `markdown links`，以及校验重新记录的 README 配对的 `translation pairing`。`pnpm exec vitest run apps/desktop/tests apps/desktop-host/tests` 在 71 个文件中通过 789 个测试；`pnpm exec vitest run packages/extensions/cordis-host-runner` 在修正跳过清单后通过 114 个。`pnpm run test:snapshot -t cordis-inspect` 的 3 个用例通过。`pnpm run test` 报告 10 个失败文件，均非本次合并所致：6 个 CI workflow spec 读取 fork 不携带的 `.github/workflows/ci.yml` 及其同类文件；`executor`、`spawn-runner` 与 `helper-processes` 在合并前的本机就以同样方式失败；`checkers` 单独运行时通过。`pnpm run hygiene` 在合并前后报告同样的两个既有失败——`constraints` 要求 `@deepseek-ai/dsh-desktop` 等于根版本，而 fork 的构建后缀从不如此，`publint` 报告 300 个发布视图声明 `files` 中不含 `src` 却导出 `./src/*`——同时 `vendor rescope` 现已通过。
