# Agent Note: 0.2.2-alpha.2 post-release sync — the fork adopts upstream's file actions and keeps its Linux menu

Status: implemented

English | [中文](2026-10-30-merge-0.2.2-alpha.2-linux-desktop.zh.md)

## Problem

Upstream `master` advanced 351 commits past the previous sync point at tag `dsh-v0.2.2-alpha.2`; the engine version stays `0.2.2-alpha.2` because no release tag follows the previous one. The delta changes 1461 files — 365 added, 9 deleted, 1087 modified — with three new packages (`client/ui-context-menu`, `client/ui-file-actions`, `fs/fs-patch`) and the shell's file-action, DevTools menu grouping, sidebar workspace-tree, schedule/automation, forge and CUA-helper work.

Merging produced nineteen conflicts: thirteen modify/delete conflicts on trimmed paths and six content conflicts (`apps/desktop/README.i18n.yaml`, `apps/desktop/package.json`, `apps/desktop/src/main.ts`, both application-menu snapshots, and `apps/desktop/tests/main-startup.spec.ts`). The fork carries no `packages/` divergence, so the upstream engine work enters unchanged; the decisions land on the shell, its menu tests, and the sync lists.

## Decision

**The merge adopts upstream's file actions and menu grouping while keeping the fork's Linux shell.** `apps/desktop/src/main.ts` gains upstream's `installFileActions` wiring and the visible localized "Developer tools" command with its hidden F12 alias (Windows keeps its hidden shortcut pair), and keeps the fork's packaged-Linux `Menu.setApplicationMenu(null)` and `rebuildTrayMenu`. The desktop-cli "Manage dsh Command…" item stays in the Linux tray menu only: upstream moved it into the application menu for darwin and win32, and copying that would have moved a fork entry into a menu the packaged shell never shows. The language dictionaries keep the fork's tray strings and take upstream's `toggleDevToolsMenu`. The paired desktop README takes upstream's new DevTools and file-action paragraphs; only its pairing record needed re-recording.

**The menu snapshots and startup spec record the fork's menu, not upstream's.** Both `apps/desktop/tests/expected/application-menu-*.json` files and the menu assertions in `main-startup.spec.ts` drop the desktop-cli item and add upstream's DevTools group. Upstream's new DevTools test now asserts the packaged-Linux tray menu (Show Window, Check for Updates, Manage dsh Command, Quit) and its language refresh, and mocks `app.getLocale` because the tray's `DesktopLocaleController` falls back to the system locale rather than `getPreferredSystemLanguages`. These three test paths join `.github/sync-forked-paths.txt` (30 → 34 paths).

**Seven more upstream files are trimmed, and the trim list grows from 418 to 425 paths.** The macOS-only `cua-helper-package.yml` workflow; the four `apps/desktop/config/publishing/*/*.json.example` templates and their `desktop-publish-templates.spec.ts` reader, which imports the trimmed `desktop-publish-config.ts`; and `scripts/cua-helper/package.ts`, which imports the trimmed macOS signing and notarization scripts, are absent from the fork. The remaining `scripts/cua-helper` modules stay: `scripts/release/publish.ts` imports `verify-tarball.ts`, and the payload, artifact-selection, staging and smoke modules typecheck and pass their tests. All thirteen modify/delete conflicts were trimmed paths, so the trim list resolved them without a decision.

**`apps/desktop/package.json` keeps the fork's packaging surface and takes upstream's new dependency.** The Linux-only scripts, fork author and homepage, and the absent `tencentcloud-sdk-nodejs-teo` stay; `@deepseek-ai/dsh-client-ui-file-actions` joins as the dependency the shell now needs. The lockfile needed no regeneration: `pnpm install --frozen-lockfile` accepts the merged file.

**The desktop version stays `0.2.2-alpha.2`, equal to the engine version.** Upstream cut no release after the previous sync point, and the fork's packaging workflow keys on `apps/desktop/package.json`; a new build requires a separate build-counter bump. This merge changes no fork-authored shell behavior, only adopts upstream's.

**The CUA native README links one target in both languages.** Upstream points the English page at `apps/desktop/packaging/README.md` and the Chinese page at `README.zh.md`; the fork trims that guide, so the pairing check could not collapse the two locales into one semantic target. The Chinese page now links the English target, which the trim-list link exemption covers in both languages, and the page joins `.github/sync-forked-paths.txt`.

## Alternatives considered

**Keep upstream's desktop-cli item in the application menu.** Rejected: the fork moved that entry into the Linux tray when it hid the packaged menu bar; duplicating it would add a command the packaged shell never displays and contradict `main.ts`'s recorded fork behavior.

**Keep the packaged Linux application menu so the DevTools command is always reachable.** Rejected: hiding the menu bar is a shipped fork decision whose tray mirrors Show Window, Check for Updates, Manage Command and Quit; DevTools remain reachable through F12 and the unpackaged application menu.

**Restore the macOS signing scripts so `scripts/cua-helper/package.ts` typechecks.** Rejected: the fork carries no macOS packaging pipeline; restoring the scripts would bring back the trimmed pipeline only to keep an orphaned entry compiling.

**Trim the whole `scripts/cua-helper` tree.** Rejected: `scripts/release/publish.ts` imports the tarball verifier, and the payload, selection, staging and smoke modules and their tests are self-contained and pass.

**Keep the publishing templates and their spec.** Rejected: the spec imports the trimmed `desktop-publish-config.ts`, so it cannot typecheck, and the templates only feed the trimmed publishing pipeline.

**Bump the desktop version in the merge commit.** Rejected: the engine version did not change, the fork's release history separates build-counter bumps from sync merges, and keeping the version equal also keeps `check-workspace-constraints` green.

**Regenerate the lockfile.** Rejected: the frozen install accepts the merged file, so a fresh resolution would only move unrelated transitive versions.

## Consequences

The next sync starts from upstream `master` beyond tag `dsh-v0.2.2-alpha.2`. The engine is still `0.2.2-alpha.2`, so shipping this sync requires an explicit `chore(desktop): 版本提升到 0.2.2-alpha.2.N` bump; merging alone finds the already-published `v0.2.2-alpha.2` release and skips publishing. The trim list records 425 paths and `.github/sync-forked-paths.txt` records 34 fork-modified paths.

`scripts/rescope-vendor.ts --check` fails on this upstream commit: its postcondition still looks for `17. **@deepseek-ai rescope**`, while upstream's stable-ID rewrite of `vendor/README.md` changed the line to `V17 · @deepseek-ai rescope`. Upstream `master` carries the same mismatch, so the fork inherits it; a later vendor sync that runs `pnpm run rescope-vendor --apply` needs the postcondition updated to the stable-ID text.

`scripts/ci-workflow.spec.ts` and `scripts/tests/ci-release-selfhosted.spec.ts` keep reading trimmed workflows (`ci.yml`, `release-publish.yml`, `cua-helper-package.yml`), so repository-wide unit runs keep failing where the fork's CI does not run them.

`pnpm install --frozen-lockfile` passes. `pnpm run typecheck` reports five gates passed (the host aggregate needs `NODE_OPTIONS=--max-old-space-size=5120` on this 7 GiB host), `pnpm run build:artifacts` eight and `pnpm run build:check` two. `pnpm run lint` reports zero errors and one warning in upstream's `packages/experimental/client-ui-cot-translation` (an unused `oxlint-disable` directive). `pnpm run test:docs` passes all 21 gates. `pnpm exec vitest run apps/desktop/tests` passes 87 files and 1067 tests with five skipped.

`pnpm run hygiene` passes 22 of its 23 gates; `rescope-vendor:check` fails on the upstream postcondition mismatch described above, and `verify-optional-dependency-imports` passes within the 5120 MiB heap.
