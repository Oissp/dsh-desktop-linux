# Agent Note: 0.2.3-alpha.1 upstream sync — the fork adopts five connectors and a promoted recommendation stack while trimming the new Windows packaging tools

Status: implemented

English | [中文](2026-11-22-merge-0.2.3-alpha.1-linux-desktop.zh.md)

## Problem

Upstream `master` advanced 703 commits past the merge base that `0.2.2-rc.5` left behind and cut `0.2.3-alpha.1`. The delta changes 3163 files — 740 added, 41 deleted, 2234 modified, 147 renamed, and 1 type change — with 93977 insertions and 17483 deletions. It adds five hosted-MCP connectors in `packages/connector/{dingtalk,feishu,tencent-docs,tencent-meeting,wecom}`, each with its own `cordis.patch.yml`, locales, snapshots and upgrade guides; graduates action cards and the recommendation stack from `packages/experimental` into `packages/{interaction,client,extensions}` and retires `packages/experimental/personalized-recommendations`; adds `packages/session/tool-session-control` and `packages/client/remote-connection`; consolidates the Office skill into a single `office` entry whose format guidance loads on demand; adds CUA recent-window activity and held system keyboard/mouse input (macOS and Windows), an inline composer placeholder slot, model-catalog reasoning levels, deferred system compaction, and an SDK prompt time zone. It also adds Windows packaging summary, uninstall-registration and CI-runner process tooling under `apps/desktop`.

The merge produced 47 conflicts. Forty-one are on trimmed paths: forty listed files plus `apps/desktop-publisher/package.json`, covered by the whole-directory entry. The six content conflicts were `apps/desktop/package.json`, `apps/desktop/README.md` and `.zh.md` with their `README.i18n.yaml` pairing record, `apps/desktop/tests/main-startup.spec.ts`, and `docs/development.i18n.yaml`.

## Decision

**Trimmed paths stay deleted, and twelve new Windows packaging/CI files join the trim list.**

The modified trimmed files resolve to the fork's deletion. The new upstream files `apps/desktop/installer/uninstall-report.h`, `apps/desktop/scripts/{uninstall-registration.ps1,windows-packaging-summary.d.mts,windows-packaging-summary.mjs,windows-runner-processes.cs,windows-runner-scheduler.ps1}`, and `apps/desktop/tests/{windows-installer-process-test.ps1,windows-installer-process.ps1,windows-packaging-summary.spec.ts,windows-runner-boot.ps1,windows-runner-processes.ps1,windows-runner-recovery.ps1}` are consumed only by trimmed installer sources, the trimmed Windows workflows (`windows-package.yml`, `ci-windows.yml`) and the trimmed `windows-runner-task.ps1`. They are added to a `0.2.3-alpha.1` group in `.github/sync-trimmed-paths.txt`; `apps/desktop/tests/fixtures/register-test-protocol.cjs` stays because it is a cross-platform fixture. `scripts/verify-sync-trimmed-paths.sh --stale upstream/master` confirms all 419 listed paths are absent from the worktree and still exist upstream.

`apps/desktop/package.json` takes upstream's `0.2.3-alpha.1` version and keeps the fork's `productName`, author, homepage, Linux-only scripts, and its removal of the macOS/Windows packaging scripts and the publisher devDependency. No new reference to the trimmed publisher workspace arrived, because upstream's packaging scripts remain outside the merged script block.

The `apps/desktop/README.md` and `.zh.md` Windows-installer section keeps the fork's "not shipped in this Linux fork" paragraph and omits the upstream paragraph that documents running `scripts/test-windows-installer.mjs`, which is trimmed. The desktop `README.i18n.yaml` pair is re-recorded after the merge.

`apps/desktop/tests/main-startup.spec.ts` adopts upstream's new Settings application-menu item and keeps the fork's divergence: the application menu still has no "Manage dsh Command…" item, which the fork shows only in the Linux tray. Its expectations therefore gain `messages.settingsMenu` after the About separator while keeping the fork's developer-tools entries. The import conflict resolves to both sides — upstream's `WELCOME_IPC` for the new welcome-skip tests and the fork's `SCHEME` for its protocol-handler test.

`docs/development.i18n.yaml` is re-recorded because upstream edits the TypeScript-layout paragraph in both languages.

`scripts/rescope-vendor.ts` adds `apps/web/tests/input-plugin-extensions.e2e.ts` to `GENERIC_SKIPS` for `schemastery`. The new test builds an installed-package fixture by joining a private `node_modules/@deepseek-ai` scope directory with a separate `schemastery` segment, the same filesystem layout as `client-config-sync.e2e.ts`; rewriting the segment would nest the vendored directory one level too deep.

The desktop version equals the engine version, `0.2.3-alpha.1`, with no build counter, because the merge changes no fork-authored shell behavior. Upstream's Settings entry is an engine change; the tray's existing entries are unchanged.

## Alternatives considered

**Mirror the new Settings item into the packaged Linux tray.** Rejected: Settings has an in-app UI entry and a registered shortcut, and the packaged Linux tray mirrors the entries whose application-menu counterparts it replaced (show window, check updates, Manage dsh Command, quit). Adding it would be fork-authored shell behavior that needs a build-counter bump for a convenience entry already reachable.

**Rename the fixture's `schemastery` segment to the scoped package name instead of skipping it.** Rejected: the segment is a directory entry inside the private `@deepseek-ai` scope directory, not a package specifier. Renaming it produces `node_modules/@deepseek-ai/@deepseek-ai/schemastery`, which resolves to nothing.

**Keep upstream's `test-windows-installer.mjs` usage paragraph in the desktop READMEs.** Rejected: the script and its PowerShell fixtures are trimmed, so the paragraph would document a command the fork cannot run.

**Add the new Windows CI-runner scripts rather than trimming them.** Rejected: they run only on upstream's Windows runner through the trimmed `ci-windows.yml`, and the C# process helper is loaded by the trimmed `windows-runner-task.ps1`.

## Consequences

The next sync starts from upstream `master` beyond tag `dsh-v0.2.3-alpha.1`. The new trim entries follow Windows packaging and runner tooling that upstream keeps developing, so later syncs may report modify/delete for them and resolve to deletion. The recommendation stack now lives under `packages/{interaction,extensions,client}`, so fork-local references to the retired `packages/experimental` locations must move with it. `apps/desktop/tests/main-startup.spec.ts` remains a fork-modified file whose application-menu expectation now differs from upstream only by the Manage dsh Command item; a future upstream menu addition needs the same comparison. The fork baseline still matches the fork-modified files at the new merge base.
