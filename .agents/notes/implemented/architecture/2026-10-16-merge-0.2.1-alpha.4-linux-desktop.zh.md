# Agent Note: 0.2.1-alpha.4 合并——插件市场到来，Linux 进程隔离加固

Status: implemented

[English](2026-10-16-merge-0.2.1-alpha.4-linux-desktop.md) | 中文

## Problem

上游 `master` 在上一次同步点之后前进 73 个提交，发布引擎 `0.2.1-alpha.4`（tag `dsh-v0.2.1-alpha.4`）；增量改动 802 个文件。覆盖五个领域：插件市场（新增 `packages/boot/plugin-market`、`packages/util/plugin-market-index`、`packages/client/ui-plugin-market` 与 `packages/experimental/plugin-market-bundle`，以及私有的 `apps/plugin-market-generator` 参考生成器、Discover 安装流程和「自定义插件市场」bundle）、客户端宿主版本变更刷新提示（`packages/client/modules` 在应用其他宿主版本的图之前先比对宿主发布版本）、composer 命令 chip（`ui-conversation`、`ui-commands` 与 `ui-input-trigger` 将斜杠命令作为原子 chip 认领）、自定义 API 模型的推理等级编辑，以及 Linux 进程隔离（`packages/subprocess/subprocess-local` 探测用户 systemd manager，为原生 scope 支持 v254 之前的 systemd，并把隔离决策移入可测试的选择器）。

合并产生 24 处冲突。23 处是命中被裁剪桌面路径的修改/删除对：发布路由与发布记录库、目录安装器脚本及其测试，均在前几次同步中已被 fork 删除。唯一的内容冲突是 `apps/desktop/package.json`。

两个上游新增文件合并不冲突，但属于被裁剪的 macOS/Windows 范围：Windows NSIS 的 `directory-report.h` 头文件，以及读取被裁剪的 `macos-package.yml` 与 `windows-package.yml` 的 `scripts/desktop-package-source.spec.ts` 夹具。

## Decision

**所有修改/删除冲突保留 fork 的删除。** 23 条被裁剪路径用 `git rm` 删除，保持 fork 的 Linux-only 姿态。

**两个新的 macOS/Windows 文件被裁剪，清单从 348 条增至 350 条。** `apps/desktop/installer/directory-report.h` 沿用此前对 `extract-report.h` 与 `uninstall-data.h` 的裁剪：它是被裁剪的目录安装器专用的 Windows 头文件，仅被保留的 Windows 专有源码 `window-frame.cpp` 引用，Linux 构建从不编译它。`scripts/desktop-package-source.spec.ts` 读取两个被裁剪的打包 workflow，且两个夹具都不存在，spec 无法运行——与 `scripts/windows-package-workflow.spec.ts` 被裁剪的原因相同。

**`apps/desktop/package.json` 保留 fork 元数据，采用上游版本号。** `author` 与 `homepage` 仍是 fork 仓库。版本号升至 `0.2.1-alpha.4`（与引擎版本一致）。scripts 仍只有 Linux 目标，fork 保留 `tar`、省略 `koffi`。

**自动合并的 fork 修改文件保留 fork 内容。** `apps/desktop-host/package.json` 只取版本号，保持无 `koffi`。`scripts/check-workspace-constraints.ts` 取上游新增的 `apps/plugin-market-generator` 例外。`THIRD_PARTY_NOTICES.md`、`package.json` 与 `pnpm-lock.yaml` 两侧都合：上游的 `hosted-git-info`、`minisearch`、`@types/hosted-git-info` 与迁移后的 `tar` 条目、新增的 `verify-no-top-level-await` 脚本，与 fork 的 `libreoffice-kit@0.1.5` 条目和 Linux-only 依赖集并存。`scripts/no-unknown-casts.baseline.json` 取上游收缩后的基线。

**桌面壳的 Linux 改动原样保留。** 本次同步没有任何上游提交改动 fork 修改的桌面源文件：`main.ts`、`locale.ts`、`update-coordinator.ts`、`desktop-build-paths.mjs`、`electron-builder.config.mjs`、`package-target.ts`、`prepare-runtime.ts` 与 desktop-cli 文件全部原样带过；上一次同步中与 fork 相悖的两个自动合并上游测试（`update-coordinator.spec.ts`、`package-target.spec.ts`）本次未被改动。

**上游的 Linux 隔离工作原样采用。** `packages/subprocess/subprocess-local` 是 fork 所服务的上游 Linux 工作，fork 在 `packages/` 上没有分叉，新增的 `linux-scope-selector.ts` 未经修改进入代码树。

## Alternatives considered

**保留 `apps/desktop/installer/directory-report.h`。** 拒绝：fork 已裁剪其他所有新增的 Windows 安装器源码（`extract-report.h`、`uninstall-data.h`、`uninstall.nsh`），而该头文件只服务于被裁剪的目录安装器。保留的 `window-frame.cpp` 仍 include 它，与它既有的、对同样被裁剪的 `extract-report.h` 的悬空 include 一致；它在 Linux 上从不编译。

**保留 `scripts/desktop-package-source.spec.ts`。** 拒绝：fork 保留了另两个其 workflow 已被裁剪的 spec（`macos-package-workflow.spec.ts`、`desktop-publish-workflow.spec.ts`），但本 spec 是已被裁剪的 `scripts/windows-package-workflow.spec.ts` 的直接同类，且它读取的夹具全部缺失。

**把上游的 Linux 隔离改动回退到 fork 此前的行为。** 拒绝：fork 正是这些工作所服务的 Linux 消费者，且该选择器是上游规划的引擎工作，而非 macOS/Windows 专有路径。

## Consequences

下一次同步从上游 tag `dsh-v0.2.1-alpha.4` 开始。裁剪清单共 350 条路径。

fork 仍携带半裁剪的 Windows 安装器源码树：`window-frame.cpp` 与 `installer/*.nsh` 保留，而它们 include 的头文件被裁剪。它们在 Linux 上无作用，整组裁剪仍是未来可能的简化方向。

`pnpm run test:docs` 仅 `verify-repository-references` 失败，它标出上一次合并的 Agent Note 与 `python/sdk/uv.lock` 中的 commit 哈希文本。两个文件都未被本次合并改动，该失败早于本次合并。
