# Agent Note: 0.2.1-alpha.2 合并——桌面打包重构、plan-mode 与 ui-chat 修复到来

Status: implemented

[English](2026-10-10-merge-0.2.1-alpha.2-linux-desktop.md) | 中文

## Problem

上游 `master` 在上一次同步之后前进 669 个提交，发布引擎 `0.2.1-alpha.2`。增量覆盖四个领域：桌面打包基础设施（Electron 44.7.0、electron-builder 26.17.0、Windows 手动打包 CI、运行时补丁模块重构）、plan-mode 行为修复（仅在批准时退出、取消时结束轮次）、ui-chat 布局修复（折叠跟随、流式布局、子像素取整）以及 web 功能新增（Auto 审核盾牌-A 权限图标、实验性目录页、插件设置重组）。

合并产生 44 处冲突，分为三类。16 处修改/删除对命中被裁剪的 workflow 与桌面脚本路径。14 处内容冲突命中 fork 修改路径文件（`package-target.ts`、`prepare-dsh.ts`、`prepare-runtime.ts`、`package-target.spec.ts`、`apps/desktop/package.json`）。其余命中版本提升文件、`pnpm-workspace.yaml`、`pnpm-lock.yaml`、`THIRD_PARTY_NOTICES.md` 与双语配对记录。

五个上游新增文件未冲突但需裁剪：Windows 手动打包 workflow 及其准备/测试基础设施，以及上游运行时补丁模块及其测试。两个新增上游测试文件测试 mac/win 目标与 fork 不使用的上游专有运行时代码路径。

## Decision

**所有修改/删除冲突保留 fork 的删除。** 16 条被裁剪路径（16 个 `.github/workflows/*.yml` 文件与 12 个桌面脚本/测试）以 `git rm` 移除，以保持 fork 的 Linux-only 定位。

**所有 fork 修改路径源文件保留 fork 版本。** 上游对 `package-target.ts`、`prepare-dsh.ts`、`prepare-runtime.ts`、`package-target.spec.ts` 的改动完全是 macOS/Windows 签名、公证与打包运行重构。fork 的 `prepare-dsh.ts` 有自己的内联 `applyRuntimePatches` 函数；fork 的 `prepare-runtime.ts` 是 Linux-only，从 `../../../scripts/primary-runtime/prepare.ts` 导入而非上游的 `prepare-primary-runtime.ts`。这些文件中的上游增量均不影响 Linux 路径。

**`apps/desktop/package.json` 保留 fork 元数据、采用上游版本。** `author` 与 `homepage` 继续指向 fork 仓库。版本移到 `0.2.1-alpha.2`（等于引擎版本——无壳源码改动）。依赖版本跟随上游：Electron `^44.7.0`、electron-builder `26.17.0`、`pnpm` `11.28.5`、`sharp` `^0.35.5`、`js-yaml` `^4.3.2`、`vite` `^6.4.3`、`@types/node` `^22.20.1`。fork 保留 `tar`（运行时树打包使用）并省略 `koffi`、`cos-nodejs-sdk-v5`、`@electron/notarize`（mac/win 专有）。

**`pnpm-workspace.yaml` 保留 fork 的 `libreoffice-kit` 补丁并采用上游的 `pi-ai@1.0.2`。** fork 的 `@deepseek-ai/libreoffice-kit@0.1.5` 补丁是 fork 专有；上游将 `@earendil-works/pi-ai` 从 0.87.1 升级到 1.0.2，fork 随之携带。

**`THIRD_PARTY_NOTICES.md` 保留 fork 的 `libreoffice-kit` 条目并采用上游的 `pi-ai@1.0.2` 条目。**

**五个 Windows 打包新文件被裁剪并加入裁剪清单。** `windows-package.yml`（手动 Windows 打包 workflow，使用专用 self-hosted Windows runner）、`prepare-windows-ci.mjs`/`.d.mts`（读取 `.env.windows`、调用被裁剪的 `desktop-package-environment.mjs`）、`prepare-windows-ci.spec.ts`、以及 `scripts/windows-package-workflow.spec.ts`（读取 `windows-package.yml` 并断言 `win-x64` 目标路径）均为 Windows 专有基础设施，fork 无法使用。

**上游运行时补丁模块及其测试被裁剪。** `prepare-runtime-patches.ts` 与 `runtime-patch-policy.ts` 将运行时补丁分类重构为 runtime 与 workspace-only 两组。fork 的 `prepare-dsh.ts` 有自己的 `applyRuntimePatches` 函数，不导入这些模块——它们是孤儿代码。`prepare-runtime-patches.spec.ts` 与 `runtime-preparation.spec.ts` 测试 mac-arm64/mac-x64/win-x64 目标与上游专有代码路径（mock 被裁剪的 `prepare-primary-runtime.ts` 与 `prepare-command-link.ts`）；fork 的实现结构不同，测试无法通过。

**桌面版本等于引擎版本。** 本次同步没有改动任何壳源码，因此 `apps/desktop/package.json` 直接移到 `0.2.1-alpha.2`，不带 `.N` 构建后缀。

**双语配对哈希已重新生成。** `docs/development.md`/`.zh.md` 保留 fork 的 CI 门禁文本（描述 `package-deb.yml`）；`apps/desktop/README.i18n.yaml` 与 `docs/development.i18n.yaml` 保留 fork 侧哈希，`scripts/verify-sync-pairing-after-merge.sh` 重新记录 `apps/desktop/README.i18n.yaml`。

## Alternatives considered

**采用上游运行时补丁模块。** 拒绝：fork 的内联 `applyRuntimePatches`（在 `prepare-dsh.ts` 中）正确工作，且与上游的打包运行步骤日志无耦合。迁移需要同时采用被裁剪的 `packaging-step.mjs`，并围绕 fork 不使用的 `packagingStep` 调用重构 `prepare-dsh.ts` 的 `main()`。

**保留上游测试文件并 mock fork 的代码路径。** 拒绝：`runtime-preparation.spec.ts` mock 了被裁剪的 `prepare-primary-runtime.ts` 与 `prepare-command-link.ts`。重写测试以面向 fork 的 `prepare-runtime.ts` 将重复 fork 自己的 `smoke-runtime.ts` 覆盖，不增加信号。

**给桌面版本加 `.1` 后缀。** 拒绝：本次没有壳源码改动，纯引擎同步正是发版版本门禁接受裸引擎版本的情形。

## Consequences

下一次同步从 `0.2.1-alpha.2` 发版（上游 PR #5946）开始。裁剪清单增长 9 条（5 个 Windows 打包 + 4 个运行时补丁/测试文件），总计 276 条裁剪路径。

fork 的 `prepare-dsh.ts` 保留自己的 `applyRuntimePatches` 函数。如果未来上游同步改变了补丁应用机制，fork 的函数可能需要独立于上游的 `prepare-runtime-patches.ts` 更新。

`scripts/ci-workflow.spec.ts` 在本 fork 上按构造继续失败（其 workflow 测试读取被裁剪的 `.github/workflows/*.yml` 文件）。fork CI 不运行该 spec。
