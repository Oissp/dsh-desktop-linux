# Agent Note: 0.2.2-rc.4 upstream sync — the fork follows the account package split and trims one more CI workflow

Status: implemented

English | [中文](2026-11-18-merge-0.2.2-rc.4-linux-desktop.zh.md)

## Problem

Upstream `master` advanced 807 commits past the parent that `dsh-v0.2.2-rc.3` forked from and cut `0.2.2-rc.4`. The delta changes 3104 files — 590 added, 95 deleted, 2374 modified, 45 renamed — with 88070 insertions and 31776 deletions. It moves `packages/credentials/deepseek-account` to `packages/account/deepseek-account`, adds `packages/account/deepseek-auth`, `packages/mcp/mcp-account`, `packages/connector/cli-account`, `packages/connector/upstream-skills`, `packages/client/config`, `packages/experimental/forge-gitlab` and `packages/session-query/tool-session-list`, switches session persistence to SQLite with legacy JSONL import on open (`packages/session/session-persistence-sqlite`), merges `create_worktree` into `enter_worktree`, and adds the `.github/workflows/stale-pull-requests.yml` workflow with its `.github/stale-pull-requests` support scripts.

The merge produced five conflicts: two modify/delete conflicts on trimmed paths (`.github/workflows/pr-check-on-head-branch.yml`, `apps/desktop-publisher/package.json`) and three content conflicts (`apps/desktop/package.json`, `packages/experimental/webworker-runtime/tsdown.config.ts`, `pnpm-lock.yaml`). Unlike the `0.2.2-rc.3` merge, no upstream change touched a fork-modified desktop shell source file such as `main.ts` or the packaging scripts; the two baseline entries that did conflict, `apps/desktop/package.json` and the webworker-runtime tsdown config, are resolved below.

## Decision

**Trimmed paths stay deleted, and the trim list gains the one new upstream workflow.**

The two modify/delete conflicts resolve to the fork's deletion. Upstream reintroduced `apps/desktop-publisher/` wholesale without a conflict; the directory is removed again before the merge commit so the fork's workspace stays free of the publisher's COS, EdgeOne and signing dependencies. `.github/workflows/stale-pull-requests.yml` joins the trim list with the other upstream CI workflows, because the fork runs only `package-deb.yml` and `package-deb-test.yml`; its support scripts under `.github/stale-pull-requests/` stay, matching the kept `.github/review-ownership/` and `.github/issue-management/` trees. The list records 405 paths, and `scripts/verify-sync-trimmed-paths.sh --stale upstream/master` confirms each one still exists in the upstream tree.

`apps/desktop/package.json` takes upstream's `0.2.2-rc.4` version and keeps the fork's `productName`, author, homepage, Linux-only scripts, and its removal of the macOS/Windows packaging scripts and the publisher devDependency.

`packages/experimental/webworker-runtime/tsdown.config.ts` keeps the fork's option naming (`deps.alwaysBundle` and `outputOptions.codeSplitting: false`) and takes upstream's new `bufferPackagePlugin`, which resolves the `buffer` npm package for bundled CommonJS that names the builtin. The fork converted all three of its tsdown configs to this naming in earlier syncs; the merged file keeps the convention with upstream's plugin added.

`pnpm-lock.yaml` takes upstream's `packages/account/deepseek-account` link path and drops the `apps/desktop-publisher` importer, which the frozen install confirms.

The translation pairing record for `packages/document/office-kit/README.i18n.yaml` was re-recorded after the merge changed the English page. The desktop version equals the engine version, `0.2.2-rc.4`, with no build counter, because the merge changes no fork-authored shell behavior.

## Alternatives considered

**Adopt upstream's tsdown option spelling (`noExternal`, `inlineDynamicImports`).** Rejected: the fork's other two tsdown configs (`browser-use-stagehand-native`, `inspector`) use `deps.alwaysBundle` and `codeSplitting: false`, and the build relies on that naming; adopting upstream's spelling in one file would split the convention and leave two spellings of one option in the tree.

**Keep `.github/workflows/stale-pull-requests.yml` because the fork could close its own stale pull requests.** Rejected: the fork merges upstream releases by hand and does not run upstream's issue and pull-request automation, which the trim list already removes.

**Bump the desktop version to `0.2.2-rc.4.1`.** Rejected: the merge changes no fork-authored shell behavior, and the fork's release history separates build-counter bumps from sync merges.

**List the publisher workspace's files individually instead of relying on the directory entry.** Rejected: upstream now ships the publisher workspace under a different layout than the 53 entries the previous sync retired, and one directory entry cannot drift out of sync with upstream's file list.

## Consequences

The next sync starts from upstream `master` beyond tag `dsh-v0.2.2-rc.4`. The account provider lives at `packages/account/deepseek-account`; any fork-local reference to `packages/credentials/deepseek-account` must move with it. The trim list records 405 paths, and the fork baseline still matches the fork-modified files at the new merge base without new entries: the new `client-config-sync` e2e stays upstream-owned through a `scripts/rescope-vendor.ts` skip entry for its `'schemastery'` path segment.
