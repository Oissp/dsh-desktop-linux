# Agent Note: 0.2.2-rc.1 upstream sync — the fork keeps its single update feed and Linux shell

Status: implemented

English | [中文](2026-11-04-merge-0.2.2-rc.1-linux-desktop.zh.md)

## Problem

Upstream `master` advanced 260 commits past the previous sync point and cut `0.2.2-rc.1`. The delta changes 1593 files — 133 added, 8 deleted, 1451 modified, 1 renamed — and rebuilds the Desktop publication pipeline around a website installer, CI archive and retention, and EdgeOne purge recovery. It also adds the desktop channel version policy and staging rollout percentage, the Session menu's Open in app action, subagent catalog naming, generation continuation after failure, apply-patch row summaries, CSS-anchored panels, the CUA app approval UI, CUA publish source reuse, and PTC timeout and call-limit handling. The fork's engine-side divergences remain the tsdown build configs and one skill-office version assertion; none of them conflicted.

Merging produced 71 conflicts: 60 modify/delete conflicts on trimmed paths (59 listed files plus `apps/desktop/tests/updates/electron-updater/qualification.mjs`, which sits under a trimmed directory) and 11 content conflicts (`apps/desktop/package.json`, `apps/desktop/src/main.ts`, `apps/desktop/tests/update-coordinator.spec.ts`, the desktop README bilingual pair, the CUA native README bilingual pair, and the `2026-08-25-electron-desktop-packaging-and-updates` note triplet).

## Decision

**The merge takes upstream's channel-selection surfaces and macOS menu changes while keeping the fork's single-feed updater, Linux tray, and trimmed publication pipeline.**

`apps/desktop/src/update-coordinator.ts` keeps `configureUpdateFeed`: one `latest-linux.yml` feeds every release, both Settings channels accept prereleases, and `updater.channel` stays unset so the GitHub provider resolves the fork's `v<desktop version>` tags. `update-coordinator.spec.ts` keeps the single-feed assertions and adds upstream's older, equal, and malformed version rejection cases without a channel assertion.

`apps/desktop/src/main.ts` keeps the fork's appearance controller, locale controller, packaged-Linux `Menu.setApplicationMenu(null)`, tray, and desktop-cli entry, and accepts upstream's macOS Edit menu (Paste and Match Style on Shift+Command+V, plus substitutions and speech submenus), the `DesktopMessages` type import, and the added locale strings.

`apps/desktop/package.json` keeps the fork's product name, author, homepage, and Linux-only scripts, and takes upstream's `0.2.2-rc.1` version.

The desktop README pair takes upstream's channel-policy wording — publishers choose versions independently of version suffixes, Stable can also deliver alpha or RC versions, and an omitted channel uses the build-injected default — while retaining the fork's single-feed facts: the preload marks channel selection unavailable, Settings shows no selector, and stored values apply only on the next launch.

The `2026-08-25` packaging note keeps the fork's `package-deb.yml` release paragraph, which describes the GitHub Release created from `app-update.yml` without COS uploads. The CUA native Chinese README takes upstream's workflow and source-reuse text and keeps the fork's English-target links for the trimmed packaging guide, so the bilingual pair resolves to one target.

**Nine more upstream paths are trimmed, and the trim list grows from 419 to 428.** Upstream's new website-installer, CI archive, and purge-recovery scripts (`desktop-website-installer.ts`, `publish-website-ci.ts`, `archive-desktop-ci.ts`, `desktop-purge-recovery.ts`) import already-trimmed publication modules and cannot typecheck. Their specs and `desktop-channel-version.spec.ts` are the only readers of those trimmed modules, and `scripts/cua-helper/build-inputs.spec.ts` imports the trimmed `desktop-package-environment.mjs`. The fork runs none of those flows.

**The desktop version equals the engine version, `0.2.2-rc.1`, and needs no build-counter bump.** The fork's release repository has no `v0.2.2-rc.1` yet, so the packaging workflow publishes that version when the merge lands on `main`; equal versions also keep `check-workspace-constraints` green.

## Alternatives considered

**Keep upstream's `selectUpdateChannel`.** Rejected: the fork publishes one feed and prerelease-only releases, so pinning `updater.channel` breaks the GitHub provider's tag resolution instead of selecting another feed.

**Keep the new publication scripts and stub their trimmed imports.** Rejected: they serve the macOS, Windows, COS, and EdgeOne flows the fork does not run; restoring them would pull the trimmed publication pipeline back into the tree.

**Replace the fork's single-feed test with upstream's channel-pinning test.** Rejected: the fork never sets `updater.channel`, so the upstream assertion would fail by design. The version-ordering cases are valuable on their own and were carried over.

**Point the CUA Chinese README at the Chinese packaging guide.** Rejected: the entire packaging directory is trimmed, and the pairing gate requires both languages to resolve to one target; the English target matches the English page.

**Bump the desktop version to a `.N` counter.** Rejected: no release exists for `0.2.2-rc.1`, and sync merges keep the desktop version equal to the engine version.

## Consequences

The next sync starts from upstream `master` beyond tag `dsh-v0.2.2-rc.1`. The merge's push to `main` triggers the packaging workflow, which publishes `v0.2.2-rc.1` to the fork's release repository without a version bump.

The trim list records 428 paths. Two verification failures are inherited rather than introduced: `pnpm run hygiene` fails only `rescope-vendor:check` because upstream documentation still carries pre-rescope name tokens, and repository-wide unit runs still read trimmed workflows.
