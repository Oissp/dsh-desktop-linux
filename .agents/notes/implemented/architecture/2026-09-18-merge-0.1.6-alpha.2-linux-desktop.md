# Agent Note: 0.1.6-alpha.2 merge — Linux desktop trade-offs

Status: implemented

English | [中文](2026-09-18-merge-0.1.6-alpha.2-linux-desktop.zh.md)

## Problem

Upstream 0.1.6-alpha.2 rearchitected the desktop around "Electron is the
runtime" and treats darwin/win32 as the first-class packaging targets. This
fork (linux-only deb + AppImage, GitHub Releases updater) absorbs the
upstream rewrite, but three conflicts cannot be resolved by taking either
side wholesale: which upstream packaging surfaces survive the trim list,
which update channel the GitHub provider can actually read, and whether the
packaged Linux shell keeps a top application menu. Without a recorded
baseline, every future upstream sync re-litigates them.

## Decision

The merge adopts the upstream runtime model wholesale and records three
platform-specific resolutions as the standing baseline for future syncs:

1. **Trim list extension** (`.github/sync-trimmed-paths.txt`, ~60 new
   entries): mac/win packaging and signing scripts, the installed-update
   pipeline, the COS upload transport, and primary-runtime preparation code
   with its tests and fixtures. One exception: `primary-runtime-lock.json`
   stays — it is pure data consumed directly by
   `scripts/gen-third-party-notices.ts` and its spec; forking that
   repository-level generator would create a permanent sync conflict, and
   disclosing distributions the fork does not bundle is the harmless
   direction of error.
2. **Update channel `latest`**: `update-coordinator.ts` changes upstream's
   `updater.channel = 'nightly'` back to `'latest'`. The fork's update
   source is the dedicated release repository
   `Oissp/dsh-desktop-linux-release` (GitHub Releases); electron-builder's
   default channel publishes `latest-linux.yml`, while `nightly` requests a
   `nightly-linux.yml` that never exists under the GitHub provider.
3. **Packaged Linux hides the application menu**: `main.ts` calls
   `Menu.setApplicationMenu(null)` when
   `app.isPackaged && process.platform === 'linux'`; the tray mirrors the
   entries (show window / check for updates / quit). The menu-structure
   assertions in `main-startup.spec.ts` run unpacked, and a dedicated case
   pins the packaged behavior.

## Deferred

The primary-runtime python/pnpm payload has no linux-x64 target: upstream's
`primary-runtime-lock.json` records only darwin/win32 digests and
`desktop-host`'s `readPrimaryRuntime` platform whitelist is
`['win32', 'darwin']`. The fork ships no payload and Host startup is
unaffected, but the `load_workspace_dependencies` tool installs lazily and
fails on invocation. Porting the payload is separate work and does not
block this merge.

## Alternatives considered

**Fork `gen-third-party-notices.ts` into a Linux variant.** Rejected: it
splits a repository-level gate script that every upstream sync touches,
guaranteeing merge conflicts each release; keeping the lock data only
over-discloses.

**Keep the fork's standalone Node runtime packaging.** Rejected: upstream
rewrote the host process, office integration, and workspace dependencies
onto Electron-runtime semantics; maintaining both models costs more than
adopting the rewrite plus the fork's retained
`native-electron-fingerprint.ts` patching, which stays required for
Electron 44.2+ where the builtin profile table matches exactly.

**Keep upstream's `nightly` channel and publish `nightly-linux.yml`.**
Rejected: the channel name must then flow through electron-builder config,
release uploads, and the updater for no user-visible benefit over
`latest`, which the GitHub provider resolves out of the box.

## Consequences

Future syncs resolve conflicts inside the extended trim list automatically
(keep-trim) and treat channel `latest`, the packaged-null menu, and the
lock-file exception as settled fork decisions rather than open questions.
The cost: the fork carries a small patch on `update-coordinator.ts` and
`main.ts` that must be re-applied if upstream refactors those files, and
the `load_workspace_dependencies` tool stays degraded on Linux until the
payload port lands.

## Testing

`pnpm exec vitest run apps/desktop/tests apps/desktop-host/tests` covers
both the coordinator channel assertion (`'latest'`) and the packaged-menu
pin; `pnpm run typecheck` compiles the merged tree. The packaging gate
(`package-deb.yml`) runs the desktop suite before building.
