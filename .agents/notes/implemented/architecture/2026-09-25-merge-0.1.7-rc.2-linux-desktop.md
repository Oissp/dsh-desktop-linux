# Agent Note: 0.1.7-rc.2 merge — the Linux desktop surfaces

Status: implemented

English | [中文](2026-09-25-merge-0.1.7-rc.2-linux-desktop.zh.md)

## Problem

Upstream 0.1.7-rc.2 replaced the desktop overlay API and made closing the main window hide it instead of quitting. `update-overlay.ts` gained `DesktopUpdateOverlays.input(parent)`, which returns `{ revision, blocked }` per parent, and its `create()` grew `nativeModal` and `platform` parameters; `update-dialog.ts` gained a `resize` IPC channel and the `overlays` seam; `mandatory-update-window.ts` gained `overlays` and a per-use `locale` reader and now publishes `surface` in its view. Closing the window hides it on every platform, with a Windows `DesktopTray` and a `DesktopQuitConfirmation` that asks the Host through `inspectQuit` before quitting. The fork carries only the Linux packaging surfaces and already ships its own tray, so the auto-merge produced a tree that kept both trays, both surface selections, and upstream's mac/win packaging scripts and dependencies in `apps/desktop/package.json`.

Upstream also added `apps/desktop/scripts/flock-entry.ts` and `apps/desktop/tests/flock-entry.spec.ts`. Only the trimmed `macos-notarization-proxy.ts` imports the entry module, so the merged spec's fixture copied a file the fork does not carry and failed with `ENOENT`.

The pairing record format changed from whole-file blob hashes to per-heading-section hashes, and upstream deleted `scripts/merge-translation-pairing.ts`, `scripts/translation-pairing-merge.ts`, and the `resolve-translation-pairing-conflicts` script. Every fork-owned `*.i18n.yaml` therefore failed `verify-translation-pairing` with `malformed consistency record`.

Upstream bumped `@deepseek-ai/libreoffice-kit` to 0.1.1 while the fork's `patchedDependencies` entry and patch file still named 0.1.0, so `pnpm install` failed with `ERR_PNPM_UNUSED_PATCH`.

## Decision

**The Linux tray stays the fork's own.** `DesktopTray` is constructed only for Windows, as upstream wrote it. The fork keeps `linuxTray`, created when `app.isPackaged && process.platform === 'linux'`, with its `showWindow` / `checkUpdatesMenu` / `quit` menu, and `refreshApplicationMenu()` still installs `Menu.setApplicationMenu(null)` on that build so the tray is the only entry point. The window's Linux icon follows the resolved appearance through the same controller that updates the tray image.

**The surfaces move inside the new overlay API.** `desktopDialogSurface(platform)` and `mandatoryUpdateSurface(platform)` stay fork-owned. `create()` now takes upstream's `nativeModal` and `platform` parameters and keeps the fork's macOS input interception; `createPrompt` and `createMandatory` select between the fork's `createDialogCard` / `createFramedModal` and the transparent sheet; `fitDialogCard` is unchanged and still resizes the opaque card to the height its document reports. Upstream's destroyed-parent guard is kept in the `closed` handler, because the macOS input listeners outlive a parent that Electron has already torn down.

**`flock-entry` is trimmed.** `apps/desktop/scripts/flock-entry.ts` and `apps/desktop/tests/flock-entry.spec.ts` join [sync-trimmed-paths.txt](../../../../.github/sync-trimmed-paths.txt), because their only importer is the trimmed macOS notarization proxy.

**The LibreOffice Kit patch is regenerated for 0.1.1.** The defect it repairs — `installedPackageExists` reading `lstatSync(path, { throwIfNoEntry: false }) !== undefined`, which treats an unreadable directory as installed — is unchanged in 0.1.1, so the patch is regenerated against that version and `THIRD_PARTY_NOTICES.md` with it.

**Pairing records are re-recorded, and the trimmed link keeps the authored path.** `apps/desktop/README.zh.md` now links `tests/README.md#verification-overlay`, matching its English side. `translationStructureDiff` compares link targets literally, and it can only normalize a `.zh.md` target when the target is a registered pair source — the trimmed `apps/desktop/tests/README.md` is not, so the upstream `.zh.md` form diverges from the English form and the pair fails. The deleted merge driver is what used to require the `.zh.md` form; nothing does now.

## Alternatives considered

**Keep upstream's `DesktopTray` on Linux.** Rejected: the fork's tray carries the Linux-only appearance-following icon and the packaged-build menu mirroring, and two trays would race for the same icon and menu.

**Let the merged `flock-entry.spec.ts` run against a fork-owned proxy.** Rejected: it would keep a spec whose only subject is a file the fork does not ship, and the fork would then own the macOS proxy path it deliberately trimmed.

**Pin `@deepseek-ai/libreoffice-kit` back to 0.1.0 to keep the existing patch.** Rejected: the merge moves the engine and every consumer to 0.1.1, and the repair is a one-line behavior fix that regenerates mechanically.

**Leave `tests/README.zh.md#verification-overlay` and add a pairing exception.** Rejected: an exception file would have to name every trimmed target in every paired document, and the authored path is already the fork's recorded form ([fork-trimmed links are declared, not rewritten](../process/2026-09-20-fork-trimmed-link-gate.md)).

## Consequences

The fork re-applies its tray, its two surface selectors, and its packaged-Linux menu hiding on every upstream change to `main.ts`, `tray.ts`, `quit-confirmation.ts`, or `update-overlay.ts`; the trim list tracks deleted files only, so those modified behaviors live in this note and in the fork's tests.

Upstream's close-to-background behavior now reaches Linux unchanged, which is why the Linux tray exists at all: without it, closing the window on a packaged Linux build would leave no way back.

The pairing record is now section-scoped, so a fork-side edit to one section of a paired document needs a re-record of that pair rather than of the whole file. Any future upstream edit to a paired document whose fork side links a trimmed target lands as a structural divergence and needs the authored-path alignment, not a re-record alone.

## Testing

`pnpm run typecheck` compiles the merged tree; `pnpm run lint` and `pnpm run test:docs` are clean, with the documentation gates reporting 20 passed and 0 failed. `pnpm exec vitest run apps/desktop` passes 745 tests across 69 files, including the merged `update-overlay.spec.ts`, `update-dialog.spec.ts`, `mandatory-update-window.spec.ts`, `mandatory-update-policy.spec.ts`, and `main-startup.spec.ts`. `pnpm install --frozen-lockfile` accepts the regenerated patch and lockfile.
