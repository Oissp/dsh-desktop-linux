# Agent Note: 0.2.2-rc.4 上游同步 —— fork 跟随账号包拆分并再裁剪一个 CI workflow

Status: implemented

[English](2026-11-18-merge-0.2.2-rc.4-linux-desktop.md) | 中文

## Problem

上游 `master` 相对 `dsh-v0.2.2-rc.3` 分叉的父提交推进了 807 个提交，并发布了 `0.2.2-rc.4`。增量改动 3104 个文件——新增 590、删除 95、修改 2374、重命名 45——共 88070 行新增、31776 行删除。它把 `packages/credentials/deepseek-account` 搬到 `packages/account/deepseek-account`，新增 `packages/account/deepseek-auth`、`packages/mcp/mcp-account`、`packages/connector/cli-account`、`packages/connector/upstream-skills`、`packages/client/config`、`packages/experimental/forge-gitlab` 与 `packages/session-query/tool-session-list`，把会话持久化切换为 SQLite 并在打开时导入旧 JSONL（`packages/session/session-persistence-sqlite`），把 `create_worktree` 并入 `enter_worktree`，并新增 `.github/workflows/stale-pull-requests.yml` workflow 及其 `.github/stale-pull-requests` 支撑脚本。

本次合并产生 5 个冲突：两个落在裁剪清单内路径的 modify/delete 冲突（`.github/workflows/pr-check-on-head-branch.yml`、`apps/desktop-publisher/package.json`），以及三个内容冲突（`apps/desktop/package.json`、`packages/experimental/webworker-runtime/tsdown.config.ts`、`pnpm-lock.yaml`）。与 `0.2.2-rc.3` 合并不同，上游没有改动 `main.ts`、打包脚本这类 fork 修改过的桌面壳源码；真正发生冲突的两条基线条目是 `apps/desktop/package.json` 与 webworker-runtime 的 tsdown 配置，解决方案见下。

## Decision

**裁剪路径保持删除，裁剪清单增收一个上游新增 workflow。**

两个 modify/delete 冲突按 fork 侧删除解决。上游整目录带回了 `apps/desktop-publisher/` 且不产生冲突；合并提交前再次删除该目录，使 fork 的 workspace 不包含发布工具的 COS、EdgeOne 与签名依赖。`.github/workflows/stale-pull-requests.yml` 与其他上游 CI workflow 一样进入裁剪清单，因为 fork 只运行 `package-deb.yml` 与 `package-deb-test.yml`；其 `.github/stale-pull-requests/` 支撑脚本保留，与同样保留的 `.github/review-ownership/` 和 `.github/issue-management/` 树一致。清单记录 405 条路径，`scripts/verify-sync-trimmed-paths.sh --stale upstream/master` 确认每条仍存在于上游树中。

`apps/desktop/package.json` 取上游的 `0.2.2-rc.4` 版本，保留 fork 的 `productName`、作者、主页、Linux 专用脚本，以及其移除的 macOS/Windows 打包脚本与 publisher 开发依赖。

`packages/experimental/webworker-runtime/tsdown.config.ts` 保留 fork 的选项命名（`deps.alwaysBundle` 与 `outputOptions.codeSplitting: false`），并采纳上游新增的 `bufferPackagePlugin`，它让命名 `buffer` 内建模块的 bundled CommonJS 解析到 npm 包。fork 在此前的同步中已把全部三个 tsdown 配置改成该命名；合并后的文件保持这一约定并加上上游插件。

`pnpm-lock.yaml` 采用上游的 `packages/account/deepseek-account` 链接路径并去掉 `apps/desktop-publisher` importer，冻结安装确认一致。

`packages/document/office-kit/README.i18n.yaml` 的双语配对记录在合并改动英文页后重新录制。桌面版本等于引擎版本 `0.2.2-rc.4`，无构建计数后缀，因为本次合并没有改动 fork 自有的壳行为。

## Alternatives considered

**采用上游的 tsdown 选项拼写（`noExternal`、`inlineDynamicImports`）。** 拒绝：fork 的另外两个 tsdown 配置（`browser-use-stagehand-native`、`inspector`）使用 `deps.alwaysBundle` 与 `codeSplitting: false`，构建依赖该命名；只在一个文件采用上游拼写会让同一选项在树中出现两种写法。

**保留 `.github/workflows/stale-pull-requests.yml`，让 fork 也能关闭自己的陈旧 PR。** 拒绝：fork 手工合并上游发布，不运行上游的 issue 与 PR 自动化，裁剪清单已移除这些 workflow。

**把桌面版本升到 `0.2.2-rc.4.1`。** 拒绝：本次合并没有改动 fork 自有的壳行为，fork 的发版历史把构建计数递增与同步合并分开。

**逐条列出 publisher workspace 的文件，而不是依赖目录条目。** 拒绝：上游现在以与上次同步退役的 53 条条目不同的布局携带 publisher workspace，一条目录条目不会与上游的文件列表脱节。

## Consequences

下一次同步从上游 `master` 中 `dsh-v0.2.2-rc.4` 之后开始。账号 provider 位于 `packages/account/deepseek-account`；fork 本地任何对 `packages/credentials/deepseek-account` 的引用都必须随之迁移。裁剪清单记录 405 条路径，fork 基线在新 merge base 上仍与 fork 修改的文件匹配且无需新增条目：新的 `client-config-sync` e2e 通过 `scripts/rescope-vendor.ts` 为其 `'schemastery'` 路径段添加的 skip 条目保持上游所有权。
