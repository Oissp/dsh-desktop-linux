# Agent Note: 0.2.3-alpha.2 upstream sync — the fork raises its Node.js and Electron floors while the vendor set moves to the 4.2 alpha line

Status: implemented

English | [中文](2026-11-22-merge-0.2.3-alpha.2-linux-desktop.zh.md)

## Problem

Upstream `master` advanced five commits past the merge base left by `0.2.3-alpha.1` and cut `0.2.3-alpha.2`. The delta changes 488 files — 3 added and 485 modified — with 806 insertions and 707 deletions, most of them version fields in workspace manifests. It raises `engines.node` to `^24.22.3 || >=26.13.1` because those are the first releases whose bundled undici carries the November 2026 security fixes, moves the primary runtime to Node 24.22.3, bumps Electron to 44.11.5 with `node-addon-require-builtin` 0.1.10, adds undici major-version overrides, releases the vendor packages at cordis 4.2.0-alpha.1, cosmokit 1.10.0-alpha.1, group/hmr/include/loader/logger-console 1.2.0-alpha.1, schemastery 3.20.0-alpha.1 and timer 1.3.0-alpha.1, and adds the `node-24-22-3` upgrade guide.

The merge produced 30 conflicts. Twenty-nine are modify/delete on trimmed paths: twenty-seven `.github/workflows` files, `apps/desktop-publisher/package.json`, and `apps/desktop/tests/updates/electron-updater/verified-versions.json`. The single content conflict was `apps/desktop/package.json`.

## Decision

**Trimmed paths stay deleted, and `apps/desktop/package.json` takes the new version and Electron range while keeping the fork's Linux-only publisher surface.**

The twenty-nine modify/delete conflicts resolve to the fork's deletion. The workflow edits are upstream's Node floor pin in each job; the fork does not carry those workflows, and its own `package-deb.yml` and `package-deb-test.yml` already request `node-version: 24`, which installs a 24.x release at or above the new floor. Their `engines` comments are updated to state `^24.22.3 || >=26.13.1`.

`apps/desktop/package.json` keeps the fork's `productName`, author, homepage, Linux-only scripts, and its removal of the macOS/Windows packaging scripts, the publisher devDependency, and `cos-nodejs-sdk-v5`, which only the trimmed COS notarization and publisher tooling consume. It takes upstream's `0.2.3-alpha.2` version and `electron` `^44.11.5` range. The lockfile is regenerated by `pnpm install`, which resolves the new Electron, the 0.1.10 addon set, and the undici overrides.

The desktop version equals the engine version, `0.2.3-alpha.2`, with no build counter, because the merge changes no fork-authored shell behavior.

## Alternatives considered

**Pin the fork workflows to `node-version: 24.22.3`.** Rejected: `node-version: 24` already resolves to the latest 24.x release, which satisfies the new `^24.22.3` floor, and an exact pin would need maintenance for every floor raise.

**Keep `cos-nodejs-sdk-v5` as the upstream devDependency.** Rejected: the package's only consumers are the trimmed COS notarization and publisher paths, so keeping it would add an install-time dependency the fork never imports.

**Hand-edit `pnpm-lock.yaml` after resolving `apps/desktop/package.json`.** Rejected: Electron, the addon set, undici overrides, and the vendor releases all change resolutions; `pnpm install` regenerates them from the merged manifests and verifies the supply-chain policy in one step.

## Consequences

The next sync starts from upstream `master` beyond tag `dsh-v0.2.3-alpha.2`. Upstream's per-job Node pins will keep producing modify/delete conflicts for the trimmed workflows; they resolve to deletion without inspection unless a workflow gains behavior the fork's own workflows should adopt. The Node floor now matches the bundled runtime, so source checkouts and packaged applications agree on 24.22.3.

## Testing

`scripts/verify-sync-trimmed-paths.sh --stale upstream/master` confirms all 419 trimmed paths are absent and still exist upstream. `node scripts/verify-sync-forked-paths.ts --base upstream/master` reports the baseline matches the fork-modified files at the new merge base. `scripts/verify-sync-pairing-after-merge.sh` finds no pairing changes. `pnpm install` reports the lockfile up to date and passes the supply-chain policy check. `pnpm run typecheck` passes five gates. `pnpm run lint` passes with `DSH_OXLINT_THREADS=1` and `NODE_OPTIONS=--max-old-space-size=4096`, because the type-aware tsgolint backend exhausts this machine's memory at higher parallelism. `pnpm run test:docs` passes 21 gates. `pnpm exec vitest run apps/desktop/tests` passes 92 files and 1204 tests with two files and five tests skipped. `pnpm run hygiene` passes all 27 gates under `NODE_OPTIONS=--max-old-space-size=6144`. `pnpm run build` passes `build:artifacts` and `build:check`.
