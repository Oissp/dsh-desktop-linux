# Agent Note: 0.2.1-alpha.3 merge — desktop publication pipeline trimmed, update channels and CUA arrive

Status: implemented

English | [中文](2026-10-15-merge-0.2.1-alpha.3-linux-desktop.zh.md)

## Problem

Upstream `master` advanced 868 commits past the previous sync and released engine `0.2.1-alpha.3`; the merge target is upstream head 16 commits past that tag. The delta changes 3325 files and spans five areas: the Desktop publication pipeline (approved COS upload workflow, retained-package publication, publication approval summary, macOS packaging runner service with optional notarization, and an `app-builder-lib` patch), update-channel separation (nightly and latest channels, release confirmation before approval), CUA (new `packages/experimental/cua` and `packages/experimental/cua-macos`, screenshot pixel mapping, hover preservation), remote-access RBAC (new `packages/api/remote-access`, caller principals on explicit peers, remote method and event resources), and client work (new `ui-secret-mask` and `harness-dev-context` packages, plugin feature previews, web font-size shortcuts, HMR plugin replacement on profile recomposition).

The merge produced 63 conflicts. Forty-five modify/delete pairs hit trimmed workflow and Desktop script paths. Eighteen content conflicts hit forked-path files (`package-target.ts`, `prepare-dsh.ts`, `electron-builder.config.d.mts`), the Desktop manifests, three `tsdown` configs, `main.ts`, `update-coordinator.ts`, `desktop-build-paths.mjs`, `pnpm-workspace.yaml`, `pnpm-lock.yaml`, `THIRD_PARTY_NOTICES.md`, and bilingual pairing records.

Roughly 100 new upstream files arrived inside the trimmed Desktop publication and macOS/Windows packaging scope: two workflows, 28 publication and platform-CI scripts, 22 tests, packaging/signing configuration, and platform READMEs. Two auto-merged upstream tests asserted behavior the fork does not implement. Upstream also refactored the documentation link gate, removing `anchorCache` from `scripts/verify-md-links.ts` in favor of a per-run `markdownLinkCache()`.

## Decision

**All modify/delete conflicts keep the fork's deletion.** The 45 trimmed paths were removed with `git rm` to preserve the fork's Linux-only posture.

**Forked-path source files keep the fork's version.** Upstream's deltas in `package-target.ts`, `prepare-dsh.ts`, and `electron-builder.config.d.mts` are macOS notarization, Windows signing, and publication routing. The fork's `prepare-dsh.ts` retains its own inline `applyRuntimePatches`; its `prepare-runtime.ts` imports `../../../scripts/primary-runtime/prepare.ts`, not upstream's `prepare-primary-runtime.ts`.

**`apps/desktop/package.json` keeps fork metadata and takes upstream versions.** `author` and `homepage` stay on the fork repository. The version moves to `0.2.1-alpha.3` (equal to the engine version). The fork keeps `tar` (runtime tree packaging) and omits `koffi`, `cos-nodejs-sdk-v5`, and `@electron/notarize` (mac/win-only). `sharp` takes upstream's pinned `0.35.5`.

**`apps/desktop-host/package.json` takes upstream's new `devDependencies`** (`@deepseek-ai/cordis-plugin-loader`, `@deepseek-ai/cordis-plugin-include`, `@deepseek-ai/dsh-skill`) and omits `koffi`.

**The three `tsdown` configs merge both sides.** The root config keeps the fork's Desktop-bundling comment with upstream's `[...packages, 'apps/cli', ...]` spread. `benchmarks/tsdown.config.ts` keeps the fork's `client-bundle-composition.worker` entry and adds upstream's `user-text.worker` entry. `ptc-runtime-node/tsdown.config.ts` keeps the fork's `deps.alwaysBundle` API form and adds upstream's `persistent-process` entry.

**`main.ts` keeps the fork's Linux tray and takes upstream's earlier manifest read.** The duplicate `const manifest` from the fork's block is dropped because upstream moved that read above the policy block. The merged `DesktopUpdateCoordinator` call passes the auto-merged `updateChannel` argument, which the merged constructor accepts as an unused channel parameter.

**`update-coordinator.ts` keeps the fork's constructor body and does not set `updater.channel`.** Upstream's `channel` parameter and `this.channel === 'latest'` guard merge cleanly and stay; only `this.updater.channel = channel` is dropped. The fork's release tags are `v<desktop version>`, and pinning `updater.channel` makes the GitHub provider resolve no tag at all.

**`desktop-build-paths.mjs` keeps the fork's `linux-x64` target type and takes upstream's `unnotarizedArtifacts` field** in the JSDoc return type.

**`pnpm-workspace.yaml` and `THIRD_PARTY_NOTICES.md` keep the fork's `libreoffice-kit@0.1.5` entry and take upstream's `pi-ai@1.1.0` entry.**

**The publication pipeline and platform packaging scope are trimmed, adding 70 entries (276 → 346).** This covers the publication and rollback scripts, the macOS/Windows runner and signing scripts, the mac/win packaging configuration, the platform READMEs, and the tests that import the trimmed modules.

**The SSH helper workflows are trimmed, adding 2 entries (346 → 348).** `build-exe-for-ssh-helper.yml` compiles a standalone SSH helper executable with `pkg` (four native Node 24 targets) and `publish-ssh-helper.yml` publishes the verified archives to a GitHub Release. The helper is an optional remote-execution artifact; the fork's `prepare-dsh.ts` and `prepare-runtime.ts` do not reference it, `apps/desktop/package.json` does not depend on `@deepseek-ai/dsh-ssh`, and `package-deb.yml` does not call either workflow. The two never ran on the fork. Desktop users who need SSH execution obtain the helper from the upstream Release.

**Two auto-merged upstream tests revert to the fork's version.** `update-coordinator.spec.ts` gains an upstream test asserting `updater.channel` is `'nightly'`/`'latest'`, which contradicts the fork's no-channel decision and its own `expect(f.updater.channel).toBeUndefined()` assertion. `package-target.spec.ts` gains an upstream test that packages the `mac-arm64` target and passes `--skip-notarization`, both of which the fork's target parser rejects.

**The Desktop README keeps the fork's version.** Upstream split the monolithic `apps/desktop/README.md` into topic READMEs under `apps/desktop/packaging/`, `apps/desktop/publishing/`, and `apps/desktop/windows-signing/`, all of which this fork trims. The fork's README carries its own Linux shell-prompt text and omits upstream's Terminal command registration section, which describes macOS and Windows path changes.

**Carried pairs that upstream pointed at the split READMEs link to the fork's monolithic `apps/desktop/README.md` instead.** The two carried Desktop notes keep upstream's prose and retarget their `apps/desktop/packaging/README.md` and `apps/desktop/publishing/README.md` links to the surviving README, matching the targets the fork used before this sync.

**`scripts/verify-md-links-trimmed.ts` moves to the new link-gate API.** Upstream's refactor replaced `anchorCache()` with a per-run `markdownLinkCache()` passed to `findViolations`; the fork's trim-aware wrapper tracks that signature so the gate keeps running. Keeping the old call left the wrapper importing a removed export, which the type checker and the `no-unsafe-*` lint rules both reject.

## Alternatives considered

**Adopt the upstream publication pipeline.** Rejected: it uploads to COS and publishes retained multi-platform builds, while the fork's `package-deb.yml` creates the GitHub Release directly from the deb and AppImage artifacts with `gh release`. The publication scripts also import the already-trimmed `desktop-upload-plan.ts` and `desktop-cos.ts`, so they are orphaned code on this fork.

**Set `updater.channel` and keep upstream's channel test.** Rejected: the fork's prerelease tags carry the desktop version, and `updater.channel` takes precedence over the version's prerelease segment in the GitHub provider. Pinning it to `latest` makes both `shouldFetchVersion` and `isNextPreRelease` false, so no tag resolves and the update check throws `ERR_UPDATER_NO_PUBLISHED_VERSIONS`.

**Keep the auto-merged macOS notarization test and skip it on Linux.** Rejected: the test calls `parseDesktopPackageInvocation` with `mac-arm64` and `--skip-notarization`, and the fork's parser has neither the target nor the flag. A skipped test would leave the parser's rejection path uncovered while implying coverage.

**Trim `packages/experimental/cua-macos`.** Rejected: the trim list has never carried `packages/` entries, and the package is inert on Linux — the Desktop shell and the default profiles do not reference it. Keeping it leaves the package graph identical to upstream and keeps future syncs free of an extra divergence.

**Keep the SSH helper workflows.** Rejected: `build-exe-for-ssh-helper.yml` and `publish-ssh-helper.yml` compile and publish a standalone SSH helper executable that is unrelated to the deb/AppImage desktop package. The fork's runtime preparation does not reference it, `package-deb.yml` does not call them, and they never ran on the fork. Keeping them would publish an identical binary that upstream already ships from its own Release.

## Consequences

The next sync starts from upstream head 16 commits past the `dsh-v0.2.1-alpha.3` tag. The trim list grows by 72 entries to 348 paths.

The fork's `update-coordinator.ts` now carries an unused `channel` constructor parameter. It exists only because upstream's declaration and the mandatory-update policy identity share it; removing it would reopen a conflict on every sync while `this.updater.channel` stays unset.

All nine patched dependencies resolve to the versions upstream resolves. Eight patch files are byte-identical to upstream's; the fork-only `@deepseek-ai/libreoffice-kit@0.1.5` patch stays because it follows the kit body that upstream's engine selection does not patch.

`scripts/verify-md-links-trimmed.ts` is the fork's only consumer of the upstream link gate's internals. A later refactor of `scripts/verify-md-links.ts` fails this wrapper at import time, so each sync that changes that module needs the wrapper's call sites rechecked.

The fork keeps two workflows: its own `package-deb.yml` and `package-deb-test.yml`. The upstream `build-exe-for-ssh-helper.yml` and `publish-ssh-helper.yml` are declared in the trim list because the standalone SSH helper executable they produce is an optional remote-execution artifact unrelated to the desktop package. All 23 upstream-only CI workflows are also declared in the trim list.
