# Agent Note: 0.2.1-alpha.2 merge — desktop packaging refactor, plan-mode and UI-chat fixes arrive

Status: implemented

English | [中文](2026-10-10-merge-0.2.1-alpha.2-linux-desktop.zh.md)

## Problem

Upstream `master` advanced 669 commits past the previous sync and released engine `0.2.1-alpha.2`. The delta spans four areas: desktop packaging infrastructure (Electron 44.7.0, electron-builder 26.17.0, Windows manual packaging CI, runtime patch module refactor), plan-mode behavior fixes (exit only on approval, end turn on dismissal), ui-chat layout fixes (fold following, flow layout, subpixel rounding), and web feature additions (Auto review shield-A permission icon, experimental catalog page, plugin settings reorganization).

The merge produced 44 conflicts across three categories. Sixteen modify/delete pairs hit trimmed workflow and desktop script paths. Fourteen content conflicts hit forked-path files (`package-target.ts`, `prepare-dsh.ts`, `prepare-runtime.ts`, `package-target.spec.ts`, `apps/desktop/package.json`). The remainder hit version-bump files, `pnpm-workspace.yaml`, `pnpm-lock.yaml`, `THIRD_PARTY_NOTICES.md`, and bilingual pairing records.

Five new upstream files arrived without conflict but required trimming: the Windows manual packaging workflow and its preparation/test infrastructure, and the upstream runtime-patch module plus its test. Two new upstream test files tested mac/win targets and upstream-specific runtime code paths the fork does not use.

## Decision

**All modify/delete conflicts keep the fork's deletion.** The 16 trimmed paths (16 `.github/workflows/*.yml` files and 12 desktop scripts/tests) were removed with `git rm` to preserve the fork's Linux-only posture.

**All forked-path source files keep the fork's version.** Upstream's changes to `package-target.ts`, `prepare-dsh.ts`, `prepare-runtime.ts`, and `package-target.spec.ts` are exclusively macOS/Windows signing, notarization, and packaging-run refactors. The fork's `prepare-dsh.ts` has its own inline `applyRuntimePatches` function; the fork's `prepare-runtime.ts` is Linux-only and imports from `../../../scripts/primary-runtime/prepare.ts` rather than upstream's `prepare-primary-runtime.ts`. No upstream delta in these files affects the Linux path.

**`apps/desktop/package.json` keeps fork metadata and takes upstream versions.** `author` and `homepage` stay pointed at the fork repository. The version moves to `0.2.1-alpha.2` (equal to the engine version — no shell source changed). Dependency versions follow upstream: Electron `^44.7.0`, electron-builder `26.17.0`, `pnpm` `11.28.5`, `sharp` `^0.35.5`, `js-yaml` `^4.3.2`, `vite` `^6.4.3`, `@types/node` `^22.20.1`. The fork keeps `tar` (used by runtime tree packaging) and omits `koffi`, `cos-nodejs-sdk-v5`, and `@electron/notarize` (mac/win-only).

**`pnpm-workspace.yaml` keeps the fork's `libreoffice-kit` patch and takes upstream's `pi-ai@1.0.2`.** The fork's `@deepseek-ai/libreoffice-kit@0.1.5` patch is fork-specific; upstream upgraded `@earendil-works/pi-ai` from 0.87.1 to 1.0.2, which the fork carries.

**`THIRD_PARTY_NOTICES.md` keeps the fork's `libreoffice-kit` entry and takes upstream's `pi-ai@1.0.2` entry.**

**Five new Windows packaging files are trimmed and added to the trim list.** `windows-package.yml` (manual Windows packaging workflow using a dedicated self-hosted Windows runner), `prepare-windows-ci.mjs`/`.d.mts` (reads `.env.windows`, calls the trimmed `desktop-package-environment.mjs`), `prepare-windows-ci.spec.ts`, and `scripts/windows-package-workflow.spec.ts` (reads `windows-package.yml` and asserts `win-x64` target paths) are all Windows-specific infrastructure the fork cannot use.

**The upstream runtime-patch module and its test are trimmed.** `prepare-runtime-patches.ts` and `runtime-patch-policy.ts` refactor runtime patch classification into runtime vs workspace-only groups. The fork's `prepare-dsh.ts` has its own `applyRuntimePatches` function and does not import these modules — they are orphaned code. `prepare-runtime-patches.spec.ts` and `runtime-preparation.spec.ts` test mac-arm64/mac-x64/win-x64 targets and upstream-specific code paths (mocking `prepare-primary-runtime.ts` and `prepare-command-link.ts`, both trimmed); the fork's implementations differ structurally and the tests cannot pass.

**The desktop version equals the engine version.** This sync changes no shell source, so `apps/desktop/package.json` moves to `0.2.1-alpha.2` without a `.N` build suffix.

**Bilingual pairing hashes are regenerated.** `docs/development.md`/`.zh.md` keep the fork's CI-gates text (describing `package-deb.yml`); `apps/desktop/README.i18n.yaml` and `docs/development.i18n.yaml` keep fork-side hashes, and `scripts/verify-sync-pairing-after-merge.sh` re-records `apps/desktop/README.i18n.yaml`.

## Alternatives considered

**Adopt the upstream runtime-patch module.** Rejected: the fork's inline `applyRuntimePatches` in `prepare-dsh.ts` works correctly and has no coupling to upstream's packaging-run step journal. Migrating would require also adopting `packaging-step.mjs` (trimmed) and restructuring `prepare-dsh.ts`'s `main()` around `packagingStep` calls that the fork does not use.

**Keep the upstream test files and mock the fork's code paths.** Rejected: `runtime-preparation.spec.ts` mocks `prepare-primary-runtime.ts` and `prepare-command-link.ts` — both trimmed. Rewriting the tests to target the fork's `prepare-runtime.ts` would duplicate the fork's own `smoke-runtime.ts` coverage without adding signal.

**Give the desktop the `.1` suffix.** Rejected: no shell source changed in this merge; a bare engine version is what the release-version gate accepts for a pure engine sync.

## Consequences

The next sync starts from the `0.2.1-alpha.2` release (upstream PR #5946). The trim list grows by 9 entries (5 Windows packaging + 4 runtime-patch/test files), bringing the total to 276 trimmed paths.

The fork's `prepare-dsh.ts` retains its own `applyRuntimePatches` function. If a future upstream sync changes the patch application mechanism, the fork's function may need updating independently of upstream's `prepare-runtime-patches.ts`.

`scripts/ci-workflow.spec.ts` continues to fail on this fork by construction (its workflow tests read trimmed `.github/workflows/*.yml` files). Fork CI does not run that spec.
