# Agent Note: 0.2.3-alpha.1 上游同步 —— fork 接纳五个连接器与转正后的推荐栈，同时裁剪新的 Windows 打包工具

Status: implemented

[English](2026-11-22-merge-0.2.3-alpha.1-linux-desktop.md) | 中文

## Problem

上游 `master` 在 `0.2.2-rc.5` 留下的 merge base 之后前进 703 个提交，并切出 `0.2.3-alpha.1`。该增量改动 3163 个文件——新增 740 个、删除 41 个、修改 2234 个、重命名 147 个、类型变更 1 个——共 93977 行新增、17483 行删除。它在 `packages/connector/{dingtalk,feishu,tencent-docs,tencent-meeting,wecom}` 新增五个托管 MCP 连接器，各自带有 `cordis.patch.yml`、locale、快照与升级指南；把行动卡片与推荐栈从 `packages/experimental` 转正到 `packages/{interaction,client,extensions}`，并退场 `packages/experimental/personalized-recommendations`；新增 `packages/session/tool-session-control` 与 `packages/client/remote-connection`；把 Office 技能合并为单一 `office` 入口，格式指导按需加载；新增 CUA 最近窗口活动与系统键盘/鼠标按键持有（macOS 与 Windows）、内联输入框占位插槽、模型目录推理级别、延迟系统压缩与 SDK prompt 时区。它还在 `apps/desktop` 下新增 Windows 打包摘要、卸载注册与 CI runner 进程工具。

合并产生 47 处冲突。其中 41 处位于裁剪路径：四十个逐条列出的文件，加上由整目录条目覆盖的 `apps/desktop-publisher/package.json`。六处内容冲突为 `apps/desktop/package.json`、`apps/desktop/README.md` 与 `.zh.md` 及其 `README.i18n.yaml` 配对记录、`apps/desktop/tests/main-startup.spec.ts`，以及 `docs/development.i18n.yaml`。

## Decision

**裁剪路径保持删除，十二个新的 Windows 打包/CI 文件加入裁剪清单。**

被上游修改的裁剪文件解析为 fork 侧的删除。上游新增的 `apps/desktop/installer/uninstall-report.h`、`apps/desktop/scripts/{uninstall-registration.ps1,windows-packaging-summary.d.mts,windows-packaging-summary.mjs,windows-runner-processes.cs,windows-runner-scheduler.ps1}` 与 `apps/desktop/tests/{windows-installer-process-test.ps1,windows-installer-process.ps1,windows-packaging-summary.spec.ts,windows-runner-boot.ps1,windows-runner-processes.ps1,windows-runner-recovery.ps1}` 只被裁剪的安装器源码、裁剪的 Windows workflow（`windows-package.yml`、`ci-windows.yml`）与裁剪的 `windows-runner-task.ps1` 调用。它们被加入 `.github/sync-trimmed-paths.txt` 的 `0.2.3-alpha.1` 分组；`apps/desktop/tests/fixtures/register-test-protocol.cjs` 保留，因为它是跨平台夹具。`scripts/verify-sync-trimmed-paths.sh --stale upstream/master` 确认清单内 419 条路径均不存在于工作树，且在上游树中均存在。

`apps/desktop/package.json` 采用上游的 `0.2.3-alpha.1` 版本，保留 fork 的 `productName`、author、homepage、Linux-only 脚本，以及移除 macOS/Windows 打包脚本和 publisher devDependency 的改动。合并后的脚本块没有引入对已裁剪 publisher workspace 的新引用，因为上游的打包脚本始终在合并后的脚本块之外。

`apps/desktop/README.md` 与 `.zh.md` 的 Windows 安装器章节保留 fork 的「不随本 Linux 分支发布」段落，并省略上游记录运行 `scripts/test-windows-installer.mjs` 的段落，该脚本已被裁剪。合并后重新录制桌面 `README.i18n.yaml` 配对。

`apps/desktop/tests/main-startup.spec.ts` 采用上游新增的「设置」应用菜单项，并保留 fork 的分歧：应用菜单仍不含「管理 dsh 命令…」项，fork 只在 Linux 托盘显示它。因此其期望在「关于」分隔符之后增加 `messages.settingsMenu`，同时保留 fork 的开发者工具项。导入冲突取双方——上游的 `WELCOME_IPC` 用于新的欢迎页跳过用例，fork 的 `SCHEME` 用于其协议处理器用例。

`docs/development.i18n.yaml` 重新录制，因为上游在两种语言中编辑了 TypeScript 布局段落。

`scripts/rescope-vendor.ts` 把 `apps/web/tests/input-plugin-extensions.e2e.ts` 加入 `schemastery` 的 `GENERIC_SKIPS`。新用例通过把私有的 `node_modules/@deepseek-ai` 作用域目录与单独的 `schemastery` 段拼接来构造已安装包夹具，与 `client-config-sync.e2e.ts` 的文件系统布局相同；改写该段会把裁剪目录多嵌一层。

桌面版本等于引擎版本 `0.2.3-alpha.1`，无构建计数后缀，因为本次合并没有改动 fork 自有的壳行为。上游的「设置」项是引擎改动；托盘现有条目不变。

## Alternatives considered

**把新的「设置」项镜像进打包版 Linux 托盘。** 拒绝：设置已有应用内 UI 入口与注册快捷键，且打包版 Linux 托盘镜像的是它取代的应用菜单入口（显示主窗口、检查更新、管理 dsh 命令、退出）。为一个已可达的便利入口改动 fork 自有的壳行为需要提升构建计数。

**把夹具中的 `schemastery` 段改名为作用域包名，而不是跳过。** 拒绝：该段是私有 `@deepseek-ai` 作用域目录下的目录条目，不是包说明符。改名会得到 `node_modules/@deepseek-ai/@deepseek-ai/schemastery`，解析不到任何东西。

**在桌面 README 中保留上游的 `test-windows-installer.mjs` 用法段落。** 拒绝：该脚本及其 PowerShell 夹具已被裁剪，段落会记录 fork 无法运行的命令。

**新增 Windows CI runner 脚本而不是裁剪它们。** 拒绝：它们只通过已裁剪的 `ci-windows.yml` 在上游的 Windows runner 上运行，C# 进程辅助库由已裁剪的 `windows-runner-task.ps1` 加载。

## Consequences

下一次同步从上游 `master` 的 `dsh-v0.2.3-alpha.1` 标签之后开始。新的裁剪条目跟随上游持续开发的 Windows 打包与 runner 工具，因此后续同步可能对它们报 modify/delete 并解析为删除。推荐栈现在位于 `packages/{interaction,extensions,client}`，fork 本地对已退场的 `packages/experimental` 路径的引用必须随之迁移。`apps/desktop/tests/main-startup.spec.ts` 仍是 fork 修改的文件，其应用菜单期望与上游的差异现在只剩「管理 dsh 命令」项；上游未来新增菜单项时需要同样的比对。fork 基线仍与新 merge base 的 fork 修改文件一致。
