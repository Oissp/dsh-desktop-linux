# Agent Note: 0.2.2-alpha.2 发版后同步 —— fork 采纳上游的文件操作并保留自己的 Linux 菜单

Status: implemented

[English](2026-10-30-merge-0.2.2-alpha.2-linux-desktop.md) | 中文

## Problem

上游 `master` 在上一个同步点 tag `dsh-v0.2.2-alpha.2` 之后推进了 351 个提交；引擎版本仍是 `0.2.2-alpha.2`，因为上一个 tag 之后没有新的发布 tag。增量改动 1461 个文件——新增 365、删除 9、修改 1087——新增三个包（`client/ui-context-menu`、`client/ui-file-actions`、`fs/fs-patch`），以及壳的文件操作、开发者工具菜单分组、侧栏工作区树、计划任务/自动化、forge 与 CUA helper 相关工作。

本次合并产生十九个冲突：十三个落在裁剪清单内的 modify/delete 冲突，以及六个内容冲突（`apps/desktop/README.i18n.yaml`、`apps/desktop/package.json`、`apps/desktop/src/main.ts`、两个应用菜单快照与 `apps/desktop/tests/main-startup.spec.ts`）。fork 没有 `packages/` 分叉，因此上游引擎工作原样进入；取舍落在壳、它的菜单测试与同步清单上。

## Decision

**本次合并采纳上游的文件操作与菜单分组，同时保留 fork 的 Linux 壳。** `apps/desktop/src/main.ts` 加入上游的 `installFileActions` 接线、可见的本地化“开发者工具”命令与其隐藏的 F12 别名（Windows 保留它的一对隐藏快捷键），并保留 fork 在打包 Linux 上的 `Menu.setApplicationMenu(null)` 与 `rebuildTrayMenu`。desktop-cli 的“管理 dsh 命令…”项仍只出现在 Linux 托盘菜单：上游把它加进 darwin 与 win32 的应用菜单，照搬会把 fork 的托盘入口挪进打包壳从不显示的菜单。各语言词典保留 fork 的托盘文案，采纳上游的 `toggleDevToolsMenu`。桌面 README 双语对采纳上游新的开发者工具与文件操作段落；只有它的配对记录需要重录。

**菜单快照与启动测试记录 fork 的菜单，而不是上游的。** 两个 `apps/desktop/tests/expected/application-menu-*.json` 与 `main-startup.spec.ts` 中的菜单断言去掉 desktop-cli 项，加入上游的开发者工具分组。上游新增的开发者工具测试改为断言打包 Linux 的托盘菜单（显示主窗口、检查更新、管理 dsh 命令、退出）及其语言刷新，并 mock `app.getLocale`——因为托盘的 `DesktopLocaleController` 以系统 locale 兜底，而不是 `getPreferredSystemLanguages`。这三个测试路径加入 `.github/sync-forked-paths.txt`（30 → 34 条）。

**本次再裁剪七个上游文件，裁剪清单从 418 条增至 425 条。** 仅 macOS 的 `cua-helper-package.yml` workflow；四个 `apps/desktop/config/publishing/*/*.json.example` 模板及其 `desktop-publish-templates.spec.ts` 读取者（它导入已裁剪的 `desktop-publish-config.ts`）；以及导入已裁剪 macOS 签名、公证脚本的 `scripts/cua-helper/package.ts`，都不进入 fork。其余 `scripts/cua-helper` 模块保留：`scripts/release/publish.ts` 导入 `verify-tarball.ts`，payload、产物选择、暂存与 smoke 模块通过类型检查及其测试。十三个 modify/delete 冲突全部是裁剪清单内的路径，因此清单本身即可解决，不需要判断。

**`apps/desktop/package.json` 保留 fork 的打包面，采纳上游的新依赖。** Linux-only 脚本、fork 的 author 与 homepage、以及不存在的 `tencentcloud-sdk-nodejs-teo` 都保留；壳现在需要的 `@deepseek-ai/dsh-client-ui-file-actions` 加入依赖。锁文件无需重新生成：`pnpm install --frozen-lockfile` 接受合并后的文件。

**桌面版本保持 `0.2.2-alpha.2`，等于引擎版本。** 上游在上一个同步点之后没有发版，而 fork 的打包 workflow 以 `apps/desktop/package.json` 为准；新的构建需要单独的构建计数 bump。本次合并没有改变 fork 自行编写的壳行为，只采纳上游的行为。

**CUA 原生 README 在两种语言里链接同一目标。** 上游让英文页指向 `apps/desktop/packaging/README.md`、中文页指向 `README.zh.md`；fork 裁剪了该指南，配对检查因此无法把两个语言侧折叠成同一语义目标。中文页现在链接英文目标，两种语言都由裁剪清单的链接豁免覆盖，该页加入 `.github/sync-forked-paths.txt`。

## Alternatives considered

**在应用菜单里保留上游的 desktop-cli 项。** 拒绝：fork 在隐藏打包菜单栏时已把该入口移进 Linux 托盘；重复会多出一个打包壳从不显示的命令，并与 `main.ts` 记录的 fork 行为矛盾。

**保留打包 Linux 的应用菜单，让开发者工具命令始终可达。** 拒绝：隐藏菜单栏是已出货的 fork 决定，托盘镜像显示主窗口、检查更新、管理命令与退出；开发者工具仍可通过 F12 与未打包的应用菜单到达。

**恢复 macOS 签名脚本，让 `scripts/cua-helper/package.ts` 通过类型检查。** 拒绝：fork 不携带 macOS 打包管线；为了让一个孤儿入口编译而恢复脚本，会把已裁剪的管线重新带回来。

**裁剪整个 `scripts/cua-helper` 树。** 拒绝：`scripts/release/publish.ts` 导入 tarball 校验器，而 payload、选择、暂存与 smoke 模块及其测试是自包含且通过的。

**保留发布模板及其 spec。** 拒绝：spec 导入已裁剪的 `desktop-publish-config.ts`，无法通过类型检查；模板只服务于已裁剪的发布管线。

**在合并提交里 bump 桌面版本。** 拒绝：引擎版本没有变化，fork 的发布历史把构建计数 bump 与同步合并分开，保持版本相等也让 `check-workspace-constraints` 保持通过。

**重新生成锁文件。** 拒绝：冻结安装接受合并后的文件，重新解析只会移动无关的传递版本。

## Consequences

下一次同步从 tag `dsh-v0.2.2-alpha.2` 之后的上游 `master` 开始。引擎仍是 `0.2.2-alpha.2`，因此要让本次同步出货需要单独执行 `chore(desktop): 版本提升到 0.2.2-alpha.2.N`；只合并会命中已发布的 `v0.2.2-alpha.2` release 并跳过发布。裁剪清单记录 425 条路径，`.github/sync-forked-paths.txt` 记录 34 条 fork 修改路径。

`scripts/rescope-vendor.ts --check` 在这个上游提交上失败：它的后置条件仍在查找 `17. **@deepseek-ai rescope**`，而上游对 `vendor/README.md` 的稳定 ID 改写已把该行改成 `V17 · @deepseek-ai rescope`。上游 `master` 带着同样的不一致，fork 因此继承它；后续运行 `pnpm run rescope-vendor --apply` 的 vendor 同步需要把后置条件更新为稳定 ID 文本。

`scripts/ci-workflow.spec.ts` 与 `scripts/tests/ci-release-selfhosted.spec.ts` 继续读取已裁剪的 workflow（`ci.yml`、`release-publish.yml`、`cua-helper-package.yml`），因此仓库级单测运行在 fork CI 不运行它们的地方继续失败。

`pnpm run hygiene` 23 个门禁中 22 个通过；`rescope-vendor:check` 因上述上游后置条件不一致而失败，`verify-optional-dependency-imports` 在 5120 MiB 堆内通过。
