# Agent Note: 0.2.2-rc.5 upstream sync — the fork keeps its trimmed installer tree while upstream adds two connectors

Status: implemented

English | [中文](2026-11-18-merge-0.2.2-rc.5-linux-desktop.zh.md)

## Problem

Upstream `master` advanced 238 commits past the merge base that `0.2.2-rc.4` left behind and cut `0.2.2-rc.5`. The delta changes 960 files — 124 added, 4 deleted, 831 modified, 1 renamed — with 22274 insertions and 2710 deletions. It adds `packages/connector/linear` and `packages/connector/notion` (Linear and Notion hosted MCP servers authorized through the shared MCP manager, each with its own `cordis.patch.yml`, locales, snapshots and upgrade guides), the Forge code-review page in `packages/experimental/client-ui-forge`, Forge viewer types in `packages/experimental/forge`, the Session workspace-root routing that moves sandbox, file views and discovery onto one projection (`packages/sandbox/sandbox-policy`, `packages/api/workspace-files`, `apps/desktop-host/src/file-drag.ts`), SQLite group commits for session persistence, and CUA macOS/windows mouse-button toggles. It drops `packages/client/shortcuts/src/config.ts`, `packages/client/ui-account-notifications/src/config.ts`, `packages/client/ui-settings-models/src/onboarding-config.ts` and `packages/client/ui-sidebar-documentpreview/src/config.ts` in favor of `types.ts` / `defaults.ts` siblings, and moves `packages/session/working-directory/tests/admission.spec.ts` to `packages/sandbox/sandbox-policy/tests/admission.spec.ts`.

The merge produced twelve conflicts: nine modify/delete on trimmed paths and three content conflicts. The trimmed set is `apps/desktop-publisher/package.json` plus the eight Windows-installer files `apps/desktop/installer/{drawing,lifecycle,pages}.nsh`, `apps/desktop/installer/window-frame.cpp`, `apps/desktop/scripts/installer.nsh`, and `apps/desktop/tests/windows-installer-{progress,render}.cpp` with `windows-installer-smoke.ps1`. The content conflicts were `apps/desktop/package.json`, `apps/desktop/scripts/dev.ts`, and the `apps/desktop/README*.md` / `docs/diagnostics/README*.md` pairs with their `README.i18n.yaml` pairing records.

## Decision

**Trimmed paths stay deleted, and the installer files are the new material this sync has to remove.**

Upstream changed the trimmed Windows installer sources rather than adding them, so the merge reports modify/delete for each. All nine resolve to the fork's deletion. `scripts/verify-sync-trimmed-paths.sh --stale upstream/master` confirms all 405 listed paths are absent from the worktree and still exist upstream; no new upstream file needed a trim entry, because this delta adds no workflow under `.github/` and no other mac/win-only file.

`apps/desktop/package.json` takes upstream's `0.2.2-rc.5` version and keeps the fork's `productName`, author, homepage, Linux-only scripts, and its removal of the macOS/Windows packaging scripts and the publisher devDependency.

`apps/desktop/scripts/dev.ts` takes upstream's new `prepareDevelopmentState` import, which moves development Harness state out of `.desktop-build` into `apps/desktop/.desktop-dev` and refuses to migrate a browser profile a running Harness Dev still owns. It does not take upstream's `preparePrimaryRuntime` import or its `await preparePrimaryRuntime()` call: `apps/desktop/scripts/prepare-primary-runtime.ts` is on the trim list with the rest of the macOS/Windows runtime preparation, and the fork's `prepare-runtime.ts` is the Linux implementation that imports `scripts/primary-runtime/prepare.ts` directly. The fork has carried `dev.ts` without both lines since the `0.2.1-alpha.3` sync, so this merge removes the same pair again and leaves the development launcher on the path it already used, where the Host reads the runtime directory `DSH_DESKTOP_PRIMARY_RUNTIME_DIR` names.

The `apps/desktop/README.md` and `.zh.md` Windows-installer paragraph takes upstream's new finish-control, completion-flash and Close-button sentences but keeps the fork's link-free "Directory replacement and failure recovery follow installation checks." Upstream links `packaging/README.md#runtime-file-selection`, a trimmed page. The `docs/diagnostics/README.md` paragraph keeps the fork's "not shipped in this Linux fork" phrasing for the trimmed `apps/desktop/tests/README.md` while taking upstream's new predecessor-dedup and Windows open-retry sentences. Every `README.i18n.yaml` pair is re-recorded after the merge.

The desktop version equals the engine version, `0.2.2-rc.5`, with no build counter, because the merge changes no fork-authored shell behavior.

## Alternatives considered

**Keep upstream's `preparePrimaryRuntime` import in `dev.ts` and restore `prepare-primary-runtime.ts`.** Rejected: that module is part of the macOS/Windows runtime preparation the fork trims (`prepare-primary-runtime.ts`, `sign-primary-runtime.ts`, and the two primary-runtime specs are all on the trim list), and the fork's `prepare-runtime.ts` already prepares the Linux payload. Restoring one file would reintroduce a second runtime-preparation path that the fork's packaged build never runs.

**Take upstream's `packaging/README.md` link in the desktop READMEs.** Rejected: the page is trimmed, and the repository's Markdown link gate reads the trim list to excuse links to trimmed files; keeping a link to a dropped page would trade a clean gate result for a dead target.

**Add `.desktop-dev` state handling to the fork's `dev.ts` while keeping the old `.desktop-build/development` default.** Rejected: `pnpm run clean` removes `.desktop-build`, which is the defect upstream fixed; keeping the old default would leave the fork losing development state on every clean.

**Bump the desktop version to `0.2.2-rc.5.1`.** Rejected: the merge changes no fork-authored shell behavior, and the fork's release history separates build-counter bumps from sync merges.

## Consequences

The next sync starts from upstream `master` beyond tag `dsh-v0.2.2-rc.5`. The Windows installer sources are on the trim list and will keep reporting modify/delete conflicts for as long as the fork trims them; they resolve to deletion every time. `apps/desktop/scripts/dev.ts` is now a file whose upstream counterpart calls a trimmed module, so a future sync that touches its `main()` needs the same call-site check. Session workspace-root routing moved the effective directory's consumers onto `workspaceFiles`; fork-local code that reached for `sessions`, `sessionPersistence` or `sandboxPolicy` directly to resolve a Session's root must move with it. The fork baseline still matches the fork-modified files at the new merge base: the two files that needed decisions, `apps/desktop/package.json` and `apps/desktop/scripts/dev.ts`, are both already in `.github/sync-forked-paths.txt`.
