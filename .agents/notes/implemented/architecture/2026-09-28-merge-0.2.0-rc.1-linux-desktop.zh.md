# Agent Note: 0.2.0-rc.1 合并的 Linux 桌面呈现面

Status: implemented

[English](2026-09-28-merge-0.2.0-rc.1-linux-desktop.md) | 中文

## Problem

上游 0.2.0-rc.1 是首个 0.2 发布候选：106 个提交、672 个文件。其中大部分是本 fork 原样接受的产品改动。Session Log 上传偏好以新包 `packages/client/ui-settings-session-log` 落地，并注册进 fork 自己的 `cordis.patch.yml` 组合；持久化 schema 类型清单被压缩，`docs/persistence-schema.json` 从 97057 行降到 25277 行；继承的 settings 组合跳过未被覆盖的条目与未被引用的共享组合；桌面 preload 开始转发反馈问卷预填所用的设备描述。

有五处冲突需要判断，而不是选边即可。`apps/desktop/package.json` 新增了上游钉到 3.1.1 的 `koffi` devDependency，而该依赖的唯一使用方是本 fork 已裁剪的 Windows 签名脚本。`apps/desktop/electron-builder.config.d.mts` 在 `mac` 块中新增 `entitlements` 与 `entitlementsInherit`，而 fork 的接口只面向 Linux。`apps/desktop/scripts/macos-entitlements.plist` 是新增文件，其唯一引用方是已裁剪的 `apps/desktop/scripts/electron-builder-config.mjs`。`apps/desktop/README.md` 配对两侧都改了 `installation-ownership` 章节，记录中的哈希与两侧都不相符。另有三个裁剪清单内的路径以修改/删除冲突进入合并。

## Decision

**`koffi` 不进 `apps/desktop`。** fork 在裁剪 Windows 签名脚本时已移除该 devDependency，上游的钉版本提交是把冲突带回来的一方，并非出现了新使用方。`apps/desktop/tests/fixtures/runtime-payload-smoke.mjs` 仍提到 koffi，但它运行在打包后的运行时载荷内，模块来自随包 profile 而非本清单。`pnpm-lock.yaml` 中对应的 importer 条目一并删除，`packages/host/directory-picker-native` 与 `packages/subprocess/*` 的 3.1.1 全仓钉版本保留。

**Linux 专用打包接口不携带 mac 块。** `macos-entitlements.plist` 列入 [sync-trimmed-paths.txt](../../../../.github/sync-trimmed-paths.txt) 并删除，因为 fork 根本没有携带它的那个文件。

**裁剪清单内的修改/删除冲突取 fork 的删除侧**：`.github/workflows/sandbox.yml`、`apps/desktop/scripts/electron-builder-config.mjs` 与 `apps/desktop/tests/macos-signature.spec.ts`。

**README 配对重新记录**合并后的 `installation-ownership` 章节，而不是向任一侧对齐，因为合并结果同时带着 fork 的提示窗口与 shell 外观段落，和上游新增的设备描述与全屏段落。

**Office kit 版本断言改为从已解析的 manifest 推导。** `packages/skill/skill-office/tests/skill-office.spec.ts` 写死了上游最后写下的 kit 版本，自 fork 把 kit 钉到 0.1.2 起就一直在失败；现在它按 skill 自身的做法解析 `@deepseek-ai/libreoffice-kit/package.json`，并断言该副本自报的版本。[Office 预览补丁](../bug-fix/2026-09-18-desktop-office-preview-asar-engine-probe.zh.md)不受影响，仍然生效。

## Alternatives considered

**把 `koffi` 加回 `apps/desktop`，让清单跟随上游。** 否决：这会往一个不再有任何脚本导入它的 Linux 专用外壳里安装 Windows FFI 包，且下一个发行版会重新起同样的冲突。

**把 `macos-entitlements.plist` 当作无害数据保留。** 否决：fork 中没有任何东西读它，而一个 fork 不携带、上游却持续修改的文件，每个发行版都会产生同样的冲突。

**在 `electron-builder.config.d.mts` 中采纳上游的 `mac` 字段。** 否决：该接口描述的是 fork 的 `electron-builder.config.mjs`，只构建 Linux 目标；声明工厂永远不会产出的字段会误述它。

## Consequences

后续同步按保留 fork 侧来解决 `koffi`、plist 与 `.d.mts` 三处冲突；三者现已记录在裁剪清单或本笔记中。桌面版本提升到 `0.2.0-rc.1.1`，使 fork 的构建后缀继续跟随引擎基线，与 0.1.x 期间一致。

## Testing

`pnpm run typecheck` 编译合并后的代码树，`pnpm run lint` 干净。`pnpm run test:docs` 报告 20 通过、0 失败，其中 `markdown links` 读取扩展后的裁剪清单，`translation pairing` 校验重新记录的 README 配对。`pnpm exec vitest run apps/desktop/tests` 在 67 个文件中通过 746 个测试，`apps/desktop-host` 与新的 `ui-settings-session-log` 套件在 6 个文件中通过 27 个测试。`pnpm run test` 报告 11 个失败文件，均非合并所致：六个 CI workflow spec 读取 fork 不携带的 `.github/workflows/ci.yml` 等同名文件；`executor`、`spawn-runner` 与 `helper-processes` 在合并前于本机同样失败；`watch-config` 与 `checkers` 单独运行即通过。`pnpm run hygiene` 在合并两侧报告同样两项既有失败：`constraints` 要求 `@deepseek-ai/dsh-desktop` 与根版本相等，而 fork 的构建后缀从来不等于根版本；`publint` 报出 300 个包的发布视图中 `./src/*` 导出匹配不到文件，因为这些包清单的 `files` 中没有 `src`。
