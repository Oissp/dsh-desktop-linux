# Agent Note: 0.2.1-rc.2 merge — DeepSeek Search and Fetch APIs arrive with a temporary model label

Status: implemented

English | [中文](2026-10-17-merge-0.2.1-rc.2-linux-desktop.zh.md)

## Problem

Upstream `master` advanced nine commits past the previous sync point (`dsh-v0.2.1-rc.1`) and released engine `0.2.1-rc.2` (tag `dsh-v0.2.1-rc.2`, which is this merge's target). The delta changes 456 files, and unlike the previous release it carries real engine work across four areas: a new `packages/web/web-deepseek-api` provider that exposes DeepSeek's Search and Fetch endpoints behind a settings switch (with transport, credential, egress, and redirect tests, locale dictionaries, and a `snapshots/session/deepseek-fetch` recorded-session case), a new `packages/client/ui-deepseek-model-label-1017` client package that renders a temporary "1017" badge on the bundled DeepSeek Flash model label (with a Web e2e scenario and account overlay fixture), a reworked `WebSearchCard` in `ui-settings-web-search` that gains its own CSS module and controller changes, and supporting documentation (capability seams, subsystem page, config catalog, persistence schema, and a `docs/persistence-changes/2026-10-13-deepseek-search-thinking` record).

The merge produced one conflict: `apps/desktop/package.json`, where the fork's metadata block meets the upstream version bump. No other forked-path file changes upstream in this delta.

## Decision

**The single conflict keeps the fork's metadata and takes upstream's version.** `author` and `homepage` stay on the fork repository, and the version moves to `0.2.1-rc.2` (equal to the engine version). This is the same recurring conflict recorded in the previous sync notes.

**No trim-list change.** All 51 files the delta adds sit inside the engine and documentation scope: the two new packages, their tests and locale files, the Web e2e fixtures, the persistence-change record, and the DeepSeek Search/Fetch feature note. None belongs to the trimmed macOS/Windows packaging or publication scope, so the list stays at 377 paths.

**No fork source change.** `main.ts`, `locale.ts`, `update-coordinator.ts`, `desktop-build-paths.mjs`, `electron-builder.config.mjs`, `package-target.ts`, `prepare-runtime.ts`, and the desktop CLI files carry through unchanged; the only forked-path file upstream touched is `apps/desktop/package.json`, and its sole upstream change is the version.

**Upstream's engine work is adopted unchanged.** The fork carries no `packages/` divergence, so the new provider, the new label package, the Web search card rework, and every accompanying test enter the tree as upstream authored them.

## Alternatives considered

**Trim `packages/client/ui-deepseek-model-label-1017` because the badge is temporary.** Rejected: the trim list has never carried `packages/` entries, the badge is a bundled default-profile package that the Web and Desktop clients compose, and removing it would make the fork's client graph diverge from upstream for a package upstream plans to remove on its own schedule. A future upstream revert then merges cleanly instead of reopening a conflict.

**Trim `packages/web/web-deepseek-api`.** Rejected: it is an ordinary engine web provider, inert unless a profile enables it, and the fork's engine carrier has no `packages/` divergence. The trim list exists for packaging and platform scope, not for optional product features.

**Fold the desktop version into a `.N` suffix because the client graph changed.** Rejected: the runbook assigns a `.N` suffix only when fork shell code changes. This sync changes none, so the desktop version equals the engine version.

## Consequences

The next sync starts from upstream tag `dsh-v0.2.1-rc.2`. The trim list holds 377 paths.

The fork now ships the DeepSeek Search and Fetch provider and the temporary model label, both reachable only through the engine's own composition. Neither touches the Linux shell, so `package-deb.yml` needs no change and the updater keeps deriving its channel from the version's prerelease segment.

The new persistence-change record under `docs/persistence-changes/2026-10-13-deepseek-search-thinking` is documentation of an engine schema record; the fork carries it as upstream wrote it because the fork does not fork persistence.
