# Agent Note: 0.2.0-rc.2 merge at da00f7f535 — kit 0.1.5 and the restored CLI payload

Status: implemented

English | [中文](2026-10-03-merge-0.2.0-rc.2-da00f7f535-linux-desktop.zh.md)

## Problem

Upstream `master` moved from `639ed01539` to `da00f7f535`, 258 commits over 3925 files, without bumping the engine past `0.2.0-rc.2`. Product work the fork takes unchanged includes the Session inspector with its raw-log, grouped-chat and embedded DevTools views, parsed tool arguments that stream during preparation, Claude Code mods as DSH plugins, the LibreOffice Kit 0.1.5 release, and a bulk archive of 306 Agent Notes. On the Desktop side the Host moved to an OS-assigned port and the native account-state decoder learned the `no-response` sign-in failure.

Twenty-five paths conflicted. Fifteen were modify/delete pairs: the trim list covers most of them, and three arrive as renames — upstream archived the `desktop-cos-upload-transport`, `windows-lock-release-probe` and `desktop-mandatory-update-client` notes, which the fork had either trimmed outright or kept active. The rest were content conflicts in `apps/desktop-host/package.json`, `pnpm-workspace.yaml`, `pnpm-lock.yaml`, the Desktop README pair, the development-guide pair, `skill-office.spec.ts`, and `.agents/notes/archived/manifest.json`.

The merge also surfaced two defects that predate it. The `2026-09-30-desktop-cli-linux-sync` note shipped English-only, which fails the translation-pairing gate whenever a `.i18n.yaml` file is staged, and the Linux `dsh` command installed by that same feature could not run at all.

## Decision

**Trim-list conflicts keep the fork's deletion.** The two desktop installed-update testing notes, `ci.yml` and `ci-master.yml` stay deleted.

**The two archived mac/win notes stay deleted.** `2026-09-16-desktop-cos-upload-transport` and `2026-09-14-windows-lock-release-probe` describe pipelines the fork does not carry, so their archived triplets are removed along with their manifest seals. The cos-upload-transport note was already deleted without a trim-list entry; both paths are now listed.

**The mandatory-update-client note takes upstream's archive move.** The fork ships the Desktop command this note documents, so the triplet moves to `archived/feature/`. The fork's earlier removal of links to its trimmed local-qualification note is re-applied, and the triplet and its manifest seal are re-recorded against the merged content.

**LibreOffice Kit follows upstream to 0.1.5, and the fork's patch is rebased onto it.** Upstream did not fix the `installedPackageExists` probe the fork patches, so the change is re-applied rather than dropped: `patches/@deepseek-ai__libreoffice-kit@0.1.5.patch` carries the same `Boolean(lstatSync(...))` form inside a `try`, and `patchedDependencies` names the new version. The kit 0.1.5 body is not a cosmetic bump — it adds RTL tile correction and a native-process transport — so staying on 0.1.2 would have kept the fork behind a dependency it already patches. `createRuntimeProjectMetadata` pins the patched version in the build root automatically, so the packaging path needs no further change. The `skill-office.spec.ts` conflict resolves to the fork's manifest-derived version expectation, which survives the bump.

**The Desktop README regains the sections the trim had removed.** The `Bundled command runtime` section and the `The Desktop-installed command can manage its plugins…` sentence describe a feature the fork ships again, so both take upstream's text. The fork's own `Shell prompts are modal children of the product window` paragraphs stay.

**The development guide takes upstream's edits plus the fork's CI section.** Resolving the file to the fork's side alone would have dropped upstream's prerequisites, DevTools and build-loader changes, and would have kept a link to the archived `ts-build-config` note. The fork's `CI gates` paragraph replaces upstream's, and the rest is upstream's.

**The archive manifest is the union.** Upstream's seals, minus the two trimmed triplets, plus the fork's `desktop-cli-linux-sync-plan` entry.

**The missing CLI entry is restored.** `apps/desktop/cli/dsh` executes `@deepseek-ai/dsh-desktop-host/lib/cli.js` inside `app.asar`, but commit `3266005df5` restored the feature without restoring the four places that had described the trimmed shape: the `tsdown` entry list, the package `files`, `DESKTOP_HOST_RUNTIME_FILES`, and the workspace constraint table all still named `lib/index.js` alone. The build therefore never emitted `lib/cli.js`, and every installed command would have failed with `ERR_MODULE_NOT_FOUND`. All four return to the two-entry form, and the package-set fixture gains the matching file.

**The desktop-cli Linux sync note gains its Chinese side.** The repository requires bilingual pairs, and the pairing gate blocks a commit that stages any `.i18n.yaml` file while an unpaired note exists. The existing Chinese text becomes `.zh.md` and an English `.md` is written to match, following the sibling `fork-debian-linux-packaging` note.

## Alternatives considered

**Keep the fork's kit 0.1.2 pin.** Rejected: it defers the same conflict to the next sync and leaves the fork on an older kit body than upstream for no gain, since the patch mechanism already pins the version it targets.

**Regenerate the kit patch with `pnpm patch`/`pnpm patch-commit`.** Rejected as unnecessary: the patched function is byte-identical between 0.1.2 and 0.1.5, so regenerating the diff against the 0.1.5 file reproduces the same hunks, which was confirmed by first reproducing the 0.1.2 patch from its own sources.

**Repoint the Linux launcher at `lib/index.js`.** Rejected: `index.ts` is the Electron Host entry; the CLI dispatch lives in `cli.ts`, whose `import.meta.main` block is what the launcher runs.

**Commit the merge with `--no-verify`.** Rejected: the unpaired note is a real gate violation that would keep failing on every later commit that touches a pairing record.

**Fix the pre-existing documentation gates in this branch.** Rejected as out of scope: `verify-md-wrap` and `verify-repository-references` fail on the fork's `2026-09-30-fork-debian-linux-packaging` note, which this merge does not touch and which fork CI does not gate.

## Consequences

The kit patch now tracks the kit version, so a future bump is a rename plus a regenerated diff rather than a version-pin decision. The trimmed shape no longer has a caller: nothing in the fork still assumes `apps/desktop-host` ships only `lib/index.js`.

`desktop-cli-linux-sync` leaves the set of unpaired notes, so staging any pairing record no longer fails the pre-commit hook.

Two failures remain that this merge neither caused nor fixed. `pnpm run test:docs` reports `markdown wrap` and `repository references` failing on `2026-09-30-fork-debian-linux-packaging.md`, whose blockquote is hard-wrapped and whose header cites commit hashes. `apps/desktop/tests/command-installation.spec.ts` cannot load on macOS because its `darwin` branch imports the trimmed `prepare-command-link.ts`; Linux CI runs the suite and passes it.

The desktop version moves to `0.2.0-rc.2.3`. Because `shellVersionExtendsEngine` accepts only the engine version or the engine version plus a build counter, a stable `0.2.0` shell cannot be built while the engine stays at `0.2.0-rc.2`; the release must either bump the engine or stay on the `.N` line.
