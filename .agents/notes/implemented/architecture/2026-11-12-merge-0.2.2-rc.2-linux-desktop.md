# Agent Note: 0.2.2-rc.2 upstream sync — the fork follows the Office kit rework and trims the rollout pipeline

Status: implemented

English | [中文](2026-11-12-merge-0.2.2-rc.2-linux-desktop.zh.md)

## Problem

Upstream `master` advanced 923 commits past tag `dsh-v0.2.2-rc.1` and cut `0.2.2-rc.2`. The delta changes 3479 files — 602 added, 107 deleted, 2684 modified, 85 renamed, and one type change — with 108953 insertions and 33648 deletions. It reworks Office around LibreOffice Kit 0.2.3: the kit lives in `packages/document/office-kit`, resident `office_render`, `office_convert` and `office_recalculate` tools replace the render, export and recalculate skills, and Desktop reads skills from the package's assets inside ASAR instead of a `runtime/office-skills` copy. It also adds the Host-owned desktop theme preference, the update status dialog, the Windows restart banner, the website/COS/EdgeOne staged rollout pipeline, CUA Windows support with explicit inspection and AX traversal limits, the Forge review UI, terminal panel tools, session worktree reclamation, Cordis rc.12, and the zod 4.6.6 and Stagehand 4.4.0 bumps. The fork's engine-side divergences remain the tsdown build configs and the Linux-only packaging scripts; none of them conflicted.

Merging produced 30 conflicts: 19 modify/delete conflicts on trimmed paths (the workflow `pr-check-on-head-branch.yml`, the Windows installer sources `window-frame.cpp` and `installer.nsh`, the packaging and publishing README pairs, seven publication and macOS runtime scripts, and four specs), and 11 content conflicts (`apps/desktop-host/package.json`, `apps/desktop/package.json`, the desktop README pair plus its pairing record, `apps/desktop/tests/main-startup.spec.ts`, `apps/desktop/tests/welcome-flow.e2e.ts`, `packages/skill/skill-office/tests/skill-office.spec.ts`, `pnpm-lock.yaml`, `pnpm-workspace.yaml`, and `scripts/no-unknown-casts.baseline.json`).

## Decision

**The merge follows upstream's Office kit, theme and update-status surfaces into the Linux shell, and trims the publication pipeline the fork does not run.**

Eleven more upstream paths are trimmed, and the trim list grows from 435 to 446. The desktop rollout lineage — `.github/workflows/desktop-rollout.yml`, `apps/desktop/scripts/desktop-rollout.ts`, `publish-desktop-rollout-ci.ts` and `desktop-rollout.spec.ts` — imports already-trimmed publication modules and cannot typecheck. `.github/workflows/cua-helper-package-windows.yml` and the Windows restart banner sources (`installer/restart-banner.h`, `restart-status.h`, `restart-text.h`, `scripts/restart-banner.nsh`, `tests/fixtures/restart-status-owner.nsi`, `tests/windows-restart-status.ps1`) serve Windows flows the fork never builds; the fork's own `package-deb.yml` creates the GitHub Release directly.

`apps/desktop-host/package.json` follows upstream's dependency set, which drops `libreoffice-kit`, `home-paths`, `skill-office`, `tool-workspace-dependencies`, `cordis-plugin-loader`, `cordis-plugin-include`, `skill` and `tool-executor-native` because the Host no longer imports them, and keeps the fork's removal of `koffi`. The Office kit and its tools now reach Desktop through the profile composition upstream moved them to.

`apps/desktop/package.json` takes upstream's `0.2.2-rc.2` version and `zod` 4.6.6, and keeps the fork's product name, author, homepage, and Linux-only scripts. `apps/desktop/README.md`, `README.zh.md` and the pairing record take upstream's new paragraphs — theme preference, update status dialog, Office skills inside ASAR, restart notice — and re-record the pairing hashes; the fork's Linux packaging links and trimmed-target links stay.

`apps/desktop/tests/main-startup.spec.ts` merges upstream's theme and update-status cases with the fork's Linux tray, appearance-controller and menu harness, including the `nativeTheme` EventEmitter mock and the menu without the `cliCommand` item, and adapts the window-listener assertion to the fork's app-lifetime appearance controller. `apps/desktop/tests/welcome-flow.e2e.ts` takes upstream's rewrite around the new `apps/desktop/tests/harness.ts`; the fork's `linux-x64` synthetic-project target moves into that harness and is added to the fork baseline. `packages/skill/skill-office/tests/skill-office.spec.ts` takes upstream's rewrite, which drops the installed-manifest version read the fork had adjusted. `pnpm-workspace.yaml` follows upstream's LibreOffice Kit 0.2.3 release-age exclusion and Stagehand 4.4.0 entry, and keeps the fork patch pin now pointing at `patches/@deepseek-ai__libreoffice-kit@0.2.3.patch`; `pnpm-lock.yaml` carries the merged lockfile minus the `desktop-host` `koffi` entry.

Three baseline entries leave `sync-forked-paths.txt` because upstream absorbed their changes: `welcome-flow.e2e.ts` and `welcome-startup.spec.ts` now match upstream, and the `skill-office.spec.ts` manifest assertion no longer exists. `scripts/no-unknown-casts.baseline.json` is regenerated for the files upstream changed.

**The desktop version equals the engine version, `0.2.2-rc.2`, with no build counter.** The fork's release repository has no `v0.2.2-rc.2` yet, so the packaging workflow publishes that version when the merge lands on `main`.

## Alternatives considered

**Keep the rollout workflow and scripts and stub their imports.** Rejected: they serve the COS, website installer and EdgeOne flows the fork does not run, and their publication dependencies are already trimmed.

**Keep the previous `desktop-host` dependency list.** Rejected: upstream's Host no longer imports those packages, and unused workspace dependencies fail the repository dependency gates.

**Re-apply the fork's LibreOffice Kit manifest assertion in the Office skill spec.** Rejected: the manifest read is gone; the kit version now comes from `office-kit` 0.2.3, and the spec's version-agnostic checks cover the skills.

**Keep the stale baseline entries.** Rejected: the baseline must list files that still differ from upstream, or the next merge treats absorbed changes as pending decisions.

## Consequences

The next sync starts from upstream `master` beyond `dsh-v0.2.2-rc.2`. The trim list records 446 paths and the fork baseline 75 entries, including the new harness and the Office kit Chinese README. Office packaging follows kit 0.2.3 and reads skills from ASAR; `scripts/libreoffice-packages.mjs` still derives the asar-unpack closure from the installed kit manifest.
